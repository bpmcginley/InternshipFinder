# P-2.1h one-click unsubscribe HTTP route

[#266](https://github.com/bpmcginley/InternshipFinder/pull/266), draft and needs-bruce. Stacked on frozen #261 `e29eb17c`; ordinary merge `3bcc02a4` brings in published main, including WP-4.3 #259. The refactor lead released `worker/src/index.js`. Existing main data, public files and stamped golden pair are retained unchanged.

**URL contract:** `POST https://<approved Worker origin>/follows/unsubscribe?token=<unsubscribe UUID.secret>`. Exactly one `token` query parameter, with the entire query at most 256 characters. The existing #243 handler requires exactly one text form field `List-Unsubscribe=One-Click` in URL-encoded or multipart form data, bounding actual streamed body bytes at 4,096. This integration adds a five-second absolute read deadline in that bounded reader; chunks never renew it. Timeout cancels the reader, returns empty retryable 503, and cannot proceed to D1. The existing hashed `unsubscribe` purpose authorizes deletion; confirmation/management tokens do not. The `fd_` request-only capability is a separate operation and is rejected here. No bearer is reflected in a response or stored by this adapter.

The route is registered only for POST. GET/HEAD and other unsupported methods retain the router's 404 fallback without D1 access or mutation. Global OPTIONS retains its existing 204 behavior. The router's existing trailing-slash normalization remains. Successful deletion, replay, unknown token and other shaped-but-wrong-purpose tokens return the same empty no-store 204. Malformed input returns empty no-store 400. There is no redirect, HTML page or new visible copy. Cookies and Authorization never select an identity; a mailbox POST needs neither sign-in nor an Origin header. Existing CORS behavior only controls response readability.

The four-slot in-flight bound is an independent per-isolate counter, with no IP, bearer, email or other identifier retained. Slots are released on completion, malformed input or thrown error. Body timeout, saturation and unavailable storage return empty no-store 503 with `Retry-After: 60`, without invoking the router's error logger. This is bounded local concurrency, not a deployment-wide quota or durable rate limit; restarts reset it and stalled body streams are cancelled at five seconds. Completed-body requests retain their slot until the actual D1 operation settles; no outer timeout races or detaches database writes. No request target or caught storage error is logged by this path. Infrastructure request-log redaction still needs operator verification before issuing links.

Deletion has no signup/sending configuration dependency. Missing bindings/schema remain retryable storage failures, not an invented activation switch. Once deployed with the approved parent schema, deletion works independently of any later signup or sending switch. This PR wires no registration, confirmation/manage/request-only route, sender, provider, dispatcher or cron. It does not modify the mail renderer or generate real links. No new approval is required for the four-slot non-identifying bound; owner merge/deployment and the existing mail release prerequisites remain gates. Already accepted mail cannot be recalled.

Validation: baseline 11 focused Node tests passed; final 16 focused and 393 full Node tests passed. All 25 actual local Workers/D1 tests passed. HTTP tests cover anonymous URL-encoded/multipart forms, GET/HEAD/method fallbacks, malformed and oversized input, ignored cookie/auth and foreign Origin, storage failure without logging, saturation and slot recovery. An injected deterministic timer test cancels four stalled streams (including a complete field without EOF and chunked input), confirms the deadline never resets and no expired read reaches D1, and proves a later request proceeds. A separate pending-write test proves cleared body timers cannot release slots during actual database work. Actual D1 proves target-only deletion cascades scopes, purpose tokens, request-only capabilities and outbox; retains another subscriber and the independent send-day marker; and leaves a later resubscription intact on replay. Historical route response bytes/headers are unchanged: the original fixture is not refreshed, and the contract assertion explicitly names this sole added route. Generated API documentation, ESLint, formatting and diff checks pass. Startup payload report ran; public assets/golden pair are byte-identical to integrated main, with no startup change or UI screenshots required. All requests and rows were synthetic/local; no provider calls, remote DB, production analytics, deployment or release.
