Draft needs-bruce on exact #625 `6c0954836ea74deb27e57516eeceae8b2cbeebaa`. Own only new `scripts/follow_labels.py`, `backend/tests/test_follow_labels.py` and this note. Existing assembler, catalog producer, writer, vocabulary, allowlist, workflow and Worker bytes are unchanged. The Product lead owns the shared Waiting for Bruce tracker.

`produce_follow_labels` is a repository-only, default-off bytes producer for the exact #629 `15a503356dee1913fda0d2d78850e903d3350c93` contract, now merged as `063d523f`. Its canonical compact UTF-8 JSON has ordered `version`, `source_sha256`, `catalog_sha256`, `companies`, `fields` and `states` fields. Each group is a key/label pair array covering exactly the catalog's valid set. The result also carries its SHA-256 and the explicit predecessor label hash. It performs no I/O, fetch, write, rendering, acquisition or activation.

The caller supplies the original selected index/majors/shard bytes, expected current catalog bytes/hash, all existing catalog staging pins and bounds, and a positive label-byte limit. The producer captures the bounded selected mapping once and rebuilds the canonical catalog with the existing producer. Exact byte equality binds labels to the same original export, current aliases and retained valid sets. The Worker contract caps are enforced at one million catalog bytes, two million label bytes and ten thousand keys per group. Pair sizes are counted before accumulation. Every label obeys the existing Worker plain-text and 200 UTF-16-unit bound.

For current company keys, the producer counts each unique open role once and uses the existing employer-page spelling rule of most frequent name, then shortest name, then name order. Cross-shard copies do not add votes. It selects only qualified aliases in that same catalog. Fields use the shared display overrides and existing native Core formatting, restricted to the known field vocabulary. States and provinces use the shared vocabulary. Unknown current vocabulary fails rather than displaying a guessed key. Existing display examples include `Software`, `New York` and `Ontario`. No new authored email or public-page copy is introduced.

An explicit genesis accepts no predecessor labels. Every later generation requires both the pinned predecessor catalog and a complete pinned predecessor label artifact. The prior label artifact must have the correct canonical shape, source/catalog hashes, exact valid-key coverage and valid label values. Retained-only keys keep those exact historical labels. Missing, crossed, duplicate, malformed or incomplete lineage fails as a whole. This does not authenticate caller-supplied pins or choose historical labels. Their trusted acquisition remains an upstream release responsibility. No unresolved company spelling choice is needed for this dormant producer.
