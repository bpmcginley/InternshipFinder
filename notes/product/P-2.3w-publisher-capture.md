Draft [#453](https://github.com/bpmcginley/InternshipFinder/pull/453) starts on `ca660a4a`. The historical #407 publisher is an ancestor of main; its behavior is preserved by the later #410 adapter. Current refactor claims on link tests and screenshot preparation remain untouched.

The publisher accepts `--employer-posting-capture` only alongside exactly one `--employer-postings`. Both options remain absent from production workflows. The existing same-export adapter must validate and stage the catalog, all declared slim shards and first preview successfully; the ordinary page/feed/widget build must then succeed. The final capture pass adds only `data-employer-posting-counts="1"` to the existing exact `/js/count.js` script, before normal asset stamping. Targets are the dashboard and this build's `/internships/` pages containing the approved organic annotations. Activation selects only current build pages. Before any staging or rendering, a separate preflight checks the dashboard and retained internship HTML, including stale pages outside this build, and rejects any existing capture mark. Reused destinations must therefore be freshly staged and unmarked; the publisher does not silently preserve or remove activation. Missing, duplicate, altered, unclosed or already marked counter tags fail the build. Any script URL containing a potential counter filename, after conservative percent/whitespace normalization, must have the exact canonical serialization. The guard deliberately does not trust Python authority parsing or reproduce browser URL rules; foreign and slash-heavy/encoded/fullwidth-host counter aliases are rejected too. Script insertion offsets count LF only, matching the HTML parser even when Unicode line separators precede the tag. Every target is validated before capture writes; an I/O failure still invalidates the entire artifact, which must not be published.

Fresh unmarked default builds and annotation-only builds are unchanged. No visible words, styles, posting destinations, data fields, content dates, paid listings, widget/feed output or Worker behavior changes. Existing browser logic handles trusted organic activations, one company per page load, exclusions and `nocount`. The public conditional privacy paragraphs already match main exactly. There is no additional policy copy in this package.

Validation and browser evidence are recorded in [the capture README](screenshots/P-2.3w/README.md). The catalog, shards, first preview, content-date metadata and all other files are identical to the annotation-only build. The default golden pair is not refreshed.
