# P-2.1ep detached retired-slot conditional cleanup

Draft #659 stacks on frozen #657 `e1cce9276877b12a4929b8018ef7b69fc2a15948`. Scope: new `worker/src/follow-checkpoint-cleanup.js`, shared bounded capture extraction in `worker/src/follow-checkpoint-retirement.js`, the additive pinned-authority effect closure in `worker/src/follow-checkpoint-control.js`, `worker/src/follow-checkpoint-runtime.js`, native harness delegation in `worker/test-checkpoint-integration/worker.js`, new `worker/test-checkpoint-integration/cleanup-retired.test.js`, and this note. No tracker, schema, entry, alarm or settings changes.

The runtime exposes `cleanupRetired()` only through the already explicit enabled factory; disabled calls return held without dependency access. It reuses the exact #657 metadata validation, including slot separation, predecessor relationships and the original reservation cutoff. It admits only an exact current witness/control snapshot with an existing retired descriptor and physically reads that exact slot, payload nonce and ETag before preparing any mutation. No new expiry restriction is imposed: an already retired rejected or superseded record may have an original expiry in the future.

The existing control transition now supplies an optional third effect argument: a closure that reads the operation's already-pinned witness and verifies the exact prepared predecessor/nonce/successor against unchanged SQLite metadata. Existing effects ignore this argument and retain their behavior. Cleanup checks it once immediately before its physical attempt and again after exact tombstone readback. It does not call a fresh witness supplier for either check. Each check also requires unchanged bounded control and a nonregressing native clock. Independently changed authority cannot authorize the PUT.

The effect freshly verifies the original payload and control, creates one native single-use tombstone receipt, then makes one conditional PUT against the original retired ETag. It requires known stored acknowledgement and exact new tombstone nonce/ETag/empty digest and payload readback before allowing the existing SQLite CAS to clear only retired metadata. The other slot and active metadata remain unchanged. It returns committed only after the control's existing exact witness acknowledgement completes; all absent, stale, malformed, changed or ambiguous outcomes are held. No automatic retry, raw receipt replay, reconstructed envelope, journal addition or reset exists.

A physically committed PUT whose acknowledgement is lost can leave the old retired metadata and a prepared witness. That state remains held, including after restart, and this normal-path package cannot recover it. The existing expired-reservation journal is not extended to cover retired records. If SQLite committed but witness acknowledgement was lost, the existing separate exact acknowledgement recovery remains available; cleanup itself does not repeat the physical attempt. Any new recovery authority for the pre-SQL ambiguous physical effect needs separate design and review. Tombstone readback proves only replacement of the observed current local object, never provider erasure, backup expiry or restore qualification.

Qualification uses only local native SQLite/R2 and injected witness/EMAIL-free ports with external requests forbidden. All 186 native cases across 13 configured checkpoint files pass, including 14 new cleanup cases. A final focused 14-case run additionally asserts exactly two prepared-authority reads on success. The 23 adjacent Node payload/witness and native default-entry checks pass; scoped lint, formatting and diff checks pass. New cases cover success and one-use replay refusal, concurrent contenders, missing/replaced/wrong-identity objects, pinned-witness change before PUT and after readback, metadata race, committed PUT with uncertain/thrown acknowledgement, both witness-finish loss positions, default closed behavior and malformed metadata. Existing retirement, reservation cleanup/recovery, promotion and snapshot cases remain passing.

No production selection, schedule, cleanup cadence, provider/bucket, new retained fields or physical-retention policy is chosen. Production storage and independent witness/restore evidence, bounded operational cleanup and controlled recovery remain release gates. Independent exact review is required; this draft does not authorize merge or deployment.
