# P-2.3s employer retention schedule

The existing `4,34 * * * *` Worker clock can invoke the reviewed [#403](https://github.com/bpmcginley/InternshipFinder/pull/403) helper when `EMPLOYER_POSTING_MAINTENANCE_ENABLED` is exactly `"1"`. The first scheduled invocation of a UTC day is 00:04. The next half-hour invocation can retry a temporary failure or continue a bounded backlog. The helper checks the actual database UTC day before and during its batch. A delayed event's scheduled timestamp cannot set the retention day.

Maintenance has its own waitUntil task and can run while GitHub dispatch is unconfigured or fails. The clock branch still returns before the existing daily billing, report and order work. The intake setting is independent. Keep maintenance enabled after pausing intake if aggregate rows remain. Verify the production clock and current-day cap before enabling intake. This package adds no setting value, trigger, publication or live activation.

Local validation passed 15 Workers/D1 cases and 22 focused Node clock, campaign and billing cases. The scheduled tests cover exact opt-in, no D1 access when disabled, preservation of the current cap and cleanup while intake is off, with missing and failed GitHub dispatch. Dispatch failures were synthetic. No provider or production request was made.
