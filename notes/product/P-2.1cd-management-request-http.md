# P-2.1cd Dormant management request HTTP

[#541](https://github.com/bpmcginley/InternshipFinder/pull/541) adds a body-only HTTP adapter on exact #535 `c55ff438`. It delegates to the existing enqueue operation without changing its SQL, storage, retention or request policy. There is no public route, configuration, sender, dispatch or visible copy.

The factory requires literal enabled=true, an explicitly trusted synchronous Origin predicate, D1 and positive safe-integer request TTL/global daily cap. The TTL keeps the existing maximum of seven days; there are no production values. Missing configuration returns generic 503 before body access. The future mounting must construct one shared factory per isolate. Four in-flight slots bound both body and storage work, without persisting identities; this is not a deployment-wide quota.

Only POST is accepted. Query/fragment delimiters, absent/null/foreign Origin, wrong media type, malformed declared length, invalid UTF-8/BOM, duplicate or extra JSON members and malformed email cannot reach enqueue. The exact object is {email:string}; escaped JSON keys are accepted only once. The existing shared email normalizer remains the single grammar. The shared body reader enforces 16 KiB and one absolute five-second deadline, cancels stalled streams and releases their slots. Storage is not raced against a timeout that could prematurely release its slot.

Valid requests delegate once. An empty 202 is identical for unknown inboxes, new jobs and duplicates; the existing live job expiry is unchanged. Empty 400/403/405/415 distinguish malformed input, origin, method and type; unavailable/cap/uncertain outcomes use empty 503 with Retry-After:60. Every response is no-store/nosniff, with no address, provider detail, cookies or redirect. Cookies and authorization do not confer permission. A committed but unacknowledged queue write is not retried or refunded.

Nine shared scenarios run in standalone Node SQLite and actual local Workers/D1. They cover explicit disabled/policy checks, strict exact-shape transport, generic unknown/duplicate receipts and normalization, concurrent daily cap, committed acknowledgement ambiguity, four held storage slots, stalled bodies, elapsed chunk deadlines and unavailable storage. The focused Node lane including the existing enqueue suite passed 19 cases; native HTTP/enqueue/full migration parity passed 28. Normal registered npm test passed 907 cases with zero failures/skips; pinned ESLint/Prettier, generated API check, startup payload reporting and whitespace checks passed.

The normal Node registry import is at the released request-test anchor, disjoint from #539's management-claim/delivery anchor. No default API inventory or Worker startup dependency changes. Public assets/goldens, migrations and production configuration remain identical. Exact request TTL/re-request policy/cap, physical expired-job deletion, routing, provider qualification and activation remain gated. The public management page/link/copy is separately proposed in #542, not implemented here.
