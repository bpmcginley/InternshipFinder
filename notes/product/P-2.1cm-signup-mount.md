# P-2.1cm Follow signup route mount

[#555](https://github.com/bpmcginley/InternshipFinder/pull/555) registers exact `POST /follows/signup` with the reviewed `{email, link, scope}` JSON body and no query or fragment. Only `https://internscout.org` with existing CORS permission can submit. Anonymous requests use no session. Explicit linkage still needs a current non-refreshing Worker session and the existing final D1 session and catalog-expiry guards.

The router keeps the existing 404 before reading the body or touching D1/catalog unless `FOLLOW_SIGNUP_ENABLED` is exactly `"1"` and a synchronous trusted `followSignupRelease()` supplies a qualified current release. The deployed entry supplies no such function. A request, browser, environment string or downloaded catalog cannot supply it. Malformed, absent, future, expired and asynchronously returned authority fail closed.

The supplier receives no request or account information. It returns exactly `{origin, release, previousValid, maxBytes, maxKeys, deadlineMs, dailyLimit}`. The existing release shape is `{url, sourceSha256, catalogSha256, notBefore, expiresAt}`. The SHA-256 pins come independently from the approved public export and canonical artifact. Prior approved company, field and state Sets must be explicit. No missing value becomes an empty prior catalog. No URL, bounds, dates or quota values are selected here.

The isolate-scoped HTTP handler checks Origin, URL and body framing and reserves one of the existing four in-flight slots before consulting the supplier. The route copies the release and prior Sets before reading the body. Each admitted request owns its constrained catalog GET and uses one current release cutoff across the Worker clock and SQLite admission. Bad bytes, continuity failures and a cutoff reached during body/loader/D1 work cannot queue a signup. Generic acknowledgements, limits and both original Follow token and management routes stay unchanged.

Production still needs G3 and lead release, the independently pinned #510/#518/#522 artifact and predecessor continuity, and an approved supplier binding and publication path. Qualification must prove that the exact published origin, pin delivery, window and bounds work before adding a real supplier. Signup and sending remain separate rollout decisions. This PR makes no provider calls or production/configuration changes.
