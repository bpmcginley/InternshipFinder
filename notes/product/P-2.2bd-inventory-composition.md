# P-2.2bd offline history inventory composition

This test-only package composes the existing inventory and Events page reader on exact main `ff18e01cd7910ead8d0445ff0fde6f3a83e72d57`. It adds a shared synthetic fixture, standalone Node and native Workers wrappers, and this note.

The fixture explicitly forwards GET, manual redirects, omitted credentials, no-store and the same cancellation signal into an injected transport. It uses a fixed fake authorization value and never invokes fetch. Native Request construction verifies the method, redirect and cache settings. The pinned Workers runtime does not expose Request.credentials, so that property is checked only where present. The injected credentials policy is checked in both runtimes. This does not qualify real credentials or browser cookie handling.

Ten scenarios cover exact URL, interval, cursor and headers; historical event schema distinct from the request API version; disabled and malformed input before transport; mode, account scope and known event object mismatch; redacted unknown labels; response and redirect rejection; failed second pages with no partial counts; duplicate IDs at equal timestamps; empty continuation; exact byte and page bounds; elapsed deadlines; late response cancellation before headers; stalled-body cancellation and reader release; and an empty terminal list. Observed inventory is not a completeness or replay-compatibility certificate.

Qualification passed 38 strict Node tests and 32 native Workers tests across the new composition, existing inventory and existing page-reader suites. The new scenarios account for ten tests in each runtime. The ten new native scenarios use synthetic streams without a database or migrations. The existing page-reader group also exercises its original local D1 traversal fixtures. Scoped lint, formatting and diff checks passed.

Reproduce from the repository root with Node 22:

```powershell
node --unhandled-rejections=strict --test worker/test/topup-history-inventory-composition.test.js worker/test/topup-history-inventory.test.js worker/test/topup-history-page.test.js
```

Run the native suite from `worker/` with the pinned dependencies:

```powershell
$env:CLOUDFLARE_CF_FETCH_ENABLED='false'
$env:WRANGLER_SEND_METRICS='false'
node --unhandled-rejections=strict node_modules/vitest/vitest.mjs run --maxWorkers=1 test-workers/topup-history-inventory-composition.test.js test-workers/topup-history-inventory.test.js test-workers/topup-history-page.test.js
```

No runtime, registry, provider, database, configuration or coverage-authority behavior changes. Provider account access, mode and historical schema qualification, and any production coverage decision remain separate owner work. This package remains needs-bruce.
