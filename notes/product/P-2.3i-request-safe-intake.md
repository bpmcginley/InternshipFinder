# P-2.3i request-safe intake prerequisites

[Draft #292](https://github.com/bpmcginley/InternshipFinder/pull/292) is stacked on exact #287 `bda23b59`. Fresh refactor status and actual open paths showed no competing visits/cache writer; the test registry append is additive. Needs-bruce; no merge or deployment.

## Implemented boundary

`createRequestSafeEmployerCatalogCache` accepts the loader on each request. Isolate-shared state contains only parsed membership, expiry/clock/retry numbers and a plain generation token. Competing refresh requests fail closed immediately. They never await the owner's promise or cancel its response, reader, abort signal or timer. The existing coalescing factory remains compatible and supplies the request-local bounded UTF-8 reader and timeout; only its validated pure predicate is published. Refresh starts a hard five-minute expiry; malformed/failed/oversized refreshes retain no stale data, with a five-second retry delay. A late owner cannot replace a newer generation.

The employer-specific factory reuses the existing catalog validator. Its separate counter factory captures D1 and the loader only in the request. `countHit` keeps shared Origin/bot checks and all legacy branches, but selects the exact organic event before the legacy limiter. With no trusted injected service it remains off. Strict `{e,c}` validation precedes the independent organic budget, which issues a server-only single-use admission receipt. Only then may the trusted service perform cleanup/catalog/D1 work. The receipt is a frozen opaque object whose metadata lives in a module-private WeakMap. `countAdmitted` gets and deletes that entry before any await or caller-controlled operation, without a second budget charge and checks time, UTC day, cleanup health and the exact catalog lease. No IP or request is passed to the service.

The existing production `/hit` route still supplies no service. This package does not choose or publish a catalog, bind the route table, schedule cleanup, establish cross-isolate health, emit browser events, alter schema/retention/disclosure, or deploy anything. The later integrated package must supply the fixed first-party catalog and request-scoped binding, preserve daily cleanup while collection is off, and test durable D1 cap health across UTC rollover/isolate boundaries. Existing local minute limiting remains isolate-local; no global anti-abuse guarantee is claimed.

## Measured validation

- Pinned Node 22.23.4: baseline 363 tests; corrected aggregate 373 pass. The ten new Node cases cover immediate competing rejection, owner timeout/cancellation, late generations, hard expiry/clock regression, failed/malformed/oversized refresh, default-off/shared Origin/bot checks, strict body admission, one budget before cleanup, receipt replay/UTC rejection (including replacement of `take()` and construction through `receipt.constructor`), and independent legacy/paid/global limits.
- Actual local Workers/D1 suite: 25 tests across nine files pass. The new D1 case exercises separate request-scoped counters sharing only the catalog, concurrent refresh rejection, retained aggregate/day-cap counts, duplicate catalog rejection/retry and a captured receipt crossing UTC midnight. This D1 test runs in one test invocation; separate request ownership is measured by the probe below.
- `node worker/test-probes/employer-request-context.mjs` with pinned Node/Miniflare/workerd: separate local fetch invocations overlap while the owner streams synthetic catalog bytes. The competitor returns false, the owner completes, and a later invocation reuses parsed membership. Zero outbound requests (the outbound service throws if called; Cloudflare context fetching is disabled). No production route, catalog or binding is used. This local probe does not establish behavior across deployed isolates.
- JavaScript lint: zero errors/warnings. Existing synthetic cache API/core tests remain green. No site files, screenshots or golden artifacts change.

Cloudflare documents that request-owned I/O cannot be used by another request ([runtime errors](https://developers.cloudflare.com/workers/observability/errors/#cannot-perform-io-on-behalf-of-a-different-request)), binding-only changes can reuse isolates ([bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/#making-changes-to-bindings)), and local fetch events can be dispatched through Miniflare ([test API](https://developers.cloudflare.com/workers/testing/miniflare/core/fetch/)). The pinned installed Miniflare version uses `convertV4MiniflareOptions` for its compatibility configuration.

## Open privacy blocker; not ready

Independent review found two receipt bypasses at `5096f4d4`. Both reproduced before correction: overriding `take()` admitted the same receipt twice; `new receipt.constructor(...)` minted admission after the organic budget was exhausted. The private WeakMap correction rejects both and retains only an unforgeable object identity; regression tests now pass.

The inherited raw-address limiter does **not** provide reliable idle erasure in Workers. `node worker/test-probes/employer-minute-idle.mjs` reproduces this with the actual limiter factory in local workerd: a request fills a synthetic address budget and schedules the normal expiry for 20ms later, then returns. After a 150ms host-side wait, another invocation observes zero timer callbacks and an exhausted entry when queried with the same synthetic minute. A next-minute call clears the old map. This is a source-plus-local-runtime finding, not a production measurement. Only a documentation-reserved synthetic address is used; the probe makes zero outbound requests. It deliberately preserves this failing privacy property as a blocker rather than claiming the test repaired it.

The counter is still dormant. Do not mark this PR ready or wire production intake while the raw-address lifetime claim is unresolved. No limiter or approved data-policy change is made here.

A candidate for a separate approved correction is to compute an HMAC over the UTC minute and validated address inside each request, using an isolate-random secret, and retain only bounded minute-code/count pairs. Raw addresses would not enter shared state; no shared crypto promise or request object is needed. The same address/minute must yield the same code, preserving the 30-hit cap and 2,000-entry bound. Hashing must follow shared/body checks, and a late digest crossing a minute boundary must fail closed rather than reopen an older bucket. However, pseudonymous codes and key material may remain in an idle isolate until the next request clears/rotates them or the isolate is evicted. This is **lazy expiry**, not guaranteed deletion after 60 seconds, and requires an explicit policy decision. Per-isolate keys also retain the existing per-isolate limit boundary; they do not create a global rate limit. Request-local-only state would weaken the cap; [`waitUntil` is limited to 30 seconds after an HTTP response/disconnect](https://developers.cloudflare.com/workers/runtime-apis/context/), so it cannot guarantee every next-minute expiry. Durable coordinated state would be a larger retention/binding change and is outside this package.

Corrected-head independent review and fresh CI remain pending. The entire worker stack remains owner-controlled and dormant.
