# P-2.1w Staged follow proof

The opt-in helper receives a writer proof and the exact tree ID produced by staging. It requires the Git index to identify that tree before and after validation. It uses the existing writer validator on that immutable candidate, with raw Git object reads for the listing index and slim shards. The raw staged listing paths must also match those seen by the validator. This keeps Git archive line-ending conversion or an ignored extra slim shard from changing what the proof covers.

The index generation and SHA-256, the complete shard key set, and every shard SHA-256 must match the in-process proof. A partial, stale, or mismatched candidate yields no receipt. Only the verified receipt exposes the #334 evidence conversion and the immutable index and shard bytes for that candidate. The receipt describes a staged candidate. A later caller must still bind consumption to the actual accepted publication.

The helper adds no public files and never stages files, commits, pushes or sends data. The existing command-line writer does not call it and retains its default behavior. Cross-run lineage, staged-to-published handoff, writer release, archive publication, and operator activation remain separate.
