# P-2.1di Bounded Follow maintenance through the Worker scheduler

A distinct operator-supplied cron string selects the Follow maintenance branch in the actual Worker entry. The branch requires a separate enable flag and explicit deadline, page size and D1 call limit. Existing scheduled jobs keep their routing. No trigger is installed by this change.

Each invocation runs one page from each unfinished category in order. The database samples its existing expiry cutoffs and the Worker checks elapsed time before admitting another page. It reports whether the captured scan completed, exceeded its work budget or lost a trustworthy acknowledgement. A completed scan can leave a scope whose confirmation token appeared after the token scan. The next pass checks it again. A partial pass carries no progress into another invocation. The scope and orphan pages come from [#612](https://github.com/bpmcginley/InternshipFinder/pull/612). The invocation has no access to the email binding or delivery owner acquisition.

Before release, use the actual backlog and database allowance to verify that complete passes finish within the approved retention windows. A prefix that needs more work than fits in one invocation can recur on every fresh invocation, so a partial result cannot establish retention coverage. The 0032 finalizer is required for the measured digest cost. Actual trigger timing, production rollout and sending remain separate.
