## Contract

`stage_follow_companies` is the actual dormant byte staging integration: it calls #518 `prepare_follow_catalog` on the complete immutable captured index, declared organic slim shards and majors, with explicit prior bytes/digest or explicit genesis. It compares the newly computed catalog digest with the trusted expected digest before using its exact aliases. It never normalizes a display name itself or reuses employer-counter annotations.

Only literal `enabled=True` admits work; omitted or other values return `None` without inspecting inputs. This is an internal API option, not a new production flag or default. The caller retains the original bytes when it receives `None`.

The caller also supplies independently pinned `first.json` bytes from the same trusted selected export and explicit positive byte/row/output limits. The first descriptor must identify that path and exact bounded row count. Every preview row must be an exact full-fact match to a captured open organic row, with no duplicate ID. Boolean/numeric fact substitutions, additional fields, another public spelling of the same company, closed/unknown rows and mismatched pins fail. Catalog validation already rejects missing/extra shards and conflicting duplicate listing IDs. Preexisting `follow_company_key` is rejected even when correctly pinned.

The result contains an immutable mapping of declared slim shards plus `first.json`, the existing immutable catalog receipt, and the verified original preview hash. Current open rows receive only `follow_company_key` from the approved alias map. Closed rows are left without a key. No paid index, saved snapshot, description, feed or unrelated file is an input/output path. Eligibility here means current open organic company availability, exactly as #510 defines; it makes no claim about later digest eligibility.

The selected input must be an exact dict with at most `26**2 + 4` entries before its snapshot copy. Input byte/row/key bounds are enforced by #518/#510; separate preview bytes/rows and total returned annotation bytes are bounded. No limit is chosen for production. Output serialization is deterministic. The source digest continues to bind ORIGINAL captured bytes, not the annotated output. Every original row fact is preserved. No output is returned on any failure; the helper does not open paths, write files, fetch, publish or retry. A future publisher must stage the complete returned set atomically; this helper does not claim filesystem atomicity or independent freshness/commit provenance.
