# P-2.2ao Attached checkout recovery HTTP

Draft [#472](https://github.com/bpmcginley/InternshipFinder/pull/472), needs-bruce. Built on reviewed #464 and normally integrated its published merge 82c3c429. Add a separate session-authenticated bodyless POST at /billing/topup/recover. Reject query and body input, require the existing dashboard Origin policy, and send no-store for every outcome. Missing historical provider configuration returns 503 disabled before recovery. Other outcomes are 401 auth, 403 unavailable for disallowed Origin, 400 invalid request, 405 wrong method, 429 limited, 202 pending, or 200 open, settled, expired or inactive. Only open can carry the bounded validated Stripe URL.

Use the stored attached Checkout ID and historical Price configuration, independent of current sales. Open recovery requires an unpaid hosted Checkout, the exact associated historical offer and economics, an unexpired provider Checkout, matching trusted dashboard return URLs and an exact Stripe URL for the attached ID. A final D1 read checks the exact attempt tuple, revision and session using database UTC. The request clock rechecks both deadlines after the read. Use #464 for paid and expired state changes. Recovery performs bounded GETs only and cannot create a replacement Checkout. Allow three requests per account and 30 globally per UTC minute in the existing rate table under recovery-only buckets. Check for an attached attempt before charging the budget. The existing cleanup removes prior-day buckets. Provider read phases keep the existing 22-GET and 1,835,008-byte combined caps. A successful open uses two GETs.

The Worker route uses the existing dashboard Origin policy and trusted configured dashboard root. The authenticated GET /me response includes only can_recover_topup: true when historical configuration is ready and its exact session account owns an attached open attempt. The lookup uses the active-attempt index and does not call Stripe. With recovery unconfigured, GET /me keeps its existing output and does not perform the lookup. App and account deletion clients are separate.


Shared fixtures exercise the real bodyless HTTP boundary, absent configuration, wrong origin/account, verified open URL, stale revision, revoked session, expiry, settlement, pending and both rate caps. The synthetic transport rejects any POST. The mounted route tests verify the account hint, CORS, absent configuration, the existing disabled purchase response and zero provider POSTs. Existing #464 and signed webhook scenarios run through the same test entrypoints.
