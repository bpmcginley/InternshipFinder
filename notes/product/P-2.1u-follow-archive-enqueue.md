# P-2.1u Archive-qualified follow enqueue

The dormant coordinator handles one subscriber ID supplied by an internal caller. It reads the bounded confirmed scope set and asks the archive reader for a verified latest snapshot covering the oldest watermark. The archive transport sees only the configured public manifest and digest paths. The existing matcher and enqueue helper then reread the current scope set, check each scope's coverage, and compare all scope lifetimes and watermarks in the transaction.

The reader returns the verified exclusive enqueue deadline with the snapshot. The qualified path checks an explicit monotonic Worker clock after the progress read and digest calculation. The first mutating D1 statement independently checks SQLite UTC time against the snapshot generation, the exclusive deadline, and the admission's UTC day. An elapsed cutoff or rollover blocks both a new queued job and empty-window advancement. The pending row remains tied to the exact new job in the same batch. A valid matching window queues without advancing progress. A valid complete window with no matches may advance progress without creating a job or daily marker. Gaps, stale archives and blocked writes do not advance it.

Synthetic archive transport, Node/SQLite and actual local Workers/D1 tests exercise matches, no matches, stale and gapped windows, exact Worker cutoff, and an already-expired or rolled-over database clock. A DB fence rejection follows the existing transaction conflict result. There is no retry loop. Existing direct enqueue callers retain their prior behavior.

The caller supplies the archive URL, transport, clock, catalogs and limits. Archive publication and retention, subscriber enumeration, scheduling, sending and operator activation remain separate.
