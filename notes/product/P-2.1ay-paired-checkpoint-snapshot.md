# P-2.1ay Paired checkpoint snapshot

[#497](https://github.com/bpmcginley/InternshipFinder/pull/497) adds a dormant provider-neutral source reader on exact main `8a8fbe744947cc521862db389018abb379775a80`. It supplies the existing private HTTP GET contract with accepted and pending bytes from one control snapshot. The production entry, legacy SQLite body store, mutations, workflow and provider configuration remain unchanged.

The caller supplies a synchronous native SQLite transaction returning the original control JSON and database UTC milliseconds, the separately qualified witness read, the reviewed bounded slot reader and canonical payload codec. Missing dependencies never select a fallback. Control JSON is bounded to at most 64 KiB, each header to that configured control bound, and each reconstructed body to the caller limit of at most 8,000,000 bytes. The native fixture uses 16 KiB control, 2,000-byte headers and 3,000,000-byte body limits. Combined output is at most two body limits. These are technical bounds, not provider configuration.

Strict control/phase schemas, canonical headers, typed identities, UTC-derived original expiry, predecessor association, slot separation and opaque witness classification precede body release. Both slot objects must match the captured nonce, ETag and digest. The codec verifies original canonical bytes. After reconstruction, the reader checks the witness again and synchronously captures the exact unchanged control and a non-regressing UTC time. Every returned body must still be live. No await follows that final capture. Any malformed, prepared, missing, changed, unavailable or expired-during-read observation returns only `unavailable`, never a partial pair. An upload reservation remains held. A committed live pending record remains readable after its expired accepted predecessor is retired and cleaned, matching prior per-phase qualification.

The existing HTTP handler retains its authenticated, no-store framing: `active`, `expired`, `never_seeded` or `unavailable`, followed by exact accepted/pending byte lengths. An unavailable snapshot is HTTP 200 with both lengths zero, preserving the existing client contract. The native harness invokes this actual handler against local SQLite/R2 and a simulated witness. It also compares successful bytes to the existing per-phase reads, exercises concurrent control/witness/object changes, clock regression, real expiry during a slot read, predecessor cleanup, malformed metadata, prepared/closed witness, absent control and size refusal. Existing mutations and their qualification stay intact. All 74 native cases pass through the registered 120-second Node wrapper, including 16 new cases, and the full Worker Node lane passes all 811 tests. Pinned lint, formatting and whitespace checks pass.

This is read-source integration only. The test witness is not a qualified durable provider, and the fixture bootstrap is not production initialization. External witness atomicity, physical retention and restore evidence remain unverified under #450. Injected I/O still requires an independently qualified whole-operation deadline and cancellation boundary before production selection. The private entry remains default-closed and still selects the unqualified legacy store when explicitly enabled. A complete mutation adapter, durable initialization/recovery, operator/provider approval and production selection remain separate work. No provider call, deployment, activation or sending occurs here. Public assets are unchanged, so screenshots and golden regeneration do not apply.
