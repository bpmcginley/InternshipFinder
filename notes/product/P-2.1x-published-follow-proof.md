# P-2.1x Follow proof bound to accepted data

The dormant Python call returns the existing publication result and an optional follow receipt. The ordinary writer and CLI keep their existing return and output. The shared writer checks for a no-op before attempting staged proof verification. Expected proof verification failures leave ordinary listing publication independent.

The receipt is issued only through the writer's existing accepted outcomes. These cover an acknowledged push, including a retry after an unrelated remote update, or an ambiguous acknowledgement resolved by the existing fetch and equivalence checks. The accepted commit must descend from the original candidate and preserve all ingest-owned bytes in the staged tree. Its exact public subtree must match. The receipt carries that commit, subtree and immutable staged listing bytes. It does not reread the checkout to hand those bytes to the fixed-export adapter.

No receipt is issued for a no-op, rejected or unconfirmed publication, or mismatched proof. A subsequent Pages deployment, archive publication, cross-run lineage handoff and all dispatch remain separate. No default writer, CLI, workflow, configuration or public data changes are enabled.
