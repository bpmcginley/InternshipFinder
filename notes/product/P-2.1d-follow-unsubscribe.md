# P-2.1d dormant one-click unsubscribe

Stacked on frozen P-2.1c `195fe6f3`. The handler takes a Request, a local database binding and the deletion-only token supplied by a future router. It derives no identity from cookies, login, Origin or account data. It accepts POST with exactly one text form field `List-Unsubscribe=One-Click`, using URL-encoded or multipart form data. The 4,096-byte request limit is enforced on actual streamed bytes, even without a trustworthy Content-Length. Files and extra fields are rejected.

GET and HEAD return 405 without touching D1. Malformed requests return an empty 400. A validly shaped POST returns the same empty 204 for a deletion, replay, unknown token or wrong-purpose token. Responses are noncacheable. D1 errors escape the handler so a future router can return a retryable server error. The existing unsubscribe operation cascades subscriptions, tokens and digest jobs. It preserves the independent current-day send marker, and already accepted email cannot be recalled.

The future router must keep deletion available for existing links when signup or sending is disabled. It must accept an anonymous mail receiver's POST directly over HTTPS without an Origin requirement, challenge or redirect. A human GET preview may display a manual confirmation form without deleting anything. Preview copy, routing, middleware and bearer redaction in request logs belong to that later integration.

Cloudflare documents both `List-Unsubscribe: <https://…>` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` on the existing structured `EMAIL.send` binding. The current mail wrapper does not forward these headers. This slice leaves mail and order envelopes untouched. Future mock tests must assert both exact headers and the same deletion URL in the digest body. Before activation, an authorized delivered-message check must verify a valid DKIM signature covering both headers. Operator gates still include the approved sender and postal address, onboarded domain, deployed binding, recipient entitlement, measured quota with capacity reserved for order mail, and token-safe endpoint logging. Verification uses synthetic requests, fake storage errors and actual local D1 with synthetic rows. No production router, mail adapter, schema, deployment, real address or provider send is part of this change.
