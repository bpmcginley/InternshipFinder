Draft [#357](https://github.com/bpmcginley/InternshipFinder/pull/357) on exact #341 `f5dc2f90d0b7c39ecbb633f38987febb04bc550c`. `deliverFollowSnapshotDigest` composes one existing snapshot job lease, pinned preparation, canonical rendering, budgeted claim, final consent check and finalization. Its database, job, HMAC key, cap, clock, catalog/limits, bounded pin loader, presentation and transport are explicit trusted inputs. No provider binding, schedule, route, schema, token issuance, public copy, configuration defaults or activation changes.

The helper leases through `leaseFollowDigest` and prepares matching public roles through `prepareLeasedFollowDigest`. It reads the current stored recipient, then asks trusted server presentation code for approved sender, postal address, first-party links and eligible similar facts. Presentation receives only the prepared subscriber ID and copied public roles, never the recipient. **The caller must authorize every supplied private link for that exact subscriber and honor existing token purpose/expiry rules.** This helper grants no token capability or eligibility policy. It forces `to` to the stored recipient and `matches` to the pinned prepared roles, ignoring presentation overrides for those fields. Canonical `renderFollowMail` runs before spending a budget slot, so malformed presentation cannot consume one.

Only a `claimed` result from `beginBudgetedFollowSnapshotAttempt` can reach transport. `paused` returns immediately without a retry. Ambiguous/failed claims never authorize transport. New additive `authorizeFollowSnapshotTransport` reuses the outbox's existing consent and exact snapshot-generation/progress SQL. A read-only D1 batch binds the attempting job, exact lease, prepared subscriber and rendered recipient to current stored state; it checks same-day attempted time and valid captured progress. In that final SQL read, SQLite UTC now must be at or after attempted_at, on the attempted UTC date, and strictly before both lease_until and expires_at. The fresh monotonic post-read clock must still precede both deadlines on that UTC day. No presentation, token work or other await occurs after this final authorization returns before transport is invoked.

The final D1 read is the authorization boundary. A deletion after that read cannot recall a message already handed to transport; this is not atomic delivery with database deletion. The trusted transport must initiate immediately or reject busy; it must never queue internally behind another in-flight send after authorization. It must serialize actual in-flight sends independently of row cancellation and resolve only on known provider acceptance; rejection or uncertain acceptance must reject. A non-Promise result is treated as uncertain. This package calls no existing sender or live provider and does not alter `sendFollowMail` semantics. A permanently unresolved transport remains an attempted job until existing expiry marks it uncertain; it is never retried here. A future bounded transport/scheduler must preserve these constraints.

Known acceptance is finalized once as accepted; rejection, failed final authorization or other post-claim uncertainty is finalized once as uncertain, through unchanged `finishFollowDigestAttempt` and its existing progress triggers. Failure or deletion during finalization returns only unavailable. Daily markers and budget debits are never compensated. Pre-claim preparation failures leave a reclaimable lease; invalid pinned data does not advance progress. Returns contain only accepted, uncertain, paused or unavailable status, never recipient, token, role, job or provider details. No error details are logged.
