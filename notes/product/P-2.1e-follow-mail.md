# P-2.1e dormant follow mail envelopes

Stacked on frozen P-2.1d `7ffca463`. The isolated renderer uses the approved plain-text confirmation, management and digest copy from [the design](P-2.1-follow-design.md). The caller supplies an approved sender and postal address, one recipient, and links built from trusted route and public scope data. No sender, postal address, origin or route is selected here. The renderer accepts approved HTTPS origins for first-party links, and direct HTTP(S) posting links without credentials. Public matching and share URLs must be built independently of bearer URLs. The renderer additionally rejects recognizable follow tokens in those public slots.

Digest candidates must already be eligible public roles in the intended display order. The first occurrence by ID and posting URL wins, ignoring URL fragments for duplicate detection. Similar roles cannot repeat a match or one another. The digest includes up to two distinct similar roles, uses the approved singular heading for one, omits the heading for zero, and produces no message without matches. First-seen selection, matching, candidate ranking and token minting remain caller responsibilities.

Only the digest envelope adds `List-Unsubscribe` and `List-Unsubscribe-Post`. Its header and plain-text footer use the same HTTPS deletion URL. The adapter reuses `addressOf` and sends the structured message through `EMAIL.send` once. It logs nothing, suppresses provider error detail and leaves failure classification and consent revalidation to later dispatch work. Existing order and campaign envelopes continue to use the unchanged mail wrapper.

Synthetic tests assert exact subjects and bodies, both headers, distinct-role behavior, unsafe-input handling and fake-provider failure. No real recipient, mail send, provider setup, dispatcher, router, schedule or production configuration is included. Operator prerequisites include an approved sender and postal address, deployed binding, recipient entitlement and quota with an order-mail reserve, an HTTPS unsubscribe route available even when signup or sends are off, and delivered-message verification of DKIM coverage of both headers.
