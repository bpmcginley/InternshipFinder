# P-2.1ck Follow management route mount

[#551](https://github.com/bpmcginley/InternshipFinder/pull/551) mounts the reviewed management capability and link-request HTTP handlers. All four Worker routes accept POST only. Their existing JSON contracts are unchanged.

| Path | Body | Success |
| --- | --- | --- |
| `/follows/manage/list` | `[managementToken, null or cursor]` | `200 {scopes, next}` |
| `/follows/manage/remove` | `[managementToken, scopeKey]` | `200 {removed}` |
| `/follows/manage/delete` | `[managementToken]` | `200 {deleted}` |
| `/follows/manage/request` | `{email}` | Generic empty `202` |

When `FOLLOW_MANAGEMENT_ENABLED` is absent or differs from `"1"`, all four paths keep the existing 404 response before body or D1 access. Link requests also require `FOLLOW_MANAGEMENT_REQUEST_ENABLED="1"` and explicit safe integer strings `FOLLOW_MANAGEMENT_REQUEST_TTL_MS` and `FOLLOW_MANAGEMENT_REQUEST_DAILY_CAP`. Missing or invalid policy fails closed with the existing 503 response. List, remove and delete remain independent of link requests and mail. Existing confirmation, pending-request deletion and unsubscribe routes keep their original behavior.

The only admitted Origin is `https://internscout.org`, subject to the existing CORS allowlist. Capability tokens stay in request bodies. One instance of each existing factory holds its own four isolate slots, while the current DB, Origin predicate, clock or request policy stays scoped to the call. The handlers keep their existing byte and body deadlines, D1 fences, and generic failures. A link request only queues an eligible job.

No production settings, policy values, mail call, migration, public page or activation is included. Separate rollout must qualify schema, request policy, sender and coordinated page wiring. The immutable baseline fixture stays unchanged. Exact route tests exercise disabled and cross-origin I/O ordering, the current policy and binding, both independent limits, and real D1 management actions.
