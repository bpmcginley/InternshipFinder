# P-2.1dp Follow link mail presentation

A dormant adapter supplies the existing confirmation and management delivery ports with their established public capability URLs. It uses the confirmation and request-deletion fragments on `internscout.org/follows/action.html`, the management fragment on `internscout.org/follows/manage.html`, and the shared HTTPS unsubscribe URI from the generated Worker origin. The renderer uses that same URI in the footer and one-click header. The browser unsubscribe preview is tracked in [#620](https://github.com/bpmcginley/InternshipFinder/pull/620).

The release caller supplies approved sender and postal details and trusted public label maps. It must qualify those labels with the same catalog and retain labels for existing valid keys. The adapter takes an owned snapshot, checks the canonical scope against it, and displays trusted names. The existing summary slot uses `all fields` or `anywhere` for an unrestricted side. If the combined names exceed the template's 500-character limit, the summary shows exact field and state counts, for example `3 fields; 1 state`. The templates and subjects stay unchanged.

The adapter receives existing in-memory capabilities from the claim helpers. It creates no token, storage record, provider request, or schedule. The confirmation, deletion and unsubscribe slots reject overlapping credentials. No production sender, postal address, delivery limit, cadence or rollout is selected here.

The focused suite renders actual templates, asserts exact URL shapes and unchanged unsubscribe headers, exercises canonical scope and immutable catalog handling, and rejects malformed or repeated credentials. No provider calls were made.
