## Why a completed list remains unproven

Stripe's [Events list](https://docs.stripe.com/api/events/list) exposes up to 30 days. An event keeps its creation-time `api_version`, regardless of the current request version. The existing billing header therefore cannot identify the schema of every historical event. [Cursor pagination](https://docs.stripe.com/api/pagination) uses object IDs in reverse chronological order. [Webhook ordering guidance](https://docs.stripe.com/webhooks#event-ordering) also notes that distinct events can share a timestamp. No timestamp-only cursor or lexical ID tie ordering is inferred.

Stripe documents rare [event-generation failures](https://docs.stripe.com/events/manage-webhook-endpoints#event-generation-failures) where an event cannot appear in the list. Applicability of that public-preview health mechanism and complete historical coverage for this integration remain unverified. Terminal pagination, an empty list or repeated stable snapshots cannot establish the missing proof.

## Dormant source contract

Literal `enabled: true` is required. The caller supplies a copied exact #553 coverage tuple, trusted mode/schema tag, explicit supported event-version list, fixed integer-second created window, injected page reader and optional shorter deadline. No version, credential, origin or fetch implementation is selected by this module. The eventual page adapter must authenticate and bind its account/mode and fixed provider endpoint independently.

Before upstream work, configuration and the database capture must match exactly. The window cannot start before the epoch's containing second and must lie in the preceding 30 days. This includes the whole boundary second rather than skipping equal-time events; it proves no subsecond enrollment ordering. Requests contain only fixed `created.gte`/`created.lt`, limit 100 and a locally validated `starting_after` ID. Bounds are four pages, 100 events per page, 256 KiB per streamed body, 512 KiB total and ten seconds of nondecreasing elapsed time, with a real abort timer. The traversal phase is bounded; D1 capture/closure latency is not promised by the transport timer.

Envelope validation checks the fixed list path, status, typed pagination, primitive event IDs, exact mode/version, created-window bounds, reverse-time ordering and object envelope. Decoded JSON member names must be unique within every object, including escaped aliases; a bounded iterative scan rejects last-member-wins ambiguity before envelope use. Descriptor copies preserve every own key, including `__proto__`, for exact configuration checks. Equal timestamps remain valid; duplicate IDs, repeated cursors, unsupported schema, truncation, malformed UTF-8, excessive bytes and unknown transport close the exact captured tuple. No raw payload, IDs, cursor or event count are retained or returned. The external callback receives immutable query parameters and an AbortSignal. Cancellation and late-result fences prevent a late body or callback from returning a result.

A valid traversal returns only `unproven`, with no metadata write. Failure invokes #553 closure once. Only a committed exact CAS returns `closed`; stale or unknown acknowledgements return `held`, with no retry. Rotation during traversal cannot close the replacement epoch. Complete semantic event handling, #548 observations, generation/restore evidence and an authoritative coverage transaction remain separate.
