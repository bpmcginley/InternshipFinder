# P-2.3n Optional generated posting keys

Child of [#371](https://github.com/bpmcginley/InternshipFinder/pull/371), ordinarily integrated with main `074344a5` for the published Stage 4 renderer structure. The draft [#386](https://github.com/bpmcginley/InternshipFinder/pull/386) adds an explicit optional `PostingLinks` model to generated ordinary Open posting actions and the separate highest-paying rows. It copies public ID/key/URL bindings from a validated release stage, requires catalog agreement and rejects a known ID with a different URL or canonical employer. Unknown IDs receive no annotation. The caller must stage and render the same independently pinned export; this helper does not establish Git provenance.

Production supplies no model. Existing facade calls remain unchanged, as do all default golden artifacts. The opt-in change is only `data-employer-key` on direct organic posting anchors. No new or changed visible strings, links, CSS, browser state or requests. The existing `data-aa` marker and offer-script detection remain intact. Paid boxes, Auto-Apply anchors, feeds, widgets, email, dashboard and saved-only copies are outside this renderer input. Public digest example links remain a separate integration: they have no role ID in their render model and their renderer is claimed by #373.

The future Pages caller must publish annotated dashboard data, generated links and their matching catalog together. This package does not alter Pages, allowlisting, the browser emitter, privacy, Worker configuration, retention or deployment. Those integrations and parent review/owner merge remain separate.
