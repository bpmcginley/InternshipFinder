## Actual offline path

One additional native workerd/local-D1 case calls the actual default export `fetch` with a deployment-supplied signup descriptor, without the injected signup supplier. A literal-off request returns 404 with zero catalog GETs. The enabled request verifies synthetic first-party catalog bytes and creates the confirmation queue. The actual default export `scheduled` link branch consumes its separate exact descriptor, the same catalog digest and bound labels, then delivers one synthetic confirmation through mock EMAIL. The issued confirmation is consumed by the real HTTP route.

The existing archive fixture waits for SQLite time to become strictly later than confirmation, constructs one matching role, and pins its manifest and snapshot. The actual scheduled archive branch consumes the deployment descriptor and enqueues the job; its exact GET sequence is asserted. It does not send or change delivery ownership. The existing owned digest runtime then uses the reviewed capability builder and the same synthetic archive bytes to claim, issue capabilities, render, hand off once, settle and advance the watermark. This digest runtime is deliberately invoked directly because it is not mounted in the actual scheduled entry.

Both EMAIL handoffs observe the same singleton owner in running phase and the shared budget at one then two attempts. The digest advances its pending progress exactly once; a subsequent empty digest invocation sends nothing. Its newly issued List-Unsubscribe URL must differ from the confirmation URL. The exact digest capability is sent to the real one-click POST after signup/link/archive creation flags are disabled. Deletion and replay each return 204. Subscriber, scope, capabilities, digest, pending progress and watermark rows are gone; the daily marker and two spent budget attempts remain, and the owner is ready. The independently issued management capability from that digest is also accepted by the existing read-only management route before deletion. The earlier management-removal scenario remains separate.

All addresses, sender/postal values, catalog/labels, roles, timestamps, deadlines, cron selectors and capacity values are synthetic fixture inputs. Global fetch is replaced with a closed exact first-party byte map; unknown requests fail rather than reach a network. The digest archive reader also uses the existing synthetic in-memory reader. EMAIL fulfillment is a local test receipt, not evidence of delivery, DKIM, entitlement or provider acceptance. The local Request uses workerd-supported manual redirect mode and is passed directly to the handler; this is not a browser or live HTTP network rehearsal. No raw capabilities or mail are logged or retained outside the isolated test state.

The initial ready owner is test installation setup, never a repair/reset of a held owner. Ordered current migrations run locally; no production migration or configuration is applied. This single-subscriber pass proves composition, not production backlog capacity or fairness. Independently verified writer/artifact authority, private checkpoint retention/restore, actual deployment pins and provider configuration, scheduler cadence/capacity, G3/lead release and digest entry mounting remain separate launch gates.
