# P-2.1bs Linked Follow signup admission

This dormant package starts on published main `47b46b10`. It composes the existing anonymous signup admission with the merged [scoped linking helper #517](https://github.com/bpmcginley/InternshipFinder/pull/517). The parsed request remains `{email, link, scope}`. The server caller can supply `options.sessionProof` as the exact authenticated `{id, user}` hash pair. The helper snapshots that pair before the first await. An explicit link request without a valid proof shape remains unsupported and spends no rate capacity. An unlinked request ignores the proof.

Both paths use the same existing `*follow-signup` UTC-day rate bucket, limit and explicit D1 acknowledgement checks. The linked helper still owns session, expiry and scoped consent checks in the atomic database write. If revocation or a scope conflict makes the linked operation a no-op after the rate step, a well-formed empty receipt returns the same generic accepted outcome as a queued request. Returned status carries no mailbox, account, scope or job details. Missing, sparse, malformed or ambiguous database acknowledgements fail closed. A spent attempt is retained without refund or automatic retry.

Local Node 22 tests passed 34 cases and native Workers/D1 passed 28 cases across admission, scoped linking and the existing HTTP boundary. The new scenarios cover cross-path competition for one cap, existing anonymous and conflicting owner intents, unchanged confirmation progress, proof mutation and session revocation across the awaited rate write, and malformed or lost D1 acknowledgements. ESLint, Prettier and whitespace checks passed. The existing native HTTP tests continue to cover anonymous acceptance and unsupported linking without proof.

Production still needs a trusted first-party proof caller, coordinated signup and privacy publication, the approved catalog and release pins, migration and account-deletion readiness, and owner activation. The package does not mount a route, select operating limits or exercise any provider or real send.
