# 0.6.0 strict Worker SSE parsing

Draft [#443](https://github.com/bpmcginley/InternshipFinder/pull/443) is stacked on frozen [#426](https://github.com/bpmcginley/InternshipFinder/pull/426) `a422e3f8637fb62182c5b00aa33335be3c8af0b0`. Scope is the existing Gemini client parsing/stitching boundary, a new focused test, one existing streamed-response test fixture and this tracker/evidence. The final-wait fix stays in its parent. No Worker admission, financial accounting, guard, permissions, manifest, version, provider, package or release changes.

## Behavior

The old reader silently discarded malformed JSON data lines. An isolated offline probe against the exact parent accepted a later STOP fragment in one request after an earlier malformed data event. The new reader rejects the whole response, so no partial text or tool call escapes through `callWorker`.

The reader parses complete events, joins multiline data with newlines and supports LF, CRLF and CR boundaries split across transport reads. It preserves valid UTF-8 split at any byte, a leading BOM, comments/metadata fields, thought signatures, tool arguments, supported finish reasons and usage trailers. Invalid UTF-8, malformed JSON/non-object data, oversized data, truncated final events, provider error objects and malformed known Gemini containers fail closed. Later nonterminal candidate content invalidates an earlier finish reason; prompt feedback cannot bless unfinished candidate content. The whole body must validate before stitching returns a model reply.

Event framing follows the [WHATWG SSE interpretation rules](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation). The existing Gemini convention `[DONE]` is ignored as a completion marker, including the previously supported final unframed DONE trailer. It never substitutes for a Gemini finish reason, and candidate data after DONE is rejected. Invalid UTF-8 is intentionally rejected rather than replaced. Unknown SSE fields/comments remain harmless within the bounds.

The technical client ceilings are 4 MiB of raw response bytes and 1 MiB per event including its framing/fields. Smaller positive limits can be injected into focused tests. The reader checks before JSON parsing, requires a streaming body and cancels/releases it on exit. The old text-only test double now uses a real `Response`; there is no unbounded `res.text()` fallback. A single operation-level abort race preserves the original cancellation reason without retaining a reaction for every chunk. A stalled or noncooperative reader cannot hold a canceled caller or deliver a late result.

The review correction makes framing incremental over raw bytes: each byte is visited once and each complete line is decoded once. It does not repeatedly search or encode an unfinished line. A deterministic 524,307-byte event test measures decoder/encoder/search work at 32-, 128- and 16,384-byte transport fragments, rather than enforcing a machine-dependent elapsed-time threshold. BOM, CRLF and multibyte UTF-8 count toward the exact raw-byte bounds.

Completion follows the documented [Gemini Candidate and FunctionCall schema](https://aistudio.google.com/api-reference/generate-content#Resource:Candidate). Recognized terminal reasons retain their existing result mapping, including MAX_TOKENS; CONTINUATION and FINISH_REASON_UNSPECIFIED do not complete a response. Unknown/malformed reasons reject the whole stream. Empty or unrecognized prompt feedback does not substitute for a recognized block reason. A function call requires a nonempty string name and, when provided, object arguments; omitted optional arguments retain the existing empty-object behavior. This boundary validates wire shape, while the separately reviewed tool-schema package validates individual tool parameters before effects.

## Retry policy and release gates

This package preserves the existing four attempts, backoff sequence, token refresh and financial admission semantics. Rejected streams follow the existing upstream-error retry path. A malformed, truncated or canceled response can be ambiguous after a provider has already generated output or the Worker has committed acceptance; the current run identifier is not a demonstrated duplicate-generation guarantee. Coordinating that retry/financial policy is a separate upcoming package. No claim of duplicate-generation prevention or refunded cost is made, and no paid provider experiment was run.

Before 0.6.0 release, compare these client ceilings with the actual configured Worker `FUNDED_RESPONSE_MAX_BYTES` and `FUNDED_RESPONSE_EVENT_BYTES`, including framing overhead, using synthetic large replies. Worker values are operator inputs, not public fixed defaults; legacy response streaming has no corresponding fixed source ceiling. This package selects no deployment values. Parent integration, independent review, exact CI and coordinated post-refactor release qualification remain required. Existing user-visible upstream error copy is unchanged; no screenshots are required for this parser-only change.

## Evidence

- Exact parent baseline: 363 extension tests passed (358 top-level plus five nested retry cases).
- Final full extension suite: 381 passed (376 top-level plus five nested retry cases), including 18 new focused cases.
- Focused cases cover malformed-before/after-STOP, incomplete final framing, four failed attempts/three waits, multiline CR/LF/CRLF and byte-split UTF-8, signatures/tool arguments/finish reasons, blocked prompts, completion resets, invalid UTF-8 and containers, exact byte limits, single large transport chunks, missing readers and cooperative/noncooperative cancellation. Additional review regressions cover deterministic fragmented-input work, raw CRLF/BOM/UTF-8 limits, recognized terminal/block enums and malformed function arguments followed by a valid retry.
- Pinned Prettier on changed source/new test and scoped ESLint passed. Existing `worker.test.mjs` changed only its text-only response fixture.
- Guard source, its three test files and manifest are byte-identical to the exact parent. Site/golden assets and actual extension version remain unchanged.

All input, model replies, streams, accounts and URLs in verification are synthetic. No real forms, user data, provider traffic, production request, deployment or extension release occurred.
