# P-2.1bn bounded Follow catalog loader

Draft [#520](https://github.com/bpmcginley/InternshipFinder/pull/520) on actual main `ac1b2dbf1a143610d8e08de5652553d16d82492c`. New one-shot Worker loader/test and a standard-runner import directly after follow-catalog.test.js, coordinated separately from #517/#519 registry anchors. No existing reader/parser behavior, route, configuration, workflow, public path, provider or activation changes.

`loadFollowCatalog(options)` returns disabled unless enabled is exactly true. Every option is server-owned, never accepted from a signup request. Enabled calls require an injected fetch function, exact canonical HTTPS origin, release object `{url,sourceSha256,catalogSha256,notBefore,expiresAt}`, positive explicit byte/key/deadline bounds, and prior public valid Sets. The URL must be exactly canonical and same-origin, with no credentials or literal query/fragment delimiter (including empty trailing delimiters); no URL or fetch implementation is supplied by default. The two hashes must be explicit lowercase SHA-256 values. The parser's existing prior-set validation/copy loop is extracted into one shared helper, with its grammar and parser behavior preserved. The loader calls it before GET, so malformed company/field/state members also cause zero requests. Prior Sets and release scalars are copied before the first await. Missing/invalid configuration returns only unavailable.

The caller independently establishes release authority, prior public-key continuity and the release-validity interval in UTC epoch milliseconds. No TTL, production bounds, freshness timestamp or provider setting is invented here. The explicit clock defaults to Date.now and must stay nondecreasing. The current time must lie in `[notBefore,expiresAt)` before fetch and after every body read and parser await, and once more after the outer raced result resolves before returning availability. One absolute timer covers the full operation; fresh elapsed checks also enforce the deadline when microtask work delays timer delivery. Backward/invalid clock, expiry or timeout fails closed.

One credential-omitting, no-store GET requests manual redirects. Only a 200 Response with no redirect, an exact nonempty response URL, and a readable body qualifies. A present Content-Length must be a positive integer within the cap and match completed bytes. Stream chunks must be nonempty Uint8Array values and fit the remaining cap; copies prevent retaining mutable transport buffers. Fatal UTF-8, exact canonical serialization, pins, schema, aliases and prior continuity are delegated to the unchanged merged parseFollowCatalog. No partial sets are returned.

A successful result is `{status:"available",catalog}`; every failure is `{status:"unavailable"}` without URL/provider/error detail. Each invocation owns its controller, reader, timer and output Sets. Cancellation aborts pending fetch, cancels a known body and releases its acquired reader lock; a fetch implementation ignoring abort is still observed and its late body discarded. No retry, stale fallback, cache, stored response or shared availability escapes. A returned catalog is qualified at return time, not an authorization to cache it indefinitely or send mail; the later caller must retain the release boundary for any further asynchronous admission.

## Offline evidence

- Eleven focused loader tests plus seven unchanged parser tests pass. All transport URLs and responses are synthetic; no global fetch or network call is used.
- Cases cover disabled/invalid configuration with zero requests; cross-origin, normalized URL aliases and empty delimiters; exact GET options; fresh per-call Sets; copying release/prior inputs before await; redirects/status/blank-or-mismatched-response-URL/length/chunk errors; hash/source/UTF-8/schema/continuity failure; stalled body and late fetch cancellation; later independent recovery; clock rollback/expiry/deadline without timer delivery; expiry during actual parser hashing, reader lock release, and expiry queued between the inner parser check and outer return.
- The actual standard Node 22 Worker npm test passes all 839 tests, including the registered native checkpoint wrapper. New-file formatting, ESLint and diff checks pass. Apart from that narrow shared-helper extraction, parser behavior, employer/archive readers, backend/default public files and golden artifacts remain unchanged; no screenshots apply.

This source seam does not publish a catalog, configure an origin, establish trusted pins, activate signup or authorize sending. The backend producer/staging packages remain separately G3-held. Production values, trusted release delivery and final integration stay explicit coordinated release prerequisites.
