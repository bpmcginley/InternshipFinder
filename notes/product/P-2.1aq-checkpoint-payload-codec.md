# P-2.1aq canonical checkpoint payload codec

[Draft #471](https://github.com/bpmcginley/InternshipFinder/pull/471) starts on reviewed #468 `1931a526ded2d30cd21318078005a8faa2d70d67`. Own one new Worker codec, new Node/Python tests and synthetic fixture, one test registry import, this note and two tracker rows. No R2 adapter, SQLite/control store, witness, HTTP/entry, configuration or live-resource change. Offline qualification only; storage selection and activation remain separate.

The common payload contains exactly version, covers_after, index_sha256, shard_sha256 and the complete sorted rows array. Pending headers retain predecessor (including nullable checkpoint digest), candidate_commit, candidate_tree, public_tree and prepared_at. Accepted headers retain accepted_commit, public_tree and accepted_at. Closed lineage stays in the same payload as open lineage. Nonces, ETags, control revisions and active deadline calculations are not payload fields. Both original checkpoint formats remain version 1 and byte-identical after reassembly.

`createFollowCheckpointPayloadCodec` requires explicit positive safe-integer maximum checkpoint bytes, payload bytes, header bytes and rows. `split(bytes, phase)` intrinsically copies input, validates the exact structural shape and canonical spellings, and returns canonical payload/header bytes plus original-checkpoint and payload SHA-256. `reassemble(payload, header, phase, expectedSha256)` requires an exact expected original checkpoint digest; a different header, payload, phase or digest fails. Inputs are bounded before copying/parsing and output byte limits checked before UTF-8 materialization. Every valid string is ASCII under the original ID/shard/timestamp grammars, so recursive sorted-key compact JSON exactly matches Python's ensure_ascii formatter. Parsing rejects duplicate/noncanonical keys, extra fields, ordering/duplicate-row errors, invalid calendar instants, trailing whitespace, escaped alternate spellings, malformed UTF-8 and BOM. Errors are generic and never include checkpoint contents.

These checks establish a canonical structural representation, not eligibility or storage authority. They do not reverify public source shards, raw Git ancestry, lineage observations, source-generation relations, active time windows or current control revisions. The existing trusted Python validators remain responsible for those proofs; this codec must only be composed after their evidence has been qualified. In particular, a matching digest is not permission to expose, promote, clean or restore a checkpoint. No current clock or new time/retention policy is introduced.
