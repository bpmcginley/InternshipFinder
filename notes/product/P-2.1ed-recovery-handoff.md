# P-2.1ed detached recovery handoff

Draft #640 stacks on exact #606 `5823a8898b88f89fa064f26a81e93b8a5c0ea29d`. Only `scripts/follow_recovery_handoff.py`, `backend/tests/test_follow_recovery_handoff.py` and this note are added. The existing detached adapter, checkpoint writer, archive planner, Ingest CLI, workflows and publication outputs are unchanged. The inherited #606 historical GitGuardian security hold remains unresolved. This package neither dismisses nor bypasses it.

## Dormant caller boundary

`recover_follow_handoff` is disabled unless explicitly enabled. Its trusted caller supplies the independently verified predecessor source, immutable original pending candidate checkout and native index, existing checkpoint client, exact `AcceptedFollowOperation`, fresh named-ref observer, canonical intent bytes, explicit byte limits and the existing checkpoint bounds, UTC clock, absolute monotonic deadline and optional original forward seed.

The six intent fields are `run_id`, `run_attempt`, `ordinal`, `expected_predecessor`, `candidate_commit` and `public_tree`. The wire is an ASCII JSON array with sorted object keys, compact separators and one final LF. Caller byte bounds are checked before decoding or JSON allocation, with technical ceilings of 4096 journal bytes and 1024 bytes per entry. Exactly one to three entries qualify. Duplicate members, including escaped aliases, noncanonical wire, extra fields, bool/string numeric aliases, nonconsecutive or reordered ordinals and conflicting candidate identities fail closed. Adjacent identical predecessor/candidate/tree identities can represent an unchanged retry; a candidate cannot reappear after another group. All retries retain the same raw public tree. The first predecessor matches the supplied source and the first candidate matches the original private pending candidate. The final ordinal and full identity must equal the independently trusted accepted operation. Empty/no-op or missing journals yield no receipt.

The operation authority is copied with #606's existing strict validator before any callback. Its original UTC observation, including submillisecond precision, and private pending generation are preserved. The journal becomes local immutable primitive tuples. Neither a journal, a Python record, a matching Git tip, a trailer nor a successful workflow authenticates an accepted push ordinal or exclusive writer. This helper does not obtain or invent that authority.

The observer must independently acquire the current named `refs/heads/data` and its raw public tree on every call, with replacement objects/grafts and ambient overrides excluded as required by P-2.1cr/#606. It returns exact typed `NamedFollowRef(ref,commit,public_tree,observed_at)` evidence. A cached local HEAD or a prior push response is not an admissible implementation. Each observation must match the accepted commit/tree and have an original-or-later nonfuture UTC time. Ref identity, time and monotonic deadline are checked both before recovery and after its acknowledgement. The handoff reuses #606 `_detached_environment()` before any observer or clock callback, snapshots its permitted `GIT_*` environment and requires that exact environment before and after each callback. Both prohibited overrides and changes to otherwise permitted Git identity values fail closed. The helper never repairs or mutates process environment. The caller remains responsible for immutable binding/source configuration and trustworthy callback implementations during the dedicated process.

## Mutation and publication are distinct

This is not a verify-only function. It invokes existing `recover_detached_follow` at most once, which can load private checkpoint state and perform the existing promotion CAS. The existing adapter verifies the original pending generation, original candidate HEAD/native index, accepted commit/direct predecessor and raw public tree, then reconstructs the existing typed publication receipt. No new checkpoint mutation algorithm, reset, push or retry is added.

The returned aggregate status is `disabled`, `held` or `recovered`. `checkpoint_status` is `not_attempted` before calling recovery, `unknown` if its outcome is uncertain, or the acknowledged `promoted`/`already_promoted` result. If the final named-ref check or deadline fails after acknowledged promotion, the result is **held with that acknowledged checkpoint status and no publication receipt**. The mutation is not undone, retried or represented as absent. Lost CAS acknowledgement remains unknown, even if the synthetic store physically committed. An environment/deadline failure detected inside #606 before its qualified return also remains unknown. The wrapper does not elevate an intermediate callback status string to acknowledged promotion. Only the existing adapter completed result supplies promoted/already_promoted; that acknowledged status is retained if the final observer later fails. Only a fully qualified final recheck returns the existing receipt for the unchanged #352 archive planner. This is not authority to publish artifacts or alter the current Pages receipt workflow.

Clock/deadline checks surround injected work and feed the unchanged recovery adapter. They withhold late results but cannot preempt a hung Git subprocess, observer or private request. The separate #501 outer process-group deadline remains necessary. No production duration is selected. Any later actual artifact publication must preserve its own exact release/current-ref checks.
