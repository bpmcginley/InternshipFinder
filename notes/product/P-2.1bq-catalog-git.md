# P-2.1bq raw Git Follow catalog acquisition

Draft [#522](https://github.com/bpmcginley/InternshipFinder/pull/522), stacked on corrected #518 `3ce64260f877fc834e1ea21d6d00e23f30dc22b6`. New `site/follow_catalog_git.py` and focused local-Git tests, this note and two tracker rows only. No existing selector/publisher/workflow, public/default/golden, Worker or provider changes. All backend catalog packages remain G3-held.

`acquire_follow_catalog(repo, *, enabled=False, commit, tree, timeout_seconds, **staging)` returns nothing when disabled. Enabled callers explicitly supply a full lowercase SHA-1 commit and its expected `docs/data` tree, a positive operation deadline bounded only by the platform timer limit, and #518's independent source/prior pins and byte/row/key limits. No Git ref/branch, HEAD, environment fallback or default repo is selected. The repository input must be nonempty, is frozen to an absolute path once, and must produce an empty Git prefix so a nested directory cannot silently resolve through its parent. The returned frozen receipt includes the verified commit/tree and #518's immutable catalog bytes and source/catalog/prior pins.

Git type and exact tree-entry checks bind the commit to that selected public tree. Only raw index, all declared slim shards and majors blobs are acquired. Regular Git modes 100644/100755 qualify; links, directories and gitlinks do not. Each blob size must fit the remaining aggregate budget before its payload command starts. Every subprocess stdout read is bounded before allocation, including metadata and one overflow byte; raw byte length and Git blob SHA-1 identity are verified. Manifest path grammar and file count are checked before traversing declared shards. A bounded names-only inventory of the pinned listings tree must contain exactly the eligible slim shard names declared by the index; omitted regular shards reject, while description/preview names remain unrelated. The unchanged byte-only #518/#510 stages validate complete counts/conflicts, prior continuity and exact framed source SHA before any receipt.

No checkout or export file is opened, so Windows CRLF conversion, dirty/missing checkout files and the prior stat-to-open race do not affect the result. Existing selector APIs provide checkout directories, while Core's private raw helper captures unbounded stdout; neither was changed or reused as an unsuitable bounded transport. The new small Git reader disables replacements, lazy fetching, all Git transport protocols, prompts and optional locks; inherited GIT_* repository/object/config overrides are removed. Child stderr is discarded. One caller deadline covers all child commands. Remaining time is sampled again after each process creation, and every post-creation exit, including timer construction/start failure, is kill-protected before waiting. Process creation itself is not preemptible; its elapsed time is never granted again. A final elapsed check also follows staging. Pure bounded parsing is not preempted mid-instruction. No ref, object, checkout or artifact is written by this helper.
