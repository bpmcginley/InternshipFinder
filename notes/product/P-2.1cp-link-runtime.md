## Callable contract

`createFollowLinkRuntime` is closed unless explicitly enabled. The caller supplies D1, an EMAIL binding, a synchronous trusted policy supplier and clock. Each invocation requires positive explicit `maxExpired` and `maxCandidates` (the dispatch helper's existing 1–64 range), plus its previous continuation when resuming. No cadence, sender, postal address, send quota or cleanup batch size is defaulted. The optional transport deadline only narrows #558's existing technical limit.

A sending policy supplies the explicit shared cap, trusted confirmation presentation function and management presentation/link builder. Configuration is copied before awaits. Selected cap, presentation strings/origins and function identities are checked again after cleanup, through the dispatch clock checks and immediately before transport. A disabled sending policy permits only bounded management expiry, without inspecting the binding or consuming send capacity. Missing/malformed policy, binding or limits fail closed. Async policy promises are rejected and drained. Capability construction and the existing renderer remain authoritative; this wrapper adds no link or email-copy policy.

The invocation runs one bounded expiry statement first. Unknown cleanup acknowledgements stop before dispatch, with no retry. It then invokes the reviewed dispatcher once, retaining its exact consent/expiry/claim fences, queue alternation, capacity pause and caller-owned continuation. One lazily constructed transport is reused. Overlapping invocations reject immediately rather than queue behind a previous database/transport operation. Any uncertain handoff latches subsequent sending held for this runtime instance, including after a late provider result; cleanup remains available. There is no reset/retry API.

## Entry and ownership boundary

The current `index.js` has separate clock, student-billing, campaign-report and daily-cleanup branches. This package does not add work to any of them or claim #555's entry file. A later mount must select a separately qualified event/cadence and invocation budget, obtain the policy from operator-verified values, and call this runtime through a durable global owner. That owner must serialize across isolates/restarts, preserve per-kind continuation and blocked turn, and durably hold/reconcile uncertainty before another send. Local occupancy and per-job durable claims do not supply that global authority. Recreating an instance after uncertainty is not recovery. No storage/retention choice is made here.

The production caller can pass its retained continuation into `run({maxCandidates,maxExpired,continuation})` and retain only the returned `dispatch.continuation` when present. Missing dispatch output grants no cursor advance. It must not attach this work to existing financial/clock invocations without a reviewed budget. The synthetic successful one-candidate path uses 16 D1 statements for either kind, including one management-expiry statement; this is fixture evidence, not a production cadence or workload guarantee. Trusted presentation functions must not introduce unaccounted I/O. D1 and presentation latency are not bounded by the Email acknowledgement timer.

## Evidence and gates

Shared Node and real local workerd/D1 scenarios cover explicit-off and malformed no-I/O, bounded expiry while sends are off, alternating resumed kinds, binding reuse, statement accounting, overlap rejection, actual committed-but-lost cleanup, policy disable during cleanup or after a committed claim, shared-cap pause and blocked continuation, unresolved/late transport and continued maintenance. All mail traffic uses a synthetic binding. Exact results are recorded in the PR.

Only management-request expiry is composed here. Existing subscriber/token/digest retention, midnight cleanup and provider/backup/restore proofs still need independently qualified maintenance. Actual sender/postal approval, recipient entitlement, quota/order reserve, public management/unsubscribe availability, delivered DKIM/header evidence and durable owner/cursor recovery remain mounting gates. No provider, settings, workflow, deployment or production action occurred.
