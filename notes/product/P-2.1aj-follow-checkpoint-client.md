# P-2.1aj Private follow checkpoint client

This detached Python client uses the four exact #388 HTTPS operations from one caller-configured origin. It requires a private Bearer credential, explicit bytes per slot and an explicit positive timeout. The TLS client context loads default trust roots and verifies the server certificate and hostname. Ambient `SSLKEYLOGFILE` does not enable TLS key logging. Each operation uses one direct connection, with no environment proxy, redirect or automatic retry. Application exceptions give generic errors and do not include endpoint, authorization, upstream response bodies or underlying exception text.

The timeout applies to blocking socket operations. The client also checks elapsed monotonic time between bounded body reads and rejects a response that completes after the configured interval. A blocking read, DNS resolution or header parsing can delay that check, so this does not establish a hard wall-clock deadline. Load checks the two advertised lengths, active state, HTTP framing and the exact canonical v1 records. Stage and promote send original bytes. Promotion checks the #378 typed payload digest and accepted identity and sends its exact old predecessor, pending generation and checked time. The store still owns atomic CAS and deadline decisions. Uncertain outcomes propagate for explicit recovery. Load is not authority to use lineage until the existing Git proof checks succeed.

Synthetic tests feed standard-library HTTP response parsing with fixed local bytes. They verify checked TLS configuration, exact CAS headers, chunked and fixed frames, duplicate and malformed responses, a timed-out read, a redirect and a lost reply. No socket connects in these tests. The #388 local workerd suite verifies the server side.

The client has no writer or workflow caller. GitHub runner integration, credential custody, private Access and bypass configuration, PITR and G3 release remain prerequisites. This package does not configure or contact a production account.
