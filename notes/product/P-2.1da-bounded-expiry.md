# P-2.1da bounded send-free Follow expiry

This dormant partial maintenance entry follows the independent-maintenance permission in approved [#563](https://github.com/bpmcginley/InternshipFinder/pull/563). It starts on `42973294`. It neither acquires nor releases ownership. The existing bulk retention helper and all callers are unchanged. No schema, scheduler, configuration, provider, public copy or retained field changes.

`expireFollowPage` requires literal opt-in, one explicit kind (`confirmation` or `tokens`), and a scan bound from 1 through 128. It scans at most that many rows in native rowid order and conditionally deletes expired candidates in the same atomic D1 batch. The deletion samples SQLite UTC. Confirmation jobs use their existing expiry regardless of claim state. Tokens use the existing expiry rule, including confirmation tokens belonging to unconfirmed scopes at least seven days old. Unsubscribe tokens with no expiry and live management tokens remain. No send, retry, budget reset, watermark advance or owner reset occurs.

The cursor carries only the kind, last examined signed-int64 rowid and a fixed rowid ceiling captured by a last-key seek in the first page's atomic D1 batch. It is ephemeral and database-local, not a retained capability or a content snapshot. Callers resume the returned cursor only after a known maintained receipt. `complete: true` returns null and requires the next pass to start from null. Deletions, explicit inserts, reused rowids or expiry behind a cursor are revisited on that next pass. Reaching the ceiling or a shorter page completes the pass. New tail inserts cannot extend the captured pass; the next reset sees them. A caller must not keep a cursor across restore/replacement or treat a pass as proof of timely retention. Lost/malformed acknowledgements return unavailable without a cursor or automatic retry. No cursor is stored by this package.

Each invocation uses four bounded statements in one batch: ceiling capture, page read, conditional deletion and direct change receipt. Both selection and deletion use a bounded rowid page rather than filtering an unindexed expiry column across all rows. A continued page seeks the integer primary key; an initial page reads only the first bounded rows. Token qualification probes the existing composite subscription key. Each deleted confirmation can update at most the singleton owner's matching cursor. Each deleted token can additionally cascade one unique request-deletion capability and delete at most one exact claimed linked confirmation job, which can redact the singleton cursor. Direct and native aggregate change counts are checked separately. Held/running phase, generation and next turn survive maintenance. Redaction cannot cancel or recall an already handed-off email.

## Exact coverage limits

This is not complete retention maintenance. Existing bounded management-request expiry remains separate. Unconfirmed scopes, orphan subscribers, digest jobs, pending progress and daily markers are not processed here. Scope/subscriber cascades and attempted-digest finalization can fan out; they need a separate work-bound analysis. Global expiry indexes are absent for several categories, so an unqualified `DELETE ... WHERE expired LIMIT n` is not a bounded scan. No new index or policy is silently added. Production cadence, ability to finish/restart passes within the approved retention promises, shared D1 budget, provider/backup retention and restore/hold-release authority remain gates.

## Synthetic proof

The existing Node and native retention wrappers discover the new shared scenarios. Native 20,000-row fixtures verify constant-size ceiling reads, signed-int64 extremes, initial and continued pages for both kinds, integer-key seeks, indexed correlated subscription checks, no temporary ordering tree and fewer than 100 rows read per measured statement for a seven-row page. Tests cover exact dependent cascades, held/running ownership, replaced jobs, seven-day confirmation expiry, preserved live tokens, reset after insertion behind a cursor, rollback, committed-but-lost acknowledgements and descriptor-snapshot receipts. All inputs are synthetic and no transport is called. Final test totals are recorded in the draft PR.
