# P-2.1z Archive-qualified subscriber batch

The internal operation on exact #341 takes an explicit page limit, optional subscriber-ID cursor and trusted archive and matcher bounds. It uses the existing confirmed-scope index to seek once per distinct subscriber plus one lookahead. A large number of scopes for one subscriber cannot turn the page lookup into a scan of all those scopes. The query returns no addresses, scope keys or subscription details.

A nonempty page reads one verified manifest and one pinned snapshot. Each subscriber uses the existing per-subscriber transaction and its Worker and database UTC admission checks. A subscriber outside the covered interval cannot queue or advance and does not prevent a covered subscriber from being processed. A malformed page returns an invalid result before fetching. Worker admission is rechecked after each transaction. An authoritative database UTC sample and a fresh Worker clock must both admit the archive at page completion before a continuation cursor is returned. Retrying the page reuses existing queue and watermark idempotency.

The result contains aggregate outcome counts and the next internal cursor if more confirmed IDs exist. The caller controls the schedule, durable progress and activation after owner review. The existing single-subscriber path and its archive coverage result remain compatible.

Validation on Node and local Workers/D1 covers confirmed-only pagination, multiple scopes, replay, per-subscriber coverage, expiration, malformed lookahead and an over-limit subscriber with 1,000 extra confirmed scopes. The local D1 page query used fewer than 30 rows in that fixture. All 466 Worker Node tests and 85 Workers/D1 tests passed. Scoped lint, formatting and whitespace checks passed.
