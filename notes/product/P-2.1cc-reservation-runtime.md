# P-2.1cc Follow checkpoint reservation runtime

[#540](https://github.com/bpmcginley/InternshipFinder/pull/540) moves the qualified reservation, one-use upload, reconciliation and expired-reservation cleanup from the native integration fixture into `createFollowCheckpointReservation`. The source defaults off. Explicitly enabled callers supply the existing checkpoint codec, SQLite control, payload slots and witness ports. The actual local HTTP stage harness now delegates to this source, with fault injection at its native fixture ports.

The engine persists the exact reservation and original cutoff before forwarding one conditional payload write. It holds on a missing or closed witness. An expired reservation can finish cleanup only from matching slot and witness evidence. Cold recovery checks the exact prepared journal, predecessor digest, original cutoff, and tombstone identity. A narrow SQLite method rechecks the journal and unchanged local snapshot, then commits the original successor and receipt before final witness acknowledgement. The in-memory upload receipt disappears on eviction. Recovery never replays a physical write from an uncertain outcome.

The local cases preserve the existing fault and rollback evidence, including a payload beating a stale cleanup ETag, lost acknowledgements, cold restart and original cutoff. The early-ineligibility test now exercises the real clock predicate with its original held and no-write assertions. One new native case proves default-off and closed-witness admission. All 78 focused native lifecycle cases passed. Full suite evidence is recorded in the PR.

The standalone entry still selects the existing raw SQLite store. Synthetic bootstrap, operator reject, published-slot reaping, alarms, private provider settings, retention qualification and activation remain separate.
