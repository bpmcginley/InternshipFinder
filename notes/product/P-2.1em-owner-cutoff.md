The parent checks its original release deadline before submitting owner acquisition and immediately before the captured send. A timely submitted D1 batch could nevertheless arrive after expiry, acquire the singleton and subsequently hold it without any attempted send. This package adds optional primitive `ownerExpiresAtMs` to the owned digest runtime and as the third argument of `acquireFollowDeliveryOwner`. It must be a positive safe integer, captured from an own enumerable data descriptor only after enabled/sending gates. Invalid values fail before database access; inherited or accessor authority is rejected without invoking it. Omission preserves the exact old link/digest acquisition query and parameters.

The opted-in ready-to-running UPDATE adds `AND ?>CAST(round((julianday('now')-2440587.5)*86400000) AS INTEGER)`, using the same millisecond UTC expression as migration 0025. This is an additional predicate on the existing exact version/phase/generation CAS, not a new view, field, migration or round trip. One ready lookup and the same two-statement batch remain. At or after cutoff, the UPDATE changes zero rows and the existing receipt path returns unavailable without an acquisition ticket, follow-up hold, reset, retry or queue mutation. Malformed/lost receipts keep their existing uncertainty; a batch that already acquired on time is not rolled back or reclaimed.

After catalog acquisition the release freezes one absolute cutoff as `wall + floor(min(deadlineMs - max(wall - originalWall, monotonic - originalMonotonic), catalogExpiresAt - wall))`. Original clock samples precede input validation, the fixed-public-input key probe and catalog reads. The result must be a safe integer strictly after the sampled wall time. Rounding down can conservatively refuse a submillisecond remainder, never grant extra time. The existing pre-submission guard still samples both clocks after the owner lookup; the bound SQL cutoff is never recomputed or extended there. Actual SQLite UTC decides acquisition even when the injected Worker clock lags. This does not add execution deadlines to unrelated later D1 operations or release an owner when already-admitted work becomes uncertain.

Native proof uses actual local workerd/D1 and synthetic bindings. A timely call is deliberately held until SQLite is past the catalog cutoff; the exact emitted UPDATE changes zero rows and owner/queue rows remain identical, with no budget attempt or send. Strict equality is tested without a flaky millisecond timer by replacing only the bound cutoff parameter with the identical SQLite-now expression in that single SQL step, keeping the emitted predicate unchanged. Separate cases prove exact legacy SQL/argument parity, fixed cutoff including earlier input/catalog monotonic delay, malformed cutoff/no DB, own-data option gating, and preserved running/held outcomes for lost/late acknowledgement after a real successful acquisition. Existing retained-snapshot, final handoff, shared-owner and legacy callers also run unchanged.
