# P-2.1cb: dormant management delivery composition

Draft [#539](https://github.com/bpmcginley/InternshipFinder/pull/539) stacks on reviewed #536 `74daffd2`. It adds `worker/src/follow-management-delivery.js`, shared Node/native tests and one test registry import. Existing claim, renderer, schema, routing and configuration bytes are unchanged.

## Contract

`deliverFollowManagement` requires literal `enabled: true`, an approved positive shared cap, an injected nondecreasing clock, presentation, synchronous link builder and immediate transport. Missing or malformed configuration fails before claiming. Accidentally async clock samples are rejected synchronously and their rejected promises are consumed without waiting. Presentation is copied before awaits and the existing renderer validates it with synthetic probe credentials, then with the current recipient. No sender, postal address, origin or URL default is supplied.

The existing atomic claim spends the original job and shared daily capacity once. A fresh single SQL query immediately before handoff checks the exact original subscriber, email, queue creation/expiry, claim ID, current management and unsubscribe hashes/generations, remaining scope, SQLite UTC and the claim day. The management expiry remains the claim's original 30 minutes. The final app-clock check rejects regression, midnight crossing and elapsed queue/token expiry. No await separates that check from invoking transport.

Only one invocation can hand off. A missing or malformed committed receipt, deleted or changed tuple, capability rotation or expiry returns generic `unavailable`. A throwing, rejected or non-promise transport returns `uncertain`. Neither outcome retries, refunds capacity or exposes credentials. `accepted` means the injected transport's fulfilled acknowledgement, not inbox delivery. An already handed-off email cannot be recalled by later deletion.

## Links and launch boundary

The builder receives copied management/unsubscribe credentials, and each output must contain exactly its own capability in both its raw and canonical parsed URL before passing the unchanged renderer's first-party private-link validation. All test URLs and postal values are explicitly synthetic. Their query grammar is fixture-only. Production management page/URL/fragment construction remains a separate reviewed contract. Existing renderer fragments remain forbidden for management and unsubscribe. This package adds no visible wording: it reuses the approved #177 management subject, body, 30-minute sentence and unsubscribe headers exactly.

A future caller must validate actual sender, postal address, allowed origins and the approved public URL contract, use a verified quota, serialize transport attempts, and invoke an immediate transport that never queues or retries ambiguous sends. Provider configuration, cleanup/retention evidence, scheduler and route selection remain gated. There are no provider requests, new persisted fields, public assets, production settings or activation here.
