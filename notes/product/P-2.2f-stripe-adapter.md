# P-2.2f dormant verified Stripe adapter

[PR #272](https://github.com/bpmcginley/InternshipFinder/pull/272), stacked on frozen #267 `c0996307febf2d8838db27111dc6035f4bd86993`. Approved top-up policy is $3 USD before applicable tax for 25 purchased runs. This build does not enable payments or publish terms; owner merge remains needs-bruce.

`prepareTopupStripe` requires `TOPUPS_ENABLED=1`, existing `PAYMENTS_ENABLED=1`, a private Stripe secret, a dedicated `STRIPE_PRICE_TOPUP`, and explicitly injected fetch. TOPUPS_ENABLED means Bruce has verified product/account eligibility and chooses to enable; no second eligibility Boolean or subscription offer is required. No private values are supplied here. Each preparation retrieves the dedicated price and expanded product, rejecting inactive, recurring, variable/transformed, non-USD, non-300-cent or non-exclusive-tax configurations. Exclusive tax behavior preserves the approved pre-tax amount independently of mutable account defaults. Capabilities are request-scoped, not a long-lived configuration cache.

The only shared billing change exports its unchanged Managed Payments predicate. The adapter reuses the pinned `2026-08-26.dahlia` request helper and site URL. It requests payment mode, hosted_page UI, quantity one, no adaptive pricing, fixed first-party HTTPS callbacks from a future trusted route, and the existing Managed Payments option. Attempt/account/offer/units metadata is repeated on the PaymentIntent; the attempt owns the idempotency key. No customer email, name or card fields are copied. Verification rejects mismatched mode, identity, metadata, price/quantity, totals, incomplete line items, or a URL outside the exact Stripe Checkout origin/session path. Errors use a fixed message; the injected wrapper blocks redirects and prevents private provider paths/error bodies from reaching the shared logger.

**URL/retry audit.** A future authenticated caller constructs the adapter, calls `reserveTopupCheckout`, then calls `readOpen` with the resulting server-owned open attempt. The first and later browser requests GET that same stored Checkout ID, revalidate the complete association, and return its URL only in the response. #267 stores no URL, provider body or private price identifier; this slice adds no storage. A creating/unknown attempt remains blocked, including after a timeout or lost create response. It must not blindly POST again: Stripe can prune idempotency keys after 24 hours. A paid, expired, mismatched or unavailable session returns no URL. ReadOpen is not authorization: future routes must bind the authenticated account to the row, enforce deletion/recovery barriers, avoid logging/cache retention of responses, and handle terminal settlement. A changed price/version/callback configuration can fail closed on an older open attempt; verified configuration-version recovery is still needed before rollout.

No route/index, limits, webhook, admission, deletion, recovery, frontend, schema, public assets or golden files change. Private eligibility/configuration, signed settlement with authoritative PaymentIntent/charge verification, refund-before-grant protection, unresolved-attempt reconciliation, account deletion and production activation remain separate gates. Retrieval does not grant runs or establish payment success. No provider requests, account inspection, payment, deploy, release or remote database operation occurred.

Fault matrices cover disabled configuration, unsafe callbacks/URLs, invalid prices/associations, provider ambiguity and hidden errors.
