# P-2.2y atomic sibling admission

Dormant [PR #376](https://github.com/bpmcginley/InternshipFinder/pull/376) on exact #375 `7f04fdd2`. This implements the approved #294 next-call boundary without changing first admission, callbacks, schema or live routing. Bruce authorized qualified lead merges/deployment; this draft **needs-bruce** still requires independent review, hosted CI and coordinated integration. No provider, activation or deployment action is part of this package.

`reserveFundedSibling` receives a trusted server snapshot of existing user/task/public run identity, exact generation and current task/call/budget limits. One D1 transaction requires the current Worker month and database UTC date, a surviving monthly/invite-funded generation, positive call count below the current per-run cap and no deletion fence. It increments one slot, creates a fresh server call ID and reserves the exact current account/free-day/free-month/overall estimate buckets together. Usage and invite balances are never charged again. A positive monthly allowance may already be exhausted because this generation is funded; zero allowance disables admission. Current paid/free plan flags apply to this call, independent of the generation's earlier calls.

Legacy, missing, swept or replacement generations cannot qualify. If the final failure commits first, the old generation is gone; if a sibling commits first, unchanged callbacks retain funding for it. Accepted/metered calls retain their per-run slots, whereas released calls free theirs. Callback queries use stored flags even if a caller passes stale plan data. Purchased funding remains excluded.

Each invocation represents a new server call; this is not an idempotent provider retry endpoint. An ambiguous D1 acknowledgement returns pending without a new call identity or provider permission, retaining any committed reservation. Do not automatically retry admission or refund an unknown result. Current authentication, task/rate gates and trusted configuration resolution remain the eventual caller's responsibility. The existing public run-ID and omitted-ID handling are unchanged and still belong to that caller.

Validation: normal Node22 Worker `npm test` **527 passed**; full actual local Workers/D1 **126 passed across 29 files**. Six shared scenarios compare actual existing `admit()` sequential accounting against first+sibling reservations with monthly and invite funding; exercise real sibling acceptance/release/metering and duplicate callbacks; prove concurrent per-run/budget caps and released-slot reuse; test accepted-generation paid-bucket changes, last-failure/replacement races, disabled/legacy/UTC/deletion/sweep gates, rollback and committed-but-unknown results. Inputs in the parity test come from the existing allowance/budget helpers. Scoped lint, formatting and diff checks pass. No schema, inherited runtime, public/golden or startup-route changes; no live provider or remote D1 calls.
