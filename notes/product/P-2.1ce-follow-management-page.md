# P-2.1ce Follow management page wording and link

[#177](https://github.com/bpmcginley/InternshipFinder/pull/177) approved the management workflow. This note asks for the few strings needed to display its actual responses and the exact first-party link shape. The page title, email label, recovery buttons, removal and deletion buttons, all-deleted receipt, invalid email and unavailable text stay as approved in #177.

## Exact proposed text

| Situation | Proposed text |
| --- | --- |
| Management link cannot authorize a list request | This management link is no longer valid. Enter your email to request a new one. |
| Generic management link request receipt | If this address can receive email, a management link is on its way. |
| First authorized page has no follows | You have no follows to manage. |
| Another page of follows is available | Show more follows |
| Scope has no confirmation timestamp | Pending confirmation |
| Scope has a confirmation timestamp | Confirmed |
| Selective removal was acknowledged | Follow removed. |

The same invalid-link sentence covers expired, revoked, replaced and deleted credentials. Show the same request receipt for an unknown address and for a queued or duplicate request. Show the approved all-deleted receipt only after an explicit deletion succeeds. A failed or uncertain mutation uses the approved unavailable text. The page presents scope facts as text and passes the server-supplied scope key and cursor back unchanged.

## Exact link and interaction

Proposed link shape is `https://internscout.org/follows/manage.html#token=<management-token>`. The management token has the existing canonical form and 30-minute lifetime. The page removes the fragment before loading resources, keeps the token in memory, and rejects query-bearing, malformed and duplicate token inputs. Use no third-party resources, referrer, analytics or persistent browser storage on the page. “Manage my follows” explicitly requests the list. Opening the link performs no API call. Selective removal and full deletion each require the approved named button. The API receives the token only in the existing JSON request body and enforces its management purpose.

Before publication, qualify the renderer for this exact first-party link, mount the reviewed body-only APIs with trusted origin enforcement, and test stale response and navigation behavior, pagination, unavailable results and focus. Capture before and after at 1280 and 375 pixels in light and dark. No page, route, renderer, stored fields, sending or activation changes in this design.
