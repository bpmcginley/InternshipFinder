# P-2.1dm private Follow archive staging

This dormant adapter bridges the existing typed `FollowArchivePlan` to a fresh private completed generation. It does not publish, replace the current archive, select an accepted-operation witness, or change the writer. Authored scope is exactly `scripts/follow_archive_stage.py`, `backend/tests/test_follow_archive_stage.py`, and this note.

## Contract

`stage_follow_archive(current, plan, parent=..., now=..., bounds=...)` accepts explicit prior raw bytes and the existing plan/bounds. It captures exact immutable byte values under the existing `max_entries + 1` file-count and `max_archive_bytes` aggregate limits separately for current and proposed maps before parsing or filesystem work. Only `data/follows/index.json` and lowercase SHA-256 snapshot paths are allowed. No prior path is opened. The existing `validate_follow_archive_transition` proves the exact predecessor manifest digest, every retained blob, canonical manifest, forward transition and original retention/enqueue cutoffs at the caller's explicit authoritative time. Empty genesis without a manifest cannot yield a completed generation.

The parent must already exist, be absolute, real and private, and remain exclusively owned by the caller through staging and later assembly. Every ancestor is checked for links/reparse points, including Windows junctions. A unique generation is created with exclusive files, bounded byte readback, regular-file/identity checks, then final full readback and bounded inventory validation. Directories request mode 0700 and files 0600; on Windows the caller must supply private inherited ACLs. This is not protection against a hostile concurrent owner of the filesystem, nor an ACL-provisioning tool.

Success returns a frozen receipt containing the generation directory, predecessor CAS digest, **final raw manifest digest**, and an immutable tuple of each relative path, SHA-256 and size. The final digest is the future reader's manifest pin; it is not `base_index_sha256`. Existing current file mappings and previous generations stay unchanged. Repeated calls create different private generations, never reuse output.

Failure returns no receipt. Only known files in the adapter's unchanged owned generation are removed, without recursive traversal. Unknown files or changed directory identities leave an unusable private orphan rather than deleting unrelated contents. A process interruption can likewise leave an unreferenced partial directory. No directory rename/swap or crash-atomic public commit is attempted. A later assembler must use only a successful receipt, reverify its exact files/pins, recheck current publication eligibility/continuity, and publish an entire artifact atomically under the separately reviewed publication contract. It must not discover a generation by scanning directories or resume a partial output.
