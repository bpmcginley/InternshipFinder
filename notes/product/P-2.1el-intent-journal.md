## Detached contract

`FollowIntentJournal` is disabled unless enabled is literally true. An explicitly opted-in trusted caller supplies run_id/run_attempt, positive journal/entry byte bounds, and a synchronous sink, then passes the instance as #650's observe_push port. Ordinary callers keep omitting that port. This package mounts nothing. Valid run/attempt integers are 1 through 2^53-1; caller limits cannot exceed 4096 complete bytes or 1024 per entry. Only exact PushIntent records and boolean phases qualify. All strings must be lower-case equal-width 40- or 64-character object IDs.

Each pre-push observation produces the complete prefix as compact, sorted-key ASCII JSON plus one LF. The exact six fields are run_id, run_attempt, ordinal, expected_predecessor, candidate_commit and public_tree. There are one to three consecutive ordinals. All rows retain one raw public tree. Adjacent identical retry identities are allowed; changed identity with the same candidate or a candidate reappearing after another group is rejected. Inputs become private primitive copies before the sink runs. The bounded shape is validated before JSON allocation, and encoded entry/prefix sizes before invoking the sink.

The sink receives immutable bytes and must return exact frozen `StoredFollowIntent(journal)` with a primitive bytes value equal to the entire prefix. A trusted sink returning this value asserts its own successful recording; equality alone cannot prove durability, authenticity or storage policy. No concrete storage backend, atomic file-replacement policy, retention period or cross-run persistence is introduced. The test file write is synthetic evidence only.

After a valid pre-push receipt, only #650's exact matching direct acknowledgement can set the final snapshot status to acknowledged. The snapshot contains the canonical journal and a separately copied PushIntent, not AcceptedFollowOperation or publication authority. A stored prefix without direct acknowledgement is pending. A malformed phase/record, out-of-order/replayed event, failed/mismatched/uncertain sink receipt or reentrant call permanently holds and clears exposed journal/acknowledgement. An accidentally asynchronous coroutine is closed without running or awaiting it. No failure is retried. #650 catches the generic observer error and preserves ordinary listing publication.

Inspect the final snapshot only after publish returns. Any later malformed callback also holds future snapshots, but this helper cannot revoke a copy a caller already consumed. It does not authenticate whoever invokes the observer; supplying the port to the reviewed trusted writer and keeping caller/process/checkout/endpoint configuration stable remain required. Sink/callback work must return promptly under an independently selected outer process deadline. No synchronous helper can preempt a hung sink.
