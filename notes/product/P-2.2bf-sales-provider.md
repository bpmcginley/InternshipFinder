# P-2.2bf Stripe readiness for new top-up sales

Draft #602 on exact main `c4056b78e39f4598f3a319df2c7ee5dc29c4b127`. Only the existing Stripe adapter, two synthetic fixture files and this note change. The signed webhook, attached recovery, subscriptions, employer payments, API contracts, schema, configuration and public copy keep their existing paths.

The new-sales capability requires an explicit private `STRIPE_TOPUP_MODE` of `test` or `live`, with no default. It also requires a nonempty primitive webhook signing key made of printable non-space ASCII. This local check establishes configuration presence and shape. Release still requires independent verification of the exact Stripe account, Price, endpoint, signing secret and delivered events.

The dashboard hint and offer use the same sales gate. Checkout retains its existing Origin and session checks. The adapter checks the Price against the captured mode before it allows a new attempt, then uses that mode for create/open responses. The captured provider key, signing key, Price and mode must still match after Price verification and at adapter admission and provider invocation. A settings change before reservation closes the request. A change after a creating attempt has committed prevents a new provider POST and preserves the existing pending recovery barrier.

Historical recovery still uses its independent configuration and the verified signed event's mode. Purchased balances are aggregated per user without a Stripe-mode filter. A test-mode deployment must use a separate Worker/D1 environment and signing endpoint. The live sales release requires the intended live mode and verified live configuration. This package adds no configuration values or production activation.

Six new shared scenarios cover absent/invalid settings with zero provider calls, preserved Checkout Origin and session ordering, mismatched mode in either direction with only one Price GET per route, valid-to-valid settings changes during Price and after the account read, a durable attempt without POST when configuration changes at reservation, and valid live-mode checkout. Existing valid test-mode and sales-off signed historical recovery remain covered.

The focused exact suite passed 78 strict Node tests and 63 local Workerd/D1 tests, including signed and attached recovery. Pinned formatting, lint and whitespace checks passed. All transports and accounts were synthetic. No real Stripe calls, deployment, merge or release.
