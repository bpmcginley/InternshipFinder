# P-2.2aa funded provider response boundary

Dormant [PR #384](https://github.com/bpmcginley/InternshipFinder/pull/384) on exact #381 `1044048b`, with released main/Q3 `91bbd859` merged ordinarily before implementation. This independent child establishes the provider-response boundary before the actual /ai coordinator. No existing dispatch, defaults, limits, Gemini transport or lifecycle source changes; no activation or provider calls.

`fundedProviderResponse` requires an already-authorized, freshly reserved exact call identity, a trusted bounded one-attempt `send` adapter returning the raw Response, trusted public response headers/model and synchronous authoritative usage pricing. Explicit positive integer maximum body bytes, event bytes and absolute attempt deadline are mandatory; this slice selects no production limits. `send` must bound its own transport and must not hide an explicit rejected HTTP response as an uncertain thrown transport failure. Never invoke this boundary twice for one reservation or retry a lost acknowledgment. The coordinator owns admission/authentication and must attach the returned completion promise to `waitUntil`.

Complete JSON or a complete SSE event must contain non-thought, nonblank text or a named function call with object arguments (or absent arguments) in the first candidate. Thought/signature-only content is insufficient. The exact call's acceptance commits before any reply is returned. Original UTF-8 bytes, whitespace, SSE framing and the trusted public header set are retained; no upstream headers or provider details are copied into public errors. Public success remains status 200. Internal failures use generic upstream/busy HttpErrors; no generation, call, provider request or payload is returned in errors.

An explicit HTTP rejection or a complete terminal no-answer response can release a still-reserved call. Unknown transport, malformed JSON/UTF-8, incomplete SSE, body/event overflow, timeout, interrupted output, missing usage, invalid price or uncertain acceptance retain the reservation/estimate. SSE buffering holds original bytes until the first complete usable event and durable acceptance. The monotonic clock is sampled before/after send and reads, before/after acceptance, before exposure and terminal metering, and after synchronous pricing. The deadline starts before send; the trusted send adapter still owns its bounded transport. A timer cancels stalled body reads but cannot extend the deadline when its callback is starved by microtasks. Expiry during acceptance can leave an accepted call but exposes no response. Explicit cancellation/stopped state prevents a pending read from turning cancellation into clean EOF. Cancellation retains the estimate; completion waits for any already-running metering batch acknowledgment. No outer timeout releases a reservation while a D1 acceptance is still running.

Metering uses validated nonnegative integer usage only after complete JSON, or clean SSE EOF following terminal output. A usage-only trailer can supply final accounting after a terminal frame; subsequent nonterminal content invalidates the earlier terminal accounting. SSE running totals before interruption are not treated as final. Metering failure never refunds or replays an accepted call. No prompt/reply is persisted or logged.
