# P-2.1y Follow archive planning from an accepted receipt

The offline Python entry point is `scripts.follow_archive_from_publication.plan_follow_archive_from_publication`. Call it from the repository with the backend installed or on the Python path. Obtain the receipt from the existing `scripts.ingest_data_writer.publish_with_follow_provenance` in the same trusted process. The planner does not invoke that writer. It requires the canonical accepted receipt and uses only its immutable staged index, shard and timestamp evidence. A staged-only receipt or a lookalike is insufficient.

The caller supplies the current archive bytes, the effective lower watermark, the planning time, the catalog, and the existing explicit snapshot, archive and source bounds. The planner checks the receipt byte and evidence limits before converting the evidence mapping. The fixed-export adapter checks the attestation and derives canonical snapshot bytes. The archive planner applies its existing retention and first-pin-per-UTC-day rules. Both the candidate and the selected planned pin must cover the supplied lower watermark. Missing or invalid evidence, a gap, an expired candidate, or invalid archive inputs yield no plan. A usable same-day pin may leave the plan unchanged.

The output is the existing archive plan with its base manifest digest. A later writer must still validate the actual current base and enforce the accepted publication and activation gates. This module does no I/O, configures no policy defaults, and advances no subscriber watermark. There is no archive publication, scheduled work or send.
