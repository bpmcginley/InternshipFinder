# P-2.1dy Follow digest role links

Design for Bruce's review. The existing digest template includes “See matching roles” and “Share these roles.” The dashboard share helper encodes a live filter, which can return a different set and cannot encode a digest formed by several company and search follows. The employer-buy index has a separate eligibility filter. Neither supplies a public exact-role view.

## Proposed public view

Use one first-party, noindex page for both approved link labels. The link points to the exact immutable digest snapshot and contains only its public digest and a bounded, ordered list of public role IDs. Keep these values in the fragment so they are not sent in the initial page request. Anyone with the link can see the same selection. The link carries no subscriber, email, follow scope, account, consent credential or tracking parameters. There is no per-link storage and no new retention period.

The page verifies the exact snapshot SHA-256, validates the complete role payload against its bounded public contract and requires every requested ID in the snapshot. It displays the requested roles in email order, links directly to their employer postings and provides a copy control for the same public link. It does not load current dashboard filters or replace a missing role with a different one. It reads only the matching first-party digest-addressed archive file. A missing, expired or invalid snapshot leaves the link unavailable. Retained snapshots follow the approved archive lifecycle and are never extended for share links.

Proposed copy for the new page:

- Page heading: “Internships from a Follow email”
- Intro: “These listings came from a Follow email. Check the employer’s posting before applying.”
- Share control: “Copy link” and “Link copied.”
- Unavailable state: “This list is no longer available. Browse current internships.”
- Link disclosure: “Anyone with this link can see these listings.”

## Similar roles and validation

Choose up to two distinct public open roles from the same verified snapshot. A candidate must share an employer or field with a direct match. Rank by shared employer, number of shared fields, number of shared states, most recent first-seen time, then ASCII role ID. Compare against each candidate's best matching role. Deduplicate by role ID and posting URL without fragment. A page and share link include the direct matches. The email uses the existing similar-role heading for one or two results and omits it when there are none.

Do not expose credentials or subscriber scope to the public page. Exercise exact role order and deduplication, unknown and expired digests, URL bounds, missing roles, hash mismatch, non-first-party links, copy feedback and keyboard use. Before publication capture paired 1280 px and 375 px screenshots in both supported themes. Validate emitted artifacts and old snapshot retention with the independently qualified publication workflow. This draft introduces no page, data, approval defaults, production workflow or email sends.
