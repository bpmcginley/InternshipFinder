# P-2.1cz dormant employer Follow model selection

This package supplies the missing pure bridge between paired annotation staging and the optional employer model. It is not imported by the publisher and adds no public switch, catalog location, file writes, provider operation or activation. Both preparation and selection require literal internal opt-in; omitted preparation inspects nothing and omitted selection returns the exact original model.

The integration base normally merges reviewed #575 `41253e5c22c985258a923a5bcb5a9f658aa68ce0` and #580 `8de2b273057b40ae342a15e1a6e24b9948f7ad81`. The merge preserves #575's STATUS and both golden blobs exactly. The twelve inherited catalog/staging/test/note paths belong to #510/#518/#570/#580. Only the new adapter, focused tests and this note are authored here. All backend source remains G3-held.

`prepare_follow_employer_selection` accepts an already validated `PairedAnnotationStage`, the actual organic rows loaded from that same original export, and explicit row/byte bounds. It retains both stage receipts unchanged. This is an internal trusted receipt handoff, not a new receipt authenticator: original source/catalog/preview pins, prior continuity and release freshness remain the caller's responsibility. No annotated export is fed back into raw staging.

Preparation compares public row facts and IDs against the Follow stage, checks catalog bytes against their receipt hash, and captures loaded facts and original row positions. It independently derives exact loader membership from captured slim-shard paths, excluding first preview, with the existing valid-row/URL, Canada and Canadian/US metro rules. A pre-prepare membership mutation or fact-identical row loaded from different shard membership fails closed. The ordinary loader's derived US metro uses its existing classifier; no display-name, slug, employer-counter-key or new normalization rule supplies Follow identity. Closed, absent, duplicate, preannotated or different-fact rows fail closed. Current signup companies and exact aliases are used; retained saved-scope membership is not signup availability.

Selection checks unchanged input-list length, each candidate's exact live object at its captured index and its captured facts. This costs O(candidate rows), not O(employers × full export). Replacement, removal, reorder or mutation of a candidate fails; an unrelated same-length replacement cannot authorize a different candidate. Before JSON encoding or copying, nested data is charged its exact compact UTF-8 JSON size, including quotes, escapes, punctuation and scalar digits, against the captured encoded row size. All candidate IDs must be unique before any copy. Spellings must be an exact list bounded by the captured alias count, with bounded approved names; arbitrary iterators are never materialized. The input cardinality matches the upstream maximum of 678 slim shards plus first preview. Only verified `follow_company_key` is added to copied rows. Existing `with_company_follow` validates aliases and captures the selection; its renderer still rejects mutated selection identity/spellings. Caller rows and models remain unchanged.

## Remaining release boundary

The inherited #575 renderer requires displayed company names/spellings to fit 200 UTF-8 bytes, while the catalog permits up to 200 UTF-16 units for alias text. A catalog-valid multibyte alias above the renderer bound is explicitly tested and held; this package does not broaden that existing renderer contract. Ordinary multibyte aliases within both bounds pass.

Publisher ownership remains with the held Advisor packages. Future integration must select the same original capture and both catalog receipts, prepare the adapter before any output, and explicitly enrich the real employer models. Immutable assembly of the standalone module's shared App imports is separate. No publisher/workflow/graph/STATUS file changes here. Production catalog publication, first-party signup supplier, sender readiness, coordinated rollout and G3 remain prerequisites; this adapter does not establish them.
