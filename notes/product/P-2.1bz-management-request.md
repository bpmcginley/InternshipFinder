# P-2.1bz: dormant management request enqueue

Draft [#535](https://github.com/bpmcginley/InternshipFinder/pull/535) is stacked on exact #531 `8227e619`. `enqueueFollowManagementRequest` defaults off and accepts only a parsed `{email}` request plus explicit positive safe-integer `ttlMs` and `dailyLimit`. TTL is bounded to at most the approved seven-day subscriber-linked outbox retention; no production value is selected. It reuses the existing email normalizer. Malformed input/configuration performs no storage I/O. Unknown inboxes, subscribers without any follow, and duplicate live requests receive the same accepted result as a newly queued request. It never creates a subscriber, follow, account link or token, and returns no identity or job identifier.

The existing rate-table conditional increment uses one fixed anonymous management sentinel and a `d:` UTC bucket. Every valid request, including absent/duplicate inboxes, spends the same global budget. SQL supplies the day; the queue statement also requires that day and the result rechecks it. The current UTC-day cap cannot be overshot by concurrent requests. Existing general `d:` cleanup applies; this adds no email/IP/account abuse marker. A later failed or ambiguous queue result never refunds or retries the admitted attempt.

One SQL UPSERT selects only an existing normalized subscriber with at least one stored follow, whether pending or confirmed. SQLite UTC fixes queued/expiry times at that statement. An unexpired job keeps its exact ID and timestamps, even if another request proposes a longer TTL. An expired job can be replaced by a new request. Migration0026 and its identical legacy mirror store only random job ID, unique subscriber ID, queued time and expiry time, with a subscriber deletion cascade and expiry index. No address is duplicated. The helper validates dense successful acknowledgements, exact zero/one write counts and an exact typed clock row. Unknown committed acknowledgements return generic unavailable without retry; there is no receipt readback that reveals inbox membership.

This is enqueue-only. It does not implement claiming, credential issuance, transport, a public route, configuration, visible words or activation. A later dispatch package must qualify current request/subscriber eligibility, exactly 30-minute management credentials, shared send-cap atomicity, immediate pre-transport deletion/generation/expiry fences and no ambiguous retry. The queue does not authorize sending. Future claiming must preserve duplicate handling without reopening a spent send. Exact production request TTL, re-request/cooldown policy and global request/send caps remain owner-gated. Scheduled deletion of expired pending rows must be qualified before activation; logical expiry alone does not prove physical retention. Provider quota, sender preview/retention, postal details and the reviewed management page/link contract remain separate.

SQLite clocks and local synthetic records only.
