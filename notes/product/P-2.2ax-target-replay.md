# P-2.2ax dormant bounded target replay

Draft [#573](https://github.com/bpmcginley/InternshipFinder/pull/573), based on exact #571 main `485995fc`. No caller is mounted. `replayTopupHistoryTarget` requires literal opt-in, one trusted event ID, fixed window/epoch/schema, an explicit bounded operation budget, historical offer resolver and synthetic or separately authenticated provider transport. It snapshots primitive key/Price and mode/schema/window data before awaits. No production value is selected.

The existing raw Events reader owns the fixed GET query. Existing traversal still owns duplicate JSON member rejection, UTF-8/body/aggregate limits, four pages of at most 100 events, descending timestamps with same-second IDs allowed, exact mode/version/window validation and terminal epoch check. Its omitted-option output remains exactly `unproven`. An optional target selects only one raw event in memory and also rejects connected-account/context envelopes. Nothing is admitted until all pages validate. No cursor or raw payload is persisted or returned by the composition.

After traversal, the composition rechecks the captured epoch and invokes the existing targeted association verifier once. A narrow optional `beforeObserve` port requires exact true; the composition supplies another exact epoch read immediately before observation admission. Existing callers omit the port and retain their behavior. The verifier rechecks its deadline after the callback. One caller-supplied budget, bounded by the existing ten-second maximum, covers pages and provider verification using elapsed time, a nondecreasing clock and abort. Response readers retain their existing stream bounds. Missing targets, ambiguous traversal or observation results close only the exact captured epoch, or return held when closure is stale/uncertain. No internal retry occurs.

The epoch check is an admission-time fence. Once #548 has been invoked, its hashing and D1 batch cannot be cancelled. Rotation, timeout or lost acknowledgement can therefore coexist with a committed observation. The result remains closed/held and is never retried internally. A later externally verified replay may deduplicate. This writes only the existing unlinked event digest and resets the existing purchase age/revision; it never advances coverage, reconciles balances, enrolls a purchase or authorizes erasure.

Shared Node and actual local Workers/D1 scenarios cover equal-timestamp pagination, missing/duplicate targets, mode/account/context mismatch, invalid terminal pages after a selected target, duplicate receipts, strict admission receipts, epoch rotation during verification, one credential snapshot, deadline/late-response cancellation, lost commit acknowledgement and post-admission rotation/timeout. Existing traversal/page/observation and signed recovery suites qualify unchanged callers. Exact results are recorded in the PR.

Source scope is the new composition, small optional seams in the two existing readers, focused tests/registry and this note. The test fixture repeats synthetic settled-payment setup to avoid changing unrelated test exports. No schema, router, webhook mount, scheduler, provider request/settings, public copy or live credential changes. Approved P-2.2am still requires authoritative completeness/restore evidence and a later every-event classification/coverage commit before production history qualification. Draft needs independent review and Bruce release.
