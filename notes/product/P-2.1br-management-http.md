# P-2.1br: dormant management capability operations

[#523](https://github.com/bpmcginley/InternshipFinder/pull/523) starts on exact main `6f0a5fee`. It supplies `createFollowManagementHttp` with three explicitly selected handlers. Nothing imports the factory from a public router. No schema, capability issuance, sender, public page, visible copy, configuration or activation changes.

The caller must explicitly enable the factory and supply a first-party Origin predicate returning literal `true`. Asynchronous predicates are rejected and their rejections consumed. Requests are POST only, with no query or fragment. Credentials enter only the bounded JSON body:

- List: `[managementToken, null | afterScopeKey]`.
- Remove one: `[managementToken, exactScopeKey]`.
- Delete all: `[managementToken]`.

The token is a primitive canonical lowercase UUID plus the existing 256-bit secret. Its stored hash, management purpose and original expiry authorize each operation. Reissue invalidates the prior token. The factory shares four in-flight slots and the existing absolute five-second body reader, with a 16 KiB byte ceiling and exact declared-length checks. Scope/cursor strings have a 4096-byte UTF-8 limit. Responses use `no-store` and `nosniff`, carry no address, account hash or capability, and return generic errors without caught details.

List returns at most 50 `{scope_key,created,confirmed_at}` records and a `next` key, or null at the end. Its indexed query reads at most 51 scopes, rechecks SQL UTC expiry and never changes consent. Each page is a current view, so concurrent modifications are not a frozen multi-page snapshot. Invalid capabilities return 410. Mutations retain the existing `{removed:boolean}` or `{deleted:boolean}` semantics, including false for absent replay.

Selective removal preserves the existing one captured admission timestamp for all three writes in its D1 batch. The HTTP handler captures it after body validation. A valid admitted operation may finish after token expiry. Every statement still checks the same exact stored capability and purpose. Adding independent SQL clocks to these statements could partially consume a confirmation token while leaving its scope, so this package does not do that. Delete-all is a single statement and adds the SQL-current expiry fence, with the existing helper default preserved for other callers.

Removal targets the current scope key under the inbox management capability. If a scope is recreated while another scope keeps that capability alive, the same tuple can remove the recreated scope. It does not identify an earlier subscription lifetime. Existing deletion triggers preserve sibling linkage/progress and cancel an outstanding aggregate referencing a removed confirmed scope. Accepted mail cannot be recalled.

Qualification passed 858 Worker Node tests and 12 focused actual Workers/D1 cases, plus pinned ESLint/Prettier, generated API verification and whitespace checks. Tests use synthetic Node SQLite and actual local Workers/D1. It covers indexed 50/3 pagination and exact cursor bounds, wrong purpose, expiry/reissue, inbox isolation, absent replay and current-key recreation, concurrent removal, rollback, confirmed-scope digest cancellation, default-off/Origin/tuple/byte/deadline/concurrency gates, and malformed D1 page acknowledgement. Native cases demonstrate delayed SQL expiry denial for list/delete-all and complete selective deletion using the admitted snapshot after the local database clock crosses expiry. No external traffic or private data is used.

Public routing, management request issuance/durable dispatch, a reviewed management page/link contract, provider configuration, retention/restore qualification and coordinated release remain separate. This package leaves every activation gate closed.
