# P-2.1br: dormant management capability operations

[#523](https://github.com/bpmcginley/InternshipFinder/pull/523) starts on exact main `6f0a5fee`. It supplies `createFollowManagementHttp` with three explicitly selected handlers. Nothing imports the factory from a public router. No capability issuance, sender, public page, visible copy, configuration or activation changes. Additive migration 0024 and its legacy mirror add one empty view and one trigger, with no stored fields.

The caller must explicitly enable the factory and supply a first-party Origin predicate returning literal `true`. Asynchronous predicates are rejected and their rejections consumed. Requests are POST only, with no query or fragment. Credentials enter only the bounded JSON body:

- List: `[managementToken, null | afterScopeKey]`.
- Remove one: `[managementToken, exactScopeKey]`.
- Delete all: `[managementToken]`.

The token is a primitive canonical lowercase UUID plus the existing 256-bit secret. Its stored hash, management purpose and original expiry authorize each operation. Reissue invalidates the prior token. The factory shares four in-flight slots and the existing absolute five-second body reader, with a 16 KiB byte ceiling and exact declared-length checks. Scope/cursor strings have a 4096-byte UTF-8 limit. Responses use `no-store` and `nosniff`, carry no address, account hash or capability, and return generic errors without caught details.

List returns at most 50 `{scope_key,created,confirmed_at}` records and a `next` key, or null at the end. One indexed token-authorized LEFT JOIN reads at most 51 scopes at one SQLite UTC instant. A typed all-null sentinel distinguishes an authorized empty page from an invalid capability. It never changes consent. Each page is a current view, so concurrent modifications are not a frozen multi-page snapshot. Invalid capabilities return 410. Mutations retain the existing `{removed:boolean}` or `{deleted:boolean}` semantics, including false for absent replay.

The new selective-removal path inserts transient token hash, scope key and captured request time into the empty `follow_management_removals` view. Its INSTEAD OF trigger checks the exact current scope and management capability against both captured time and SQLite UTC once. Scoped confirmation-token, scope and orphan cleanup then share that single SQLite step. Expiry before admission denies without any change. Once admitted, the complete operation may finish after expiry. Errors roll back the whole statement. Delete-all is also a single SQL-clocked statement. Existing helper callers retain their previous defaults.

Both new mutation paths require a literal successful D1 acknowledgement and a nonnegative safe-integer change count. Native D1 counts trigger and foreign-key changes, so legitimate counts can exceed one. An uncertain acknowledgement returns generic 503 even if the database committed. The handlers never retry automatically. The new selective path fails closed if migration 0024 is absent, with no legacy fallback.

Removal targets the current scope key under the inbox management capability. If a scope is recreated while another scope keeps that capability alive, the same tuple can remove the recreated scope. It does not identify an earlier subscription lifetime. Existing deletion triggers preserve sibling linkage/progress and cancel an outstanding aggregate referencing a removed confirmed scope. Accepted mail cannot be recalled.

Qualification passed 871 Worker Node tests and 27 focused native D1/migration cases, plus pinned ESLint/Prettier, generated API and whitespace checks. Tests use synthetic Node SQLite and actual local Workers/D1. It covers indexed 50/3 pagination and exact cursor bounds, typed empty pages, wrong purpose, expiry/reissue, inbox isolation, absent replay and current-key recreation, concurrent removal, rollback, scope-token/queued-job/orphan cascades, confirmed-scope digest cancellation and uncertain committed acknowledgements. Native tests delay the single read past expiry, check actual scoped index plans, and cross expiry inside a nested cleanup trigger while verifying complete removal. The new mutation also rejects an earlier Worker time when SQL UTC has expired the capability and rejects a future Worker time before SQL expiry. Migration tests compare full legacy and ordered-migration schemas. Transport cases cover default-off, Origin promises, strict tuples, UTF-8/bytes, deadline and four-slot concurrency. No external traffic or private data is used.

Public routing, management request issuance/durable dispatch, a reviewed management page/link contract, provider configuration, retention/restore qualification and coordinated release remain separate. This package leaves every activation gate closed.
