## Selection and request boundary

The actual native dashboard mounts the existing approved form below its filter/count controls, outside My List. Only explicitly selected fields and states enter the scope. Keys are sorted and deduplicated. No profile, search text, company, pay, class year or other filter is inferred or stored. Standalone Everywhere means an empty state dimension. Mixed Everywhere/state URL selections, remote/Canada selections unsupported by the current Follow schema, malformed keys and more than 64 distinct keys in either dimension make the entire mount unavailable; no truncation or silent broadening. The 66-field picker therefore cannot create a 66-field Follow under the approved current contract. Syntactically valid old/future field tags and two-letter state keys are preserved for authoritative server membership checks.

The default request is anonymous, even when the dashboard has an account. Optional linkage uses the existing unchecked consent and only a strict current native session. It binds the rendered token and auth generation before sending and again after the result, preserves the original expiry, and never retries anonymously. A scope/account change or unmount aborts the form and suppresses late feedback. A to B to A identity changes cannot reuse the earlier generation. Email and consent remain in the unchanged form's memory only.

The adapter calls the exact reviewed `POST /follows/signup` with JSON `{email,link,scope}`, an explicit signal, omitted credentials, no referrer/cache, redirect rejection and no retry. One absolute 12-second deadline covers fetch and the empty-body receipt. Only empty HTTP 202 can become the approved generic accepted message; server text/JSON is never displayed. Noncooperative fetch/read, cancellation, identity change, expiry, malformed status/body and failures remain generic unavailable. The Worker still owns current session revocation, catalog validity and atomic admission.

## Independent-review correction: raw URL provenance

Core intentionally discards malformed/repeated/overlength URL dimensions for ordinary dashboard filtering. Follow now checks the complete raw dimensions before that normalization and records only two ambiguity booleans in the existing history entry while this optional mount is enabled. Other history state is preserved; no raw query, email, credential or identity is retained. A missing/failed marker write prevents lossy normalization while ambiguity remains. No marker access/write occurs in default-off mode. Unrelated renders and sorting do not clear the hold. Explicit field or state picker correction clears only that dimension, and Clear filters clears both. A supplied saved search updates only its explicitly present dimensions. Reload and non-BFCache Back restore the same entry's flags; valid new navigation reads its own entry. Same-document traversal additionally requires raw scope and visible chips to agree, without changing Core filtering. The revision also fences in-flight request completion.
