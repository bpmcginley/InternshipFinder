## Reader boundary

`createFollowArchiveReader` accepts optional `indexSha256`. Omission (or `undefined`) preserves existing callers. Any supplied value must be a primitive string containing exactly 64 lowercase hexadecimal characters; invalid configuration throws before fetch. The reader captures that primitive value at construction.

After the existing bounded manifest read, the reader hashes the exact raw bytes before decoding or parsing JSON. It checks the operation's original deadline and abort state immediately after asynchronous hashing. A mismatch returns the existing unavailable/null result without a snapshot GET, alternative manifest, snapshot fallback or retry. Both latest selectors and queued `loadSnapshot` use this path. Existing canonical parsing, snapshot digest/date, coverage, original enqueue/retention cutoffs, transport paths and caller limits still apply. Cancellation during a noncooperative digest cannot start a late blob request.

A forward manifest may retain an older queued snapshot. The reader uses the trusted pin for that current manifest, then independently verifies the queued snapshot's original date/digest and retention cutoff. No queued job is redirected to the latest snapshot, and a correct manifest pin does not extend the old snapshot's lifetime.

## Production integration and rollback

The production adapter must require a trusted independently supplied pin, rather than relying on this compatibility default or deriving an expected digest from the response it is verifying. The pin must describe the **final raw manifest served by the accepted Pages artifact**. The writer's `base_index_sha256` is the predecessor CAS hash, not this final manifest digest.

Every changed manifest needs a newly qualified descriptor and reader, even if only `checked_at` changes. Release continuity must preserve every still-needed queued snapshot and its original cutoffs. During a propagation or descriptor mismatch, hold processing until the trusted descriptor and actual served bytes agree; never retry without the pin or accept an older manifest because it is otherwise canonical. A rollback requires separate release authorization and continuity qualification for the rollback artifact and queued snapshots. Restoring old index bytes alone, changing a pin from untrusted response data, or reusing a predecessor hash is not rollback proof. This package supplies no production descriptor, independent continuity authority or new expiry policy.
