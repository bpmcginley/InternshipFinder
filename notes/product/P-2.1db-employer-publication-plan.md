# P-2.1db dormant employer Follow publication plan

This is a pure, default-off in-memory planner on reviewed #594 `603b012d71bc944bb93b94cfa46a52107a7de432`. Only the new planner, its tests and this note are owned. No shared publisher/runtime/asset graph, workflow, allowlist or STATUS edits. No filesystem writes, public copy/configuration, publication or activation.

`plan_employer_follow_publication` requires literal `enabled=True`. Otherwise it returns `None` without inspecting any input, leaving the caller's default artifacts untouched. Enabled callers supply the already validated paired stage, actual same-export organic loader rows, a bounded nonempty list of employer models, explicit positive source-row/source-byte/model/aggregate-model-row/asset bounds, the existing `core_graph.plan(APP)` result, an independently trusted current App digest, and approved standalone bytes with their expected source digest. This is a trusted internal handoff, not release authentication or a reader of request-supplied configuration.

Before copying the graph, its file count and body byte total are bounded; path lengths are bounded too. Every included generation must have safe flat paths, complete reachable sibling imports, an entry, and its exact existing `core_graph` fingerprint. The entry must identify the explicit current generation, even when older retained generations are present. Both dependency files must match the whole reviewed #594 module SHA-256 values after LF normalization. The explicit current graph pin remains independent. This narrow release contract intentionally rejects changed helper bodies, even after their exports; future helper changes require a reviewed compatibility repin. It does not infer JavaScript semantics from declaration regexes.

The planner accepts the exact reviewed standalone opening comment and two static import declarations, with its independent source digest, and rewrites only their known byte spans to `follow-form.mjs` and `follow.mjs` in the current immutable App generation. It rejects raw/mixed/historical targets, query/fragment aliases, entry boot imports, dynamic or extra imports and invalid UTF-8. Rewritten bytes are hashed into a separate `js/follow-company-modules/<sha256>.mjs` asset. This path is a staged asset proposal, not an allowlist or public release change. The resulting mapping contains the supplied graph generations plus that immutable module; bytes and mapping are immutable.

Before any model selection or copy, the complete batch is checked for canonical `/internships/at/<slug>/` routes using the existing 80-character slug limit, excluding the publisher’s historical Altera redirect, and for an explicit aggregate row-occurrence ceiling. Dot segments, aliases without trailing slashes, external/empty/query/fragment paths and duplicate paths reject. All models then pass #594's same-export selection before any plan is returned. Duplicate paths, late invalid models, stale membership or catalog pins, and the inherited renderer's multibyte text limit fail the whole batch without changing caller rows/models. Label, spelling and selection logic are reused unchanged. The plan preserves both original stage receipts and returns selected model copies, assets, exact script URL, current graph digest and assembled-module digest. No result is returned on partial failure.

## Remaining boundary

The future publisher must bind acquisition/freshness/prior continuity, use these same captured rows and receipts, preflight its complete eligible model set before any writes, and replace the renderer's raw script URL with the returned immutable URL. The current renderer still emits its reviewed raw URL. This package does not write or select a catalog destination, change the publisher, or make failed filesystem writes atomic.

Old assembled modules and their corresponding App generations must be retained across fresh publication and rollback; this planner does not retrieve that history. Existing graph retention alone does not retain these new assembled modules. Cached older shared modules missing helper exports are ineligible. Publisher/Advisor ownership, asset allowlisting, coordinated graph/history integration, trusted catalog delivery, sender qualification and G3 remain gates. No production switch or activation is introduced.
