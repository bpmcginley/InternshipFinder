# P-2.2x funded call callbacks

Dormant [PR #375](https://github.com/bpmcginley/InternshipFinder/pull/375) on exact #367 `20d051ea`, implementing the approved #294 lifecycle. Bruce authorized qualified lead merges and deployment; this package remains a draft **needs-bruce** pending independent review, hosted checks and coordinated integration. Merge/deployment stay with the lead. No existing limits/router/schema/provider/default or public-copy change.

`acceptFundedCall`, `releaseFundedCall` and `meterFundedCall` use the full stored run key, random generation and call ID. Every dependent SQL write selects the same current call state inside one serialized D1 transaction; no caller estimate/funding flags or pre-read accounting snapshot authorizes a write. Legacy/missing/swept/deleted generations, wrong IDs and completed callbacks are inactive. Actual D1 reports three changed rows for deletion of the last run plus its two cascaded records; only that known statement admits this count, while other mutation results must be zero or one. Failed or ambiguous acknowledgements return pending without data/error details.

Acceptance atomically marks the call and generation accepted and consumes the existing first-Auto-Apply flag with its aggregate event. A future route must commit acceptance before exposing a usable response. Accepted calls cannot be released. A definitive failure returns only its recorded estimate and slot; source usage and original invite credit return only when the final sibling fails and no usable response was accepted. The run then disappears, permitting a fresh random generation under the same public ID. Terminal call IDs disappear in the transaction, so duplicate/late callbacks cannot authorize writes against a replacement.

Authoritative metering accepts only an accepted call, adjusts the exact captured month/day buckets, records optional token/task totals and removes the call once. Existing signed-delta semantics remain `MAX(0, stored + actual - estimate)` on existing rows; a missing upsert row starts at `MAX(0, actual - estimate)`. Paid/free/account flags come from storage, and metering leaves the run's call count/funding intact. Token counts and model labels are validated trusted accounting input; no provider ID, prompt or response is stored. Stream interruption or unknown cost leaves the accepted record and estimate intact until authoritative accounting or the existing month sweep. A pending acceptance is never a reason to refund or retry a provider request; a later inactive result alone does not authorize exposing a response.

Deletion follows the existing `forget` fence: current-month counters stay, and callbacks cannot recreate/refund deleted account records. Existing cleanup cascades the run metadata/calls; later callbacks are inactive and retain the pre-sweep estimate. Additional sibling admission and purchased generation receipts/restoration remain following slices. Tests seed synthetic, fully accounted siblings solely to prove this callback boundary; no new live caller is introduced.
