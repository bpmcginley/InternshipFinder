# P-2.1dk bounded orphan page lookahead

Draft claim stacked on frozen #612 `c2a524b1758467d55624f920477458dc8e821588`.

Own only `worker/src/follow-subscriber-expiry-page.js`, its existing shared scenarios in `worker/test-support/follow-subscriber-expiry-page.js`, and this note. Existing registered Node/current-native and 0029 wrappers will exercise the new scenarios. No scheduler, schema, configuration, bulk helper, STATUS or provider changes.

Expand explicit orphan `maxRows` from one to at most 128 examined subscriber rowids. Materialize the bounded page before indexed scope-absence checks, choose at most one orphan and preserve the atomic child/root guards. A page with no orphan may advance to its last examined key. A selected candidate advances only to its own key after removal, or retains the incoming cursor while still draining. Signed int64 cursors and the old `maxRows: 1` SQL/receipt path remain unchanged.

## Selection and continuation

The existing nine-statement batch retains its fixed pass-start ceiling, bounded aggregate count/last key and strict mutation receipts. For an explicit `maxRows` greater than one, a materialized scan first selects at most that many rowids. Only that bounded set is checked for scope absence, through the existing `(subscriber_id, scope_key)` index. The candidate is the minimum eligible rowid, and its predecessor is the greatest examined rowid before it. These values are returned as decimal strings, validated and copied once from their receipt descriptors.

All three mutations use the same bounded candidate query and still have their current no-scope guard. Within this atomic D1 batch, token and digest child deletion cannot change subscriber scope eligibility. Only the final statement can delete a parent, so candidate selection stays stable across the writes. No separate preflight lookup or extra D1 call is introduced.

- No candidate: advance to the last examined key, completing only when the captured scan ends.
- Candidate removed: the exact `DELETE RETURNING` rowid must match the selected candidate and sole direct deletion. Only then advance to that key, even when later healthy or orphan rows were examined. A substituted selector cannot certify removal or completion.
- Candidate still draining: conservatively retain the original incoming `after` value, including null. The predecessor receipt is checked for consistency but cannot authorize advancement. Removal before the next invocation cannot skip its successor. Re-adding a scoped subscriber at the same key preserves that subscriber and its children.
- Unknown or malformed acknowledgement: return only `unavailable`, with no automatic retry or certified continuation. A write may already have committed.

Explicit resets remain necessary to revisit keys inserted behind an earlier cursor or beyond its ceiling. `complete` remains a scan result, not proof that every retention category is empty or all due records were removed.

## Qualification

Nine new shared cases run through the existing Node, ordered-current 0031 and deployed-schema 0029 suites. They cover 20,000 subscribers with late orphan rows 300 and 400, no-orphan pages, partial child drainage, removed/re-added candidates, signed int64 endpoints, null first-candidate continuation, reset, malformed and unstable receipts, exact removed-row binding, impossible one-row and two-row cardinalities, lost acknowledgement and maximum page/child bounds. The inherited one-row behavior, TTL, owner redaction, budget preservation and rollback tests remain in place. Focused qualification passes 101 strict Node cases and 115 actual local D1 cases.

Native `EXPLAIN QUERY PLAN` verifies materialization after bounded rowid selection and a covering scope index probe. There is no global subscriber scan or temporary sort. Each of the four candidate evaluations examines at most 128 selected rows. Child and root mutations retain #612's bounds and existing indexes.

No dependency install, network provider or production binding was used.

## Release limits

This increases bounded reach through healthy subscriber prefixes. It does not guarantee eventual completion from an arbitrarily large backlog when every scheduled invocation discards partial cursors and starts over. #613 also requires its token and scope passes to complete before orphan processing. Production cold-start completion and cadence must still be qualified, or a separate reviewed progress/eligibility design is needed. This package stores no cursor, adds no scheduler behavior and does not activate maintenance.

An indexed due-first digest lane remains separate. The existing `(state, lease_until)` index can seek due attempting jobs. Global queued/leased expiry and seven-day created-time selection do not have equivalent indexes. They must not be substituted with an unbounded scan or a selector that changes to a different job between the existing ordered state transitions.
