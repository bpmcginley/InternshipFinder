# P-2.3m Employer catalog release staging

This package claims a new backend staging module and its focused tests on top of [#331](https://github.com/bpmcginley/InternshipFinder/pull/331). It implements the approved mapping in [#336](https://github.com/bpmcginley/InternshipFinder/pull/336) at `4e2d3eff`.

The dormant transform takes the complete dashboard export already pinned by a trusted caller. It checks the slim manifest, full shards and first-screen copies before returning listing annotations and their matching catalog as one in-memory result. It does not claim the ingest writer, Pages workflow, dashboard, renderers, tracked data or golden fixtures. Generated links, live publication and collection are separate.
The staging input is the exact index, every listed slim shard and its first-screen copy. The projection checks path and row/open counts, rejects conflicting copies and verifies that first-screen posting identity matches the full export. Only valid direct posting links get an annotation, including closed roles. The returned catalog and read-only listing-ID/key map are available together. No input file is rewritten. The trusted caller must verify the pinned export before staging and publish the matching generated links, dashboard output and catalog together.

The exact published data commit `b0abd45a` produced 2,794 canonical keys for 26,977 direct linked roles across 68 slim shards. The compact catalog was 43,509 bytes under the 256 KiB limit. The 12-row first-screen response increased by 49 bytes under local gzip level 6. Removing the annotations reproduced every original decoded row in order. Focused stage and parent catalog tests, Ruff and the diff check passed.
