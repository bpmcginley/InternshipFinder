# P-2.2ba funded SSE wire accounting

Draft #586 starts from exact main `0a2b668965e20b79959c48cb16df4956f009ea68`. The corrected #384 boundary is already in that ancestry. Only `worker/src/funded-provider.js`, its already registered shared Node/native tests, and this note change.

## Correction

The funded boundary previously counted decoded data payload and unfinished text. Comments, ignored fields and framing could evade that event limit, and the result depended on transport chunk boundaries. An independent baseline probe accepted a single comment event of 1 MiB plus one byte under a 1 MiB event ceiling.

The boundary now counts every original stream byte before decoding, semantic inspection, durable acceptance or enqueue. Constant-sized framing state recognizes LF, CRLF and bare CR. The terminating blank line belongs to the preceding event, including a split CRLF. An initial BOM-only blank line resets only after all BOM and delimiter bytes are charged. Comments, ignored fields and multibyte UTF-8 count without decoded re-encoding. Body bounds and deadlines remain separate. JSON responses do not use the event ceiling.

The semantic parser, exact output bytes and headers, configured thresholds, acceptance, release and metering rules remain unchanged. An invalid chunk before acceptance retains the reservation without exposing its bytes. An oversized later event errors the stream and retains the accepted estimate. It does not authorize a refund or terminal metering. A chunk containing both a usable event and oversized later framing is rejected before any acceptance.

## Qualification

All inputs and streams are synthetic. The focused extension and Worker Node lane passed 86 tests, including current Chrome stream/retry tests. The three native Workers/D1 groups passed 38 cases. These final native cases include the same-chunk ordering assertion using a controlled stream, because native Response(string) may split its bytes. The exact full strict Worker Node lane passed 1,124 tests with no failures or skips in 74.7 seconds. Scoped lint, formatting, generated API and whitespace checks pass.

A separate no-file probe compared the exact Chrome `readSSE` and funded boundary on 45 framing/limit/chunk combinations, including exact and plus/minus-one event sizes, BOM, CRLF, comments and UTF-8. All outcomes agreed. The probe reproduced baseline oversized-comment acceptance and corrected rejection. Existing shared tests cover 1 MiB plus one, event/body distinction, byte-for-byte successful output, cancellation, before/after acceptance and ledger/meter ordering.

## Remaining release boundary

This package changes no legacy route, extension, provider setting or production value. The two funded byte bounds remain operator inputs, absent from tracked Wrangler variables, and the configured mode defaults to legacy. A release qualification must establish the active Worker mode and bounds, then exercise actual synthetic Worker-to-Chrome responses. The legacy streaming path has no corresponding finite source byte ceiling.

Raw accounting parity does not assert full parser grammar parity. An independent probe confirmed the existing Chrome parser accepts bare-CR-only data framing while both the old and corrected funded semantic parser reject it. That behavior remains unchanged here as required. Production configuration, Worker deployment, Store release and any separate parser policy change are outside this package.
