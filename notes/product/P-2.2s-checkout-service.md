# P-2.2s dormant checkout URL service

[#345](https://github.com/bpmcginley/InternshipFinder/pull/345) is based on reviewed #342 `ecab9dfb`. `getSessionTopupCheckout` takes the local database, account hash, existing session token, trusted server-owned verified adapter and clock. The adapter defaults off and reuses the existing enable/eligibility gate; there is no new policy switch. Existing reservation, adapter, session, routes, schema and policies remain unchanged.

The service calls `reserveSessionTopupCheckout`, then snapshots the exact open attempt and current revision under the same session/account fence. The bounded adapter rereads and verifies the open provider checkout. A fresh monotonic Worker time and a final SQL read require the same live session, account, open attempt, checkout, offer tuple and revision before returning `{status: "open", url}`. The final read returns that exact session expiry; a second fresh clock sample after the awaited read must still be strictly before it. The existing session SHA-256 helper is private, so no shared helper export is changed. The session SHA-256 is only a transient SQL parameter, using the existing reservation algorithm; it is not stored in attempts. The service neither slides session expiry nor saves the URL. Authorization is checked at the final read; a later revocation cannot recall an already returned URL.

All other responses contain only a generic `disabled`, `pending`, `auth` or `unavailable` status. Errors, attempt records and provider/account identifiers are not returned or logged. An uncertain creation remains pending in the existing reservation and never causes another creation POST on replay. A changed revision or association requires a later fresh request rather than releasing a stale URL. No retry, settlement, dispatch or new transport is added.

Twelve shared synthetic scenarios pass in Node/SQLite and actual local D1: default-off, one-POST replay, ambiguous creation, wrong identity, revocation/expiry during GET, expiry while the final D1 read resolves, a different active attempt, changed revision, response tuple mismatch, clock/storage failure and read failure/disabling. All 492 Worker Node tests and all 91 local Workers tests pass; scoped ESLint and formatting checks pass. Actual Stripe adapter code uses injected synthetic responses only. No public assets, golden outputs, schema/migrations, router, limits or workflows change; browser/startup validation is not applicable.

Owner merge, authenticated route integration, approved publication/configuration, migration adoption and deployment remain gates. This package cannot activate checkout or make provider calls by itself.

The delayed-final-read regression was verified to fail on the initial service head (returning an open URL at expiry) and passes with the post-read expiry check. Revocation and association remain fenced at the final SQL read.
