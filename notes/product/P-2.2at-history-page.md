# P-2.2at dormant Stripe Events page adapter

Draft [#562](https://github.com/bpmcginley/InternshipFinder/pull/562), based on main `f817b811`. New `topup-history-page.js` implements the raw page port consumed by #556. Existing traversal, coverage, billing, schema, configuration and entry bytes are unchanged.

## Exact port

`createTopupHistoryPageReader` requires literal opt-in, an explicit request-version string and an injected, already-authenticated account/mode transport. No default fetch, credential, account identifier, request version or historical schema map is selected. The supported request-version syntax is a real calendar date with an optional bounded lowercase release suffix. Syntactic validity is not proof that Stripe supports that version or that it describes historical events.

The returned `readPage(query, signal)` accepts only the frozen own-data shape emitted by #556: `created` containing frozen integer `gte` and `lt`, `limit: 100`, and optional primitive `evt_` cursor. Extra filters, aliases, getters, symbols and mutable inputs fail before transport. URLSearchParams builds only `https://api.stripe.com/v1/events` with those exact parameters. The call is GET with manual redirects, the original AbortSignal and the explicit Stripe-Version header. Its options and headers are frozen. There is one transport invocation, no body and no retry.

Only a genuine status-200 Response with no redirect and the exact requested response URL is handed back unchanged. The adapter never reads, clones, parses or buffers its body. Non-success, unknown, mismatched and late responses are cancelled; errors expose only a generic message. Aborting rejects promptly even if the injected request ignores cancellation, and any later response is discarded. The authenticated transport must honor the fixed URL/options and bind the approved account/mode; this module cannot certify a caller-supplied port's authorization.

The [Stripe Events list reference](https://docs.stripe.com/api/events/list) documents the endpoint, created interval, limit up to 100 and object-ID cursor. It also states that event data retains its creation-time API version regardless of the request header. This adapter does not infer event completeness, object association or historical schema compatibility.

## Ownership and limits

#556 still owns the whole-operation deadline, streamed bytes/aggregate/page bounds, strict UTF-8 and duplicate-member parsing, window/mode/schema validation and exact captured coverage CAS. It is the only component that closes an invalid traversal's epoch. A valid list remains `unproven`, with no advance, observation or enrollment. This adapter has no independent timer or D1 access and must be used with the reviewed traversal bounds. Its AbortSignal comes from that traversal.

Shared strict Node and native workerd/D1 cases cover exact immutable request/URL/header/response identity, native Request manual-redirect construction, invalid zero-I/O inputs, generic throws/rejections and cancellation, noncooperative late responses, valid unproven traversal, non-200/redirect/unknown/duplicate-page closure, and rotation preventing stale closure. Responses and records are synthetic. No real Stripe, credentials or account settings are used. Exact results are recorded in the PR.

Account authorization, supported historical schema mapping, complete event association, provider generation/restore proof and durable coverage qualification remain separate gates. No health advance, retirement, mutation, new stored field, scheduler, entry mount, public wording or activation is added.

Independent review reproduced synchronous abort from injected response metadata: the Promise rejected but the body was not cancelled. A final finished/aborted check after metadata validation now discards it before any ownership transfer. The shared Node/native composition regression verifies one request, exactly one cancel call and underlying cancellation, plus exact captured-epoch closure. It failed on the prior source in both runtimes and passes after correction.
