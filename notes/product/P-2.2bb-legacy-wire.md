# P-2.2bb legacy SSE wire limits

Draft #589 starts from `ca219314ecbe3887eae0c82818cc26ad6d1a02fb`, including the corrected funded framing package #586. This source change adds a guard to the actual legacy streaming `/ai` branch. It does not deploy it or change financial mode.

## Source and limits

The shared `sse-wire.js` scanner is extracted from #586 without changing its raw framing algorithm. The funded boundary still applies its separate semantic-event ceiling and existing body/deadline limits. The legacy guard applies the same technical wire ceilings as the 0.6.0 extension, 4 MiB per body and 1 MiB per raw SSE event. Comments, ignored fields, BOM, multibyte UTF-8 and CR/LF framing all count. Exact-bound responses pass. A chunk exceeding either bound is canceled before either tee branch receives it.

The guard precedes the client/meter tee. At most 4 MiB of accepted raw bytes can accumulate for a slower client. Constant-sized framing state adds no growing payload buffer. The provider may supply an oversized individual chunk, which is rejected rather than forwarded. This does not claim control of the upstream implementation's own allocation.

Valid bytes, stream status and headers remain exact. The JSON branch is unchanged, including its existing full-body behavior. Initial provider fetch timing, semantic parsing, admission, retries, financial mode and configuration remain unchanged. A finite wire ceiling is not a wall-time deadline.

## Settlement and cancellation

The helper reports complete, limited or interrupted. A new byte-limit cutoff passes null usage to the existing settlement function, retaining the charged estimate and the existing first-autofill counter. A usage trailer received before the cutoff cannot reduce that estimate. No allowance release or provider retry is introduced.

Ordinary upstream read errors retain the existing usage-reader behavior and settlement. Client-only cancellation keeps the original tee behavior, allowing the meter branch to finish and settle a complete upstream response. Canceling the guard itself closes local state and releases its reader lock immediately, even if upstream cancellation hangs. A subsequently rejected pending read cannot touch an already canceled controller.

## Synthetic qualification

Nine new shared scenarios exercise the actual authenticated route through injected sessions and synthetic provider streams, plus the direct guard. They cover exact and plus/minus-one event/body ceilings, byte-identical success, unchanged JSON, provisional usage followed by cutoff, first-autofill, ordinary read errors, downstream cancellation, split UTF-8/BOM/CRLF, bounded read count and a late read rejection with hanging upstream cancellation.

The focused Node lane passed 69 cases. Actual local Workers/D1 passed 41 cases across legacy route, funded response and lifecycle groups. Scoped pinned lint and whitespace checks passed. The full strict Node 22 suite is running at this draft freeze. No actual provider requests or real account/profile data were used.

The read-only baseline at deployed-source `fa88b22b` forwarded synthetic responses of 1,048,734 and 4,194,459 bytes unchanged. The exact 0.6.0 client rejected the oversized event and body respectively. Those observations establish the source gap, not a measurement of live provider traffic. Task output-token ceilings are not raw SSE wire limits.
