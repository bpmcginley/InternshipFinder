# P-2.1bh bounded Follow catalog source

Draft [#510](https://github.com/bpmcginley/InternshipFinder/pull/510) on exact main `143f2149e24bce917227d7c91d04ab54e71ca341`. Producer-first boundary: one new pure Python module and its focused tests. The strict production Worker parser is specified below, not implemented. No existing request semantics, Worker files, routes, schema, subscriber reads, workflows, configuration, public assets or default output change. Held for G3, independent review and coordinated release.

`build_follow_catalog` receives exact captured index/shard/majors bytes from one trusted selected public export, an explicit `complete=True` assertion, mandatory approved retained public key sets and positive explicit source-byte/source-row/key/output-byte bounds. It never selects a Git revision, fetches, reads a database, infers freshness, chooses production limits or writes output. Its result is bytes only; a failing projection returns no partial artifact. Capture provenance and trusted delivery are future integration responsibilities.

All declared slim shards must be present with exact paths, counts and open counts. Duplicate JSON keys, invalid UTF-8, duplicate IDs within a shard, conflicting complete row facts across shards, invalid names/field keys and limit overflow reject the whole projection. Declared row occurrences, including cross-shard repeats, consume the source row bound. The shard-path grammar independently bounds file count. Input byte bounds are checked before JSON decoding. Descriptions, first-preview rows, paid indexes and rendered page lists are not catalog substitutes.

## Exact wire contract

Compact UTF-8 JSON, no trailing newline, object keys in this order:

`{"version":1,"source_sha256":"<64 lowercase hex>","signup":{"companies":[],"fields":[],"states":[]},"valid":{"companies":[],"fields":[],"states":[]},"aliases":[["<public display name>","<canonical employer key>"]]}`

Arrays are unique and sorted by JavaScript ordinal UTF-16 order. Alias rows sort by display name and map each current public spelling to its employer key. Existing `site.source.employer_key` performs normalization, including the existing Booz Allen alias. Page/checkout slugs are not keys. Company keys are at most 200 UTF-8 bytes; display names follow the existing 200 UTF-16-unit ceiling and an 800-byte bound. Field keys use existing lowercase/underscore tag syntax; states are two uppercase letters. No remote, country aggregate or arbitrary text filter is inferred.

`signup.companies` contains the canonical keys of open public rows, independently of whether an employer qualifies for a generated page. This is availability of a public company choice, not a promise that any role will pass the stricter digest eligibility/first-seen checks. `signup.fields` comes from that capture's majors vocabulary, including fields with no current roles; states reuse the existing shared US-place/Canadian-province vocabulary. Aliases cover current open-row names only. The current source exposes 66 fields and 65 geographic codes; catalog size is not the request-selection limit. Existing `canonicalFollow` still rejects more than 64 values in either request array. UI integration must explain/reject excess values, never truncate, discard unknown filters or broaden a saved search.

`valid` is the union of signup sets and the explicitly supplied retained sets. Retained keys must already be canonical approved public identities; the function validates their shape but never renames, derives them from subscribers, or decides retirement. The caller supplies the prior approved catalog's complete `valid` sets plus any explicitly approved public identities. Genesis requires three explicit empty frozensets. An empty complete export removes current company availability and aliases while keeping all retained valid keys. Future signup uses `signup`; validation of already saved scopes and matching use `valid`. Using the current company set for historical scopes would incorrectly invalidate a follow when an employer has no roles.

`source_sha256` binds exact input bytes, not freshness or authority: iterate full relative source paths in sorted order (index, majors and declared shards); for each path hash decimal UTF-8 byte length, colon, UTF-8 path, then decimal payload byte length, colon, exact payload. No wall-clock timestamp is added. Identical bytes and retained sets give identical output regardless of Mapping insertion order.

## Next parser interface, not implemented

A later pure Worker parser should take Uint8Array plus explicit byte/key bounds and expected source digest, fatal-decode only within the bound, and enforce the exact version/keys/shape/order above, key/name limits, sorted uniqueness, signup subset of valid, and alias-value set equality with signup companies. Exact canonical JSON reserialization must match the original bytes, rejecting duplicate JSON fields and alternate serialization. Only then return separate `signup` and `valid` company/field/state sets and an alias Map. A future bounded source reader must establish trusted artifact identity before parsing and must not accept a catalog supplied by the signup request. The interoperability test here parses only the trusted synthetic producer result; it is not a production parser or reader.
