# P-2.1cw paired annotation staging

Draft, G3-held, stacked on #570 `03eb8891a571268e47fe9546899c7353bf3a35d9`. Only the new pure helper, focused tests and this note are owned; shared STATUS belongs to the lead's checkpoint package.

`stage_paired_annotations` returns `None` without inspecting inputs unless `enabled is True`. Enabled calls require the existing Follow source/catalog/first/prior pins (or explicit genesis), existing bounds, and a positive explicit `max_combined_bytes`. It checks the exact dictionary type and existing 680-entry ceiling before copying the selected raw bytes. No paths, filesystem acquisition, defaults, clock or external I/O are introduced.

The existing `stage_follow_companies` and `stage_employer_postings` independently consume that same original snapshot and first preview. Neither consumes the other's annotated bytes. Both validators must succeed. The composition checks exact output path sets, row count/order and all original facts, including nested boolean-versus-number distinctions. It validates annotation presence/value against the existing receipts, then adds only `employer_key` and `follow_company_key` to original rows. Existing closed-row semantics remain: a direct closed role can retain its employer counter key, but receives no Follow key. Original row member order remains; only annotation members are appended.

The result is a frozen receipt containing an immutable file map and the two original, unchanged stage receipt objects. The file map contains the annotated slim shards/first preview plus the employer catalog. The Follow catalog payload and pins remain in the Follow receipt. The combined byte ceiling applies to the file map; the separately bounded Follow catalog is unchanged. Rejection returns no partial receipt and performs no writes. Default publication and fresh default rollback keep the original byte objects.

Future publication must select the merged rows and both catalog receipts together under the existing independent pins, continuity, freshness and release gates. The current employer preparation loads raw render models: optional employer-page Follow needs separate explicit model enrichment from this same selection. It is not supplied by this helper. Publisher/Advisor coordination and G3 remain open; no workflow, renderer, default output, public copy, asset, allowlist, runtime or activation changes are included.

Validation: 28 new focused cases and 68 existing Follow/employer staging cases pass (96 total). Cases cover literal opt-in/no inspection, original-byte identity, aliases, closed and non-direct rows, immutable/repeated receipts, exact combined bounds, independent pin failures, employer-only invalid input, partial/extra/reordered/truncated output, nested typed-fact drift, cross-annotation leakage, missing/wrong keys and annotated cross-feed rejection. Ruff and diff checks pass. Default golden and pinned real-export results are recorded in the PR evidence.

Pinned public-export qualification used raw Git blobs from `a4cc698d9c8d382402ef96ac9f60537990c466ca`, with sockets denied. All 68 slim shards plus first preview passed through the actual new composition: 35,039 row occurrences, 25,906 with both annotations, and 9,133 closed rows retaining the existing employer-only semantics. Every original parsed fact and row order matched, both independent receipts were exact, and feeding annotated shards back into the raw Follow stage rejected the original pin. The canonical path/row digest was `4faf3988507f8244023c130e043dbe299fbb396ca9f6d4868477f79e1a740773`. These are public fixture measurements, not traffic or signup figures. No dataset copy, public request or publication was needed.
