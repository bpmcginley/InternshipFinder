# P-2.1bc Checkpoint HTTP staging

[#507](https://github.com/bpmcginley/InternshipFinder/pull/507) starts on `b121343ebaa91ce60eeac8255b6d37279c331d92`. A dormant source coordinator supplies the existing HTTP `reservePending(body, maxBytes)` interface. The existing native SQLite/R2 harness mounts it alongside #497 paired reads. Production entry selection, the legacy SQLite body store, provider bindings, settings and workflows are unchanged.

The coordinator takes a bounded intrinsic copy before any await and validates it with the reviewed canonical codec. It never regenerates `prepared_at` or expiry. Trusted ports own the existing native reservation CAS, one-use upload receipt, reconciliation and qualified paired read. A small read-only projection returns a reservation nonce only when its exact canonical checkpoint digest matches and the current witness admits the control state. A different or unresolved reservation is held.

A new stage first checks for a live identical pending snapshot, reserves atomically, attempts one upload, reconciles physical evidence and requires an exact live paired read before acknowledging success. A repeat with a matching reservation can reconcile already uploaded bytes, including after eviction, but never reacquires an upload receipt or calls PUT. Lost acknowledgements are resolved only by the existing exact nonce/digest/ETag and witness checks. Missing bytes, a still-possible delayed upload, missing or prepared witness, malformed receipt or uncertain final state remain unavailable. Existing original-cutoff cleanup may replace an expired reservation with its approved fencing tombstone. It does not acknowledge expired data as pending. No raw conditional PUT is replayed.

The unchanged HTTP handler returns `pending` or `already_pending` with 200, a known `stale` conflict with 409, and uncertain/unavailable state with an empty 503. Operator stage requests remain 403 and malformed bodies remain 400 before any reservation. An expired predecessor cannot authorize stage replay, even though the GET interface may still return a live pending body for recovery. Exact paired observation is the success boundary. This adapter adds no publication authority: the trusted Python writer must still provide independently verified checkpoint facts.

Baseline qualification passed all 74 existing native cases. New native cases cover successful stage/GET/replay, competing distinct and identical requests, stored and absent ambiguous uploads, restart after PUT with no second write, prepared/lost-ack witness states, original expiry and future time, late physical upload fencing, intrinsic input copying, existing accepted predecessor preservation and auth/body admission. All requests, SQLite/R2 state and witness data are synthetic and local, with outbound network denied. Existing mutation primitives and their tests remain intact. The full 815-test Worker Node lane passes, and the focused 18-case native stage suite passes, including reconciliation that commits and then loses its acknowledgement. Pinned lint, formatting and whitespace checks pass.

This completes only the source staging composition. Native control mutation implementations and fixture bootstrap are still in the test harness. Durable production control/initialization, promotion/rejection interfaces, provider-qualified witness, physical 24-hour/seven-day retention, restore proof and whole-operation I/O deadlines/cancellation remain separate release gates. A retry with an unresolved reservation and no matching physical bytes stays held rather than creating or uploading a replacement. No provider, deployment, activation or sending occurs. Public assets are unchanged, so screenshots and golden refresh do not apply.
