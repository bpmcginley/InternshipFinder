# P-2.1ag Follow checkpoint recovery and promotion

The offline coordinator consumes one private pending record from #372 and an independently verified accepted publication. Its trusted caller supplies the current predecessor, fresh UTC clock, explicit bounds and a local recovery binder. The binder runs #348's typed Git checks on the exact pending candidate in an isolated checkout. The binding also returns the original candidate it actually checked. The coordinator checks that candidate, the typed receipt and exact accepted commit, public tree and staged proof against the pending record before encoding the accepted checkpoint from #365. Closed lineage survives.

The store receives one compare-and-set request. In its transaction, it uses a fresh trusted clock and requires the old accepted commit, public tree and checkpoint hash, plus the exact pending generation. It checks live deadlines, installs accepted bytes and clears that pending generation in one atomic write. A retry may report already promoted only for the same completed generation and accepted Git identity. It preserves the original accepted bytes, observation time and expiry, even if a newer pending generation is present. A no-op leaves the checkpoint untouched. Store errors propagate, and any result outside promoted, already promoted or stale raises without a retry. An unconfirmed or stale result cannot advance coverage.

The test uses local scratch Git, the real staged and accepted binders and a file-backed SQLite transaction. It simulates a committed write with a lost acknowledgement, then replays the original request with its retained pending bytes. A cold restart with no pending record reads the existing accepted checkpoint. Separate cases cover concurrent promotion, deadline, rollback, stale generation and invalid store results.

Writer and workflow integration still require G3 release and a restricted CI-accessible store that can implement the same transaction. This package adds no production store, publication, workflow changes or provider calls.
