# P-2.1bv SQL catalog admission guard

Draft [#531](https://github.com/bpmcginley/InternshipFinder/pull/531) adds an optional trusted `catalogExpiresAtMs` to dormant signup admission. Omission preserves existing callers. A present value must be a positive safe integer before rate or queue I/O. The caller must obtain it from the same immutable trusted release as its catalog and preserve its application-clock checks. This option is never a request-body field.

Migration0025 and its exact legacy mirror add an empty view and INSTEAD OF INSERT trigger. The first statement of the existing D1 queue batch validates the cutoff against rounded SQLite UTC epoch milliseconds. Missing, text, fractional, unsafe or expired values raise ABORT. No cutoff, release metadata or new person field is retained. D1 rolls back the entire batch on failure, as documented in [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch). Once admitted, the transaction completes atomically even if subsequent work crosses the cutoff. This is a batch-admission boundary, not a condition independently repeated between mutations.

The wrapper prepends the guard to both existing anonymous and linked queue batches without duplicating their SQL. It validates dense explicit success receipts and the guard's zero changes and empty results, then removes only that extra receipt before returning the existing helpers' exact result shape. Lost, malformed or unsuccessful receipts return unavailable without retry. The independently admitted daily cap remains spent on a later rejection or uncertain queue result. Existing session, consent, pending-expiry, duplicate and account-deletion fences remain intact.

Native local D1 qualification covers both ordered migrations and legacy boot: expired-before-batch rejection leaves new and existing subscriber/scope/queue/token rows unchanged, including confirmed progress. A deliberately slow later SQL step proves admitted completion across expiry. Other cases cover exact equality, malformed/missing cutoffs, whole-batch rollback, valid zero-write guard receipts, uncertain committed receipts and later queue failure. Schema parity retains the same tables and adds only one view and trigger. No HTTP registration, provider/configuration, public wording, production schema adoption or activation is included. The normal merge of exact #528 `749fa797` supplies the reviewed composition. Its only runtime delta is forwarding the same captured cutoff as `catalogExpiresAtMs`. The pinned-loader Node fixture uses a finite current-epoch window so real SQL UTC can qualify the positive case without changing its expiry assertions. The actual handler is exercised with database scheduling delayed until the cutoff: anonymous and linked requests both return unavailable with no queue state on both schema boots. Independent exact review and CI are required.
