# P-2.1dg Reduce Follow digest finalization work

An accepted or uncertain digest can advance many matching scope watermarks. The existing trigger validates the same pending JSON repeatedly inside correlated queries. A local Workers/D1 run with 183 advances and a 32,768-byte pending record measured 1,176,886 reads for that update. The optimized trigger read 4,218 rows for the corresponding fixture, including a run with 2,000 unrelated pending jobs and 2,000 other scopes on the same subscriber. The update wrote 186 rows in both versions. Local statement duration was 6–8 ms with the new trigger. These are synthetic measurements of local Workers/D1. Account allowance and rollout cadence still require qualification.

Migration 0032 and the fresh schema use the same trigger. It materializes the existing validation result and its decoded advances once, then joins through the existing subscriber and scope keys. Only the original exact confirmed lifetime, generation and starting watermark can advance. Invalid or duplicate advances leave all watermarks in place. Existing terminal handling still clears the pending row after the state transition.

The native suite covers a packed valid update, a changed or missing scope among valid siblings, invalid duplicate advances, an existing database upgrade with unrelated backlog, and a fresh schema. Existing progress, retention and migration tests cover additional transition, rollback and erasure paths. This package changes the finalization query in source. Migration adoption and Follow activation require the coordinated release.
