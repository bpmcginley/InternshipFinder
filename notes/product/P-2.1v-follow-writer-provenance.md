# P-2.1v In-process follow timestamp provenance

An opted-in caller passes one capture object to the pipeline and exporter. The pipeline records the original UTC instant only for actual new database rows, then hands it off after commit. The exporter reads the exact attested predecessor index and shards. It observes the writer's existing ID-first, raw-URL fallback, failed-board and search carry decisions. A selected predecessor supersedes a provisional database origin. A known predecessor identity without an attributable timestamp cannot become a fresh proof.

The caller supplies a trusted predecessor digest set and either an aligned forward coverage start with a verified seed observation at or before it, or trusted lineage from a previous capture. Seed evidence describes the prior observation. It does not interpret the timezone of the old text. The caller must establish the seed observation separately from the Git object ID.

The capture reads back the exact files in the caller-owned output directory and seals the index and shard digests, coverage instants, and evidence for the deduplicated naive open rows. An unknown, malformed, or contradictory open observation yields no proof. An unavailable or invalid predecessor falls back to the normal predecessor reader. Failure to read or validate the proof after writing leaves the completed public export in place. An unrelated writer failure still propagates. The output can construct the existing #334 evidence types when both leaves are integrated. The downstream fixed-export adapter remains responsible for complete snapshot validation and authoritative coverage. There are no extra public fields or changes to existing `first_seen` values. The ingest entry point accepts the hook only as an optional in-process argument; the CLI has no option that activates it.

A later isolated runner would need trusted proof for the exact predecessor, supplied by an approved durable handoff or verified replay. This slice adds neither. The existing carry rules still define observation continuity and do not establish identity for a posting absent from the selected predecessor. Production integration also needs to bind proof to the validated staged data tree, with owner approval for the forward coverage start, writer and archive publication.
