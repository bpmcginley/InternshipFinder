# P-2.1av Dormant same-process Follow publication

[#488](https://github.com/bpmcginley/InternshipFinder/pull/488) is stacked on exact #427 `659f1ff68c2453401da7cda87a07c13f115c87e1`. Refactor released the writer and ingest entry for this detached package. G3 and activation remain held.

`ingest_and_publish` first requires the provided state directory to resolve to the import-bound `internscout.config.DATA_DIR`. Registry, dropped-board, geocode, probe and daily-budget state therefore comes from the same directory that publication stages. A mismatch stops before checkpoint access or ingest. Changing the environment after module imports does not rebind these paths.

The coordinator loads independently supplied predecessor/Git evidence through the existing checkpoint writer, then carries one transient capture through the real ingest and export call. The optional publisher callback runs after the immutable candidate commit and before its first push. It does not run on a no-op or invalid capture, and runs once across ordinary Git merge retries. The original immutable staged proof survives an unrelated merge without changing the current index.

After publication the caller's observation callback must reread accepted Git. Existing typed pending decoding, #348 binding and #378 promotion perform recovery. An unknown stage reply causes a fresh read, never another stage. A lost promotion reply returns held. If a push succeeded but the subsequent trusted observation still names the predecessor, Follow returns held and retains pending. The ordinary publication tuple stays separate. Only a true no-op can return no_publication. A later attempt must reload the accepted checkpoint. An interrupted Git operation propagates and leaves recovery to a fresh isolated reader of the exact pending candidate. Existing pending records must be resolved explicitly before a new captured run. No automatic seed or coverage reconstruction is introduced.

Unavailable, expired or inconsistent Follow proof holds Follow while ordinary independently validated listings may publish. This can leave a coverage gap, which remains held. It must never be repaired by inferring timestamps from public files. Explicit forward seeding requires the existing independent attestation. Public snapshot, caches and logs receive no raw provenance. The ordinary CLI, workflow, branch protocol and output are unchanged. Optional argument injection avoids mutating global CLI arguments. No provider transport, URL, credential, deployment or resource is added.

Local tests use synthetic SQLite ingestion and file-only bare Git with Python sockets denied. They cover immutable stage-before-push ordering, lost stage/push/promotion replies, cold recovery, unrelated merge retry, an actual repeated-ingest no-op, unavailable/disabled/stale observations, forward seed, expiry deadline and closed-lineage carry. A separate Python process verifies actual import-bound cache paths, rejects an empty wrong state without starting SQLite or changing Git, then publishes from the configured state while preserving all five cache files. The checkpoint service is a typed test double, not provider storage proof. Existing checkpoint/publisher suites and both default goldens qualify compatibility.

Production integration still requires post-G3 workflow ownership, a hard outer runner deadline, verified private storage and non-rollback witness, physical retention/restore qualification and operator-supplied access. This draft does not authorize or activate those steps.
