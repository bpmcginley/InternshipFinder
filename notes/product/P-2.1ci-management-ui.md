## Capability and API boundary

The synchronous first script strips the fragment before importing any asset. The canonical lowercase UUID-dot-64-hex token stays in its closure. Query-bearing, duplicate, malformed and failed-history-clear inputs never admit a capability. Opening the page makes no API request. The skip link keeps working; a new same-document capability aborts and replaces the prior view without acting. Pagehide clears credentials, fields and displayed scopes; a persisted restore stays inert. Revision checks precede any stale continuation's fragment handling. No credential is put in a URL request, DOM, cookie, persistent storage or log. The only loaded resource is the local module.

The controller accepts an injected trusted transport with operations and exact JSON bodies matching merged #523/#541: `list` `[token, null-or-cursor]`, `remove` `[token, scopeKey]`, `deleteAll` `[token]`, and `request` `{email}`. List replies use `{scopes:[{scope_key,created,confirmed_at}],next}`; cursor and scope key are returned unchanged. Retained public facts are displayed through textContent without requiring today's signup catalog. A 410 list response clears the credential. Empty authorized lists are distinct. Removal and full deletion require explicit true receipts. Only a 202 management-request response receives the generic acknowledgement. All uncertainty stays generic and never retries automatically.

**Optional first-party transport:** reviewed #551 is integrated through exact main `fa88b22b`. The controller's transport factory returns null unless enabled is literal true. Bootstrap captures only initial `data-follow-management-enabled="1"` from the trusted HTML element; that attribute is absent in the shipped page. No URL, query, window setting or response enables it. Opening the page still makes no API call, and default explicit actions show the approved unavailable text.

When separately enabled in a reviewed static artifact, the adapter calls exactly `POST /follows/manage/list`, `/remove`, `/delete` or `/request` on the existing first-party Worker host. The full URL literals and inline method are recognized by the actual API AST inventory. Bodies are JSON only; signal is forwarded; credentials omitted, cache disabled, redirects rejected, CORS used and referrer omitted. No token is in a URL and no retries occur. Server capability and request switches, explicit policy and schema adoption remain independently required. Neither the static flag nor any Worker setting is enabled here. The response reader is fatal UTF-8 and bounded to 256 KiB; its 12-second UI deadline aborts transport and cancels/releases acquired body readers. These are UI safety bounds, not queue or sender policy.
