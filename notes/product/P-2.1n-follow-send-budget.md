[PR #302](https://github.com/bpmcginley/InternshipFinder/pull/302) is stacked on frozen #298 `e9a5a857`. Needs-bruce. The helper is dormant.

Future confirmation, management and digest senders must all reserve against this same D1 aggregate. `reserveFollowSendAttempt(db, cap, now)` requires an explicit positive safe integer from trusted operator configuration. There is no default, volume proposal or quota assumption. A true result spends one slot for one attempt, even if delivery later fails. A false result authorizes no send. An ambiguous database response can consume a slot without authorizing delivery. Do not compensate, replay or refund that slot.

Migration 0016 and the legacy schema create a singleton table. Its only data is the latest observed canonical UTC timestamp and the count for that timestamp’s UTC day. There is no recipient, request, send kind or per-attempt history. One D1 batch observes the time and conditionally increments the count. A newer day replaces the old count, the same day keeps it, and an older timestamp cannot mutate it. Cap rejection still records the newer observed time. A lowered cap prevents new attempts without erasing the count already used. The schema and safe-integer cap prevent overflow. Storage failures fail closed.

`cleanupFollowSendBudget` uses the same monotonic update without spending a slot. It clears the prior count on its first successful invocation on a newer UTC day, preserves any count already used that day, and keeps the clock fence. No idle midnight deletion is promised. Future orchestration must run cleanup even while sending is off, reserve at the attempt boundary with a fresh trusted clock, and handle atomic composition with the digest consent/claim path. The helper changes no existing email flow.
