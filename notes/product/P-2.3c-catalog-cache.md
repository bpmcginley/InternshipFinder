## Contract and bounds

`createEmployerCatalogCache` requires an injected response loader, parser/validator and positive safe-integer `maxBytes`; clock and timers are injectable for offline tests. No URL, credentials, provider request or production byte-budget value is invented. The eventual reviewed wire format must supply its bounded byte budget. Content-Length is rejected if invalid/oversize, and actual streamed bytes are independently bounded. UTF-8 decoding is strict; malformed/unavailable responses, rejected parsing and invalid predicates fail closed.

The parser must reuse the existing canonical validator in `employer-posting-counts.js`, returning its private synchronous boolean membership function. That validator currently remains private; a later coordinated integration must expose/reuse it without copying its key rules or adding a second validator. Test parsers are fixture doubles, not implementations of canonical limits. The cache exposes only async `has(key)`, never a catalog or predicate that a caller could keep using after expiry.

Fetch and validation are single-flight. The fixed 300-second lifetime starts before loading, not when parsing finishes. Every await boundary and membership result is checked against time/generation; expired, late or clock-invalid results cannot publish or accept membership. Expired cache content is unavailable while refreshing. A deadline releases waiters and aborts loading; the injected loader must honor its AbortSignal, since obsolete promise continuations cannot be forcibly killed by JavaScript. A late continuation cannot replace a newer snapshot.

Failure drops cached data and permits another load only after five seconds; concurrent calls in that interval return false. Invalid/backward clocks also invalidate the cache. This retry delay is not permission to serve stale data. There is no durable storage or person information in this module.
