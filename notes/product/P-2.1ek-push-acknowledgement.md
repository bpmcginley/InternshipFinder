# P-2.1ek Direct acknowledgement of a Follow writer push

The current listing writer accepts an optional trusted observer. Before each ordinary push, it receives the exact retry ordinal, expected predecessor, candidate commit and raw public tree. Only an acknowledged normal fast-forward update invokes the observer again with the same intent. The opt-in command pins the source commit, checks both OIDs through the pre-push hook, and requires one exact full-OID status record for the data ref. For an admitted observer, validation reads the raw staged Git tree with replacements disabled. The writer checks the public subtree and every owned state entry against that validated tree before each pinned push. An up-to-date result, a competing writer, a lost response and mismatched status records cannot acknowledge this attempt. [Git push output](https://git-scm.com/docs/git-push#_output)

The observer is absent from the CLI and production workflow. When absent, the writer retains the original command, hook, retry and public #537 receipt. The opt-in observer requires one stable endpoint shared by reads and pushes. Different endpoints at entry disable private observation. A change during the callback stops the push, and a change after the command withholds the private acknowledgement. The trusted caller owns the checkout exclusively and keeps configuration and transport stable. Endpoints never enter the observer record. The observer must return promptly. A recorder error disables further observation while pushes continue to use pinned candidates. A rejected push stops before retry if the callback changed HEAD. This package creates no journal or production setting. A direct acknowledgement needs independent run/attempt and pending-generation evidence before detached recovery. A lost acknowledgement remains unresolved even if the named ref later matches.

File-only Git fixtures cover exact first-push and ordinary merge-retry evidence, an up-to-date push, a lost response, malformed status records and observer failures. They also exercise a replacement that masks invalid raw staged data, raw commit identity despite a replacement, a recorder that changes HEAD before failing, pinned retry after a recorder error, and competing updates or endpoint changes during observation.
