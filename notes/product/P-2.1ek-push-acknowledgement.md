# P-2.1ek Direct acknowledgement of a Follow writer push

The current listing writer accepts an optional trusted observer. Before each ordinary push, it receives the exact retry ordinal, expected predecessor, candidate commit and raw public tree. Only an acknowledged normal fast-forward update invokes the observer again with the same intent. The opt-in command pins the source commit, checks both OIDs through the pre-push hook, and requires one exact full-OID status record for the data ref. An up-to-date result, a competing writer, a lost response and mismatched status records cannot acknowledge this attempt. [Git push output](https://git-scm.com/docs/git-push#_output)

The observer is absent from the CLI and production workflow. When absent, the writer retains the original command, hook, retry and public #537 receipt. Optional observer failures leave the existing listing publication result intact. The observer must return promptly. This package creates no journal or production setting. A direct acknowledgement needs independent run/attempt and pending-generation evidence before detached recovery. A lost acknowledgement remains unresolved even if the named ref later matches.

The local writer and catch-up suites passed 51 tests and 19 subtests using file-only Git. The new cases cover exact first-push and ordinary merge-retry evidence, an actual up-to-date push, a successful physical push with a simulated lost response, wrong ref and OID receipts, and observer errors before and after a successful listing push.
