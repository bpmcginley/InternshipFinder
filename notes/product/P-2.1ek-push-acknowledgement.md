# P-2.1ek Direct acknowledgement of a Follow writer push

The current listing writer accepts an optional trusted observer. Before each ordinary push, it receives the exact retry ordinal, expected predecessor, candidate commit and raw public tree. Only an acknowledged normal fast-forward update invokes the observer again with the same intent. The opt-in command pins the source commit, checks both OIDs through the pre-push hook, and requires one exact full-OID status record for the data ref. Raw object reads ignore Git replacements and check the public tree against the staged snapshot. An up-to-date result, a competing writer, a lost response and mismatched status records cannot acknowledge this attempt. [Git push output](https://git-scm.com/docs/git-push#_output)

The observer is absent from the CLI and production workflow. When absent, the writer retains the original command, hook, retry and public #537 receipt. The opt-in observer requires one stable endpoint shared by reads and pushes. Different endpoints at entry disable private observation. A change during the callback stops the push, and a change after the command withholds the private acknowledgement. The trusted caller owns the checkout exclusively and keeps configuration and transport stable. Endpoints never enter the observer record. The observer must return promptly. Optional recorder errors without a change to Git authority leave the listing publication result intact. This package creates no journal or production setting. A direct acknowledgement needs independent run/attempt and pending-generation evidence before detached recovery. A lost acknowledgement remains unresolved even if the named ref later matches.

The local writer and catch-up suites passed 54 tests and 19 subtests using file-only Git. The new cases cover exact first-push and ordinary merge-retry evidence, an actual up-to-date push, a successful physical push with a simulated lost response, wrong ref and OID receipts, observer errors before and after a successful listing push, raw tree identity with an actual local replacement, different fetch/push destinations, and a destination change during the observer.
