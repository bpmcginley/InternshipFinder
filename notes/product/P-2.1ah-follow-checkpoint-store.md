# P-2.1ah Private follow checkpoint storage

This detached SQLite Durable Object implements one pending and one accepted checkpoint slot for an independently trusted writer. It reads bounded Python checkpoint bytes, derives metadata and SHA-256 locally, and requires exact predecessor identity and pending generation before promotion. Git proof and authorization remain the caller's responsibility. A repeat of the completed generation with the same accepted Git identity preserves the original bytes and expiry. Exact rejection cannot clear another generation.

The storage mutation reads UTC milliseconds from SQLite inside `transactionSync`. Canonical microsecond record times are retained, with fractional starts rounded up and exclusive deadlines rounded down for the millisecond clock. Thus a record can close by less than one millisecond early and never gets a later deadline. Pending remains active for at most 24 hours and accepted for at most seven days. The SQLite changes and earliest-deadline alarm share one outer local transaction. Reads and mutations enforce active expiry even if the alarm runs late, and the alarm removes due rows without incoming traffic. A missing prior checkpoint requires the caller's independent forward-seed attestation.

Run the isolated runtime test from `worker/` with `node node_modules/vitest/vitest.mjs run --config vitest.follow-checkpoint.config.js`. It verifies actual SQLite/workerd storage with a measured-size synthetic payload, CAS races, replay, expiry, alarm execution/rearming and rollback. The only test entry returns 404 for HTTP. The package adds no production binding, deployment config, route or credential.

Cloudflare SQLite point-in-time recovery can restore deleted rows from up to 30 days of database history, and the API is unavailable locally. The 24-hour and seven-day intervals describe active access and deletion. Production activation requires an explicit decision on provider recoverability and operator access. It also requires private CI transport, authoritative writer observations, configured bounds and G3 release. See the [SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [alarms](https://developers.cloudflare.com/durable-objects/api/alarms/) and [limits](https://developers.cloudflare.com/durable-objects/platform/limits/).
