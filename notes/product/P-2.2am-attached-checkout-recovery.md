# P-2.2am Attached checkout recovery

Base is published 73373196. This package adds the internal service for one existing checkout attached to an account. Approved #226 refund and dispute decisions and #294 run accounting stay in their existing services. The #311 recovery contract remains the authority for expiry and first settlement.

Authenticate an unexpired existing session and select the account's attached open attempt. Read the stored Checkout ID with a bounded authoritative GET. Verify that Checkout metadata and account reference match the attempt before resolving its historical offer and mode. Use the existing payment, reversal, expiry and settlement paths. Uncertain results leave the attempt pending. The service cannot create a Checkout, discover an unattached ID or sweep historical reversals.

A future route must use authenticated account context and an explicit recovery action independent of current sales availability. It must present only a coarse recovery status and refresh the balance separately. Refactor owns the API entrypoint. Provider configuration, rollout and retention remain separate.
