`runFollowDigestRelease` is an unmounted trusted-object port, not a new descriptor encoding or settings supplier. Only an own data `enabled:true` admits. Missing, false or inherited enablement stays disabled without reading any other port; an own accessor is rejected generically without invocation inside the controlled failure path. Explicit inputs are the existing synchronous sending/presentation/buildLinks policy, database and callable email binding, already-imported signing key, fetch and wall/monotonic clocks, overall deadline and transport timeout, exact catalog deployment object, pinned archive object, matcher bounds and optional related bounds. The catalog uses #637's `prepareFollowCatalogDeployment` unchanged, including independent current source/payload pins and predecessor source/payload/URL or explicit genesis. The archive requires the fixed first-party index URL and final served manifest SHA-256. Own-data records are copied before the first await. Acquisition URLs are bounded to 2,048 characters and cannot alias each other, including decoded manifest paths.

The key port requires a caller-owned actual native HMAC SHA-256 signing CryptoKey imported with at least 256 bits and `extractable:false`. Workerd exposes mutable displayed own metadata and cannot structured-clone CryptoKeys; Node instead exposes intrinsic metadata getters. This composition validates the displayed metadata and rejects wrong native identity using a local WebCrypto HMAC sign of the fixed public text `InternScout Follow digest key preflight v1`, requiring a 32-byte result. No user, credential or private message is signed by this probe, and no key is exported, encoded, imported or retained by this package. **The metadata check does not independently prove unforgeable import length or nonextractability after caller tampering.** Establishing and sealing the actual import provenance remains a required separate mount/qualification boundary. The native probe rejects forged-prototype objects and wrong actual hash output even when displayed metadata claims SHA-256. No production key or release identity is selected.

One wall/monotonic budget starts before validation and the native probe. Clocks must be synchronous, finite and nonregressing; the wall clock must also remain inside the original catalog release interval. Predecessor/current loaders receive only remaining time. The exact reader is constructed with the remaining deadline and original pinned manifest/bounds, and is called only through `loadSnapshot({at,digest,maxBytes})` from the leased job. It never calls latest. At most three GETs occur for genesis, four for a predecessor: catalog(s), manifest and one exact retained blob. Existing catalog/manifest/archive byte and key bounds remain authoritative. No retry, cache or fallback is added.

After catalog validity and continuity are verified, the owned digest runtime handles the shared owner, one candidate, optional related selection, final consent, budget, capability issuance, transport and settlement. The same captured clock/fetch guard remains authoritative across later public reads and runtime clock boundaries. An optional own-data `beforeAcquire` callback is captured after the runtime enabled/sending gates; existing omitted callers retain their behavior. The shared owner calls it synchronously after its ready SELECT and statement preparation, immediately before submitting the ready-to-running CAS, and requires literal `true`. Throwing, refused or asynchronous admission returns unavailable without submitting that CAS. This is a JavaScript submission fence, not a SQLite execution deadline. The release composition also checks the same original deadline immediately before the captured binding send, after the final policy sample and transport envelope validation, with no awaited work in between. There is no generic database wrapper, SQL admission-cutoff claim or race that releases ownership while D1 is still running. Expiry before CAS leaves owner, queue and budget untouched. Expiry after a durable attempt keeps spent quota and issued credentials, invokes no provider, and retains existing uncertain/held semantics. Late/ambiguous work remains governed by existing owner/settlement rules; the outer result may be unavailable and does not assert rollback. A synchronously closed policy is intentionally delegated to the existing runtime after catalog acquisition and before ownership, avoiding a new policy grammar or extra policy sampling. This differs from default disabled, which performs no reads.

Public matching/share links still require the separately held #634 design and future qualified policy. No sender/link defaults, environment, schedule, route, schema, storage, retention, production allowlist or activation changes. All tests use synthetic roles, an in-memory local key and mock email binding; no provider or user data is accessed.

Native cases exercise the actual D1-owned runtime: an older queued snapshot whose enqueue window expired but retention remains valid is delivered instead of a newer manifest latest; explicit genesis and pinned predecessor both work. Negative cases cover default-off inspection, malformed key/callable bindings/catalog, retained membership loss, crossed catalog bytes, decoded path collision, wrong manifest pin with no fallback, original wall/monotonic exhaustion, late archive hold and closed policy before owner.
