# P-2.3d employer posting counts report

This dormant query is stacked on P-2.3b at `3fe4b253`. It returns the completed UTC days in the requested 1–90 day window. It selects only employer key, day and count. The temporary overall-cap total and the existing paid-order and funnel data are outside this query.

The result uses up to 1,000 rows per request and a keyset cursor tied to the same UTC report window. A new UTC day requires starting a new report. The result is a sequence of bounded reads; rows deleted between pages may be absent from later pages. Nothing is written and the function does not hold a cross-request database snapshot.

Node SQLite and local Workers/D1 cases cover the retention and midnight boundaries, ordered pagination with multiple keys on a day, invalid and expired cursors, and unchanged counter and cap records. In local D1, a three-row page after key 9,990 in a synthetic 10,000-key day reads at most eight rows, including the row used to check for a next page.

The eventual owner-only API must enforce the existing admin authorization and send `Cache-Control: no-store`. Production schema, feature activation, owner removal, catalog and route integration, policy publication and deployment remain pending. This PR changes no visible strings, public assets or golden output.
