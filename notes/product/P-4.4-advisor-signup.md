## Source and provider contract

The existing `backend/internscout/site/render/digest.py:14` form already submits email directly by ordinary HTML POST and offers an unchecked optional field tag. `site/digest.py` validates the existing configured form action. Reuse that endpoint without copying its account identifier into this note. The advisor control uses `type="checkbox" name="tag" value="advisor"`, with neither `checked` nor `required`. An unchecked control submits no advisor tag. Preserve any independently selected field tag. Never infer advisor status from the page, address, domain or profile. No new server/browser storage or analytics field.

Buttondown's [Tags documentation](https://docs.buttondown.com/tags), checked 2026-11-11, lists Tags as available on its Basic plan and requires enabling it in Settings → General → Features. Embedded forms accept repeated tag inputs. Returning signup appends tags. An unchecked resubmission does not remove an existing tag. These public docs do not establish this account's plan, settings or enabled automations. Before live activation, Bruce must confirm the existing plan supports Tags and the feature is enabled, and verify that this tag triggers no separate send or automation.

[Building your subscriber base](https://docs.buttondown.com/building-your-subscriber-base) requires the embed endpoint to be the action of a normal form, allowing provider validation/CAPTCHA navigation. Do not replace this with a fetch request, Worker proxy or subscriber API call.
