# P-2.1cx dormant shared digest ownership

This package extends the approved [shared authority design](https://github.com/bpmcginley/InternshipFinder/pull/563) and [singleton owner](https://github.com/bpmcginley/InternshipFinder/pull/576) to one digest candidate per acquisition. The composition is unmounted and disabled by default. It adds no persisted fields.

`createOwnedFollowDigestRuntime` captures its options once, including the database shared by owner CAS and delivery. Its injected synchronous policy supplies `sending`, a valid shared daily `cap`, and a stable `present` function. The remaining inputs are the existing digest key, catalog, bounds, snapshot loader, clock and email binding. No production values or provider defaults are supplied. Initial `sending: false` returns disabled without database work. After acquisition, a policy change closes the invocation without inventing a maintenance receipt.

The wrapper always calls the existing delivery tick with `maxCandidates: 1`. Existing tick callers retain their API and their current multi-candidate behavior. Both the owned link runtime and the owned digest runtime acquire the same singleton. A digest cannot hand off while a link invocation owns it, and a link invocation cannot hand off while a digest owns it. All future production entry points must use these wrappers to share that authority.

A separate digest completion validator accepts only a clean empty or single-accepted processed receipt, or one paused candidate. Uncertain, unavailable and malformed receipts leave the owner held or running. Clean completion changes only the phase. Existing link cursor fields, the next link kind and concurrent cursor redactions remain intact. There is no digest cursor or new fairness policy. One caller must choose the sequencing of link and digest invocations under the separately approved cadence and capacity policy.

Terminal digest writes now require both successful D1 receipts and an exact single direct `RETURNING 1 AS changed` row. Counts and the direct row must be plain records with own enumerable data properties. Inherited counts, getters, unexpected direct-row fields and symbols cannot certify completion. Expected outer batch entries and own enumerable data `success`, `results`, `meta` and `changes` fields are captured once without invoking accessors. Additional native metadata is ignored. Exotic receipt and metadata records are rejected. The aggregate terminal count is capped conservatively at 32,770 from the existing 32,768-byte unique-advance JSON bound, one outbox update and one pending deletion. This distinguishes the outbox update from the existing watermark-finalization trigger effects. A failed success flag, malformed direct receipt, rollback or lost terminal acknowledgement cannot release shared ownership. A lost acquisition acknowledgement invokes no transport. A lost acknowledgement of an actually committed clean owner release stops that caller without compensating or retrying.

The existing immediate email adapter preserves one-click unsubscribe headers and calls the injected send function synchronously after the delivery helper's final authorization fence. Timeout or malformed provider acknowledgement remains uncertain even if the underlying promise later resolves. No provider traffic is used in qualification.

The source claim consists of the new owned digest runtime, the owner completion seam and the outbox terminal receipt seam. Qualification adds one shared fixture, Node and native Workers wrappers and one Node test registration. This note is the only Product documentation change. The Product lead owns the shared STATUS waiting entry.

## Qualification

- 22 new shared synthetic scenarios cover one candidate, empty/paused receipts, contention in both link/digest directions, cursor preservation and deletion redaction, one-read database capture, policy changes, late acceptance, acquisition and terminal acknowledgement loss, malformed receipts, impossible aggregate counts and transactional rollback. The corrected fixtures also reject Date/Map records and inherited/accessor claims while preserving null-prototype records and native trigger effects.
- 82 selected actual local Workers/D1 cases passed across the new runtime and existing owner, tick, digest delivery and budget groups. These use synthetic addresses, public-role fixtures and an injected email binding.
- The prior corrected strict Node 22 lane passed 1,131 tests. After the outer receipt correction, all 62 selected Node cases passed and the full strict lane is running.
- Pinned ESLint and `git diff --check` passed. No browser output changes occur in this package.

## Activation prerequisites

The approved no-reset rule remains. Production restore authorization and external anti-rollback evidence, hold release, sender/presentation settings, provider capacity including separately sent order mail, cadence and per-invocation sequencing remain owner decisions. Existing bulk digest retention is not made an automatic schedule here. Qualified retention and same-release catalog/archive publication are still required before mounting a sender. This source package adds no route, scheduler, schema, config, provider call or activation.
