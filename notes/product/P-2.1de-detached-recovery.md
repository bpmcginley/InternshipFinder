# P-2.1de Detached Follow recovery and archive planning

Draft [#606](https://github.com/bpmcginley/InternshipFinder/pull/606), stacked on exact #501 `5a3121b330471ab865c23461d2bdc1589772aafb`. Only the new helper, its test and this note are owned. Existing writer, checkpoint, archive, workflow, public output and STATUS bytes are unchanged.

## Boundary

`scripts.follow_detached_recovery.recover_detached_follow` is unmounted and disabled unless `enabled is True`. The caller supplies a private checkout, existing checkpoint client, exact predecessor source, explicit bounds/deadline/clock and an optional already-authorized forward seed. The private checkout index must still equal the original pending candidate tree; the helper never resets or repairs it. An unrelated accepted descendant may have a different full tree, but the existing binder must prove all owned data equal.

The required frozen `AcceptedFollowOperation` is **caller-verified external authority**, not a verifier or self-authenticating receipt. It binds the run, attempt and one of the existing three push ordinals to the exact expected direct predecessor, original pending candidate, pending payload digest and typed accepted commit/tree/original observation time. Only strict primitive fields and the exact existing observation type are accepted, and the helper copies them before private I/O. Matching Git tip, trailer, parent edge or this Python type never proves that the operation occurred. No production witness, exclusive writer guarantee, cross-run journal or permission is selected here.

The helper uses the existing `FollowCheckpointWriter.load` and pending codec for source, full lineage, continuity and lifetime validation. It reconstructs `_StagedFollowProvenance` through the existing validator, binds it through `_bind_published_follow`, and supplies the existing `BoundFollowAcceptance` to `FollowCheckpointWriter.recover`. The asserted direct parent is checked with the pending reader's isolated raw-Git helper, but that check is not accepted-operation authority. No new token, retained witness field or storage format is added.

Only an acknowledged `promoted` or `already_promoted` result returns the original typed publication receipt. Every absent, malformed, expired, conflicting, uncertain or deadline-exhausted outcome returns no receipt. There is no mutation retry or compensating write. A lost acknowledgement may have promoted the private record; this adapter deliberately withholds archive input and does not invent a later recovery shortcut.

The returned receipt feeds the unchanged #352 `plan_follow_archive_from_publication` in this new process with the caller's existing archive bytes, catalog, coverage and bounds. The caller must independently verify the current named ref and recheck authority before publication; this historical operation record does not attest ongoing currentness. Archive planning and publication remain separate; the caller must still qualify the actual current manifest/base and release authority. This package does not put private recovery into, or remove it from, any real workflow.

## Offline proof

The focused suite uses tiny actual local Git repositories, existing checkpoint encoding/validation/promotion code and a synthetic private store. A separate Python process receives only synthetic persisted pending bytes, predecessor bytes and explicit fixture authority, reconstructs the receipt, and produces exactly the same #352 archive file hashes. Original open and closed lineage and the original acceptance instant are retained. The test authority is injected, not a production witness.

Cases include exact publication; a retry with a changed unrelated tree; absent/malformed authority with zero private I/O; wrong generation/candidate/direct predecessor; changed local index; changed accepted public facts; original expiry/future observation; already-promoted acknowledgement; lost/stale/malformed acknowledgement; caller record replacement during load; and deadline exhaustion after a committed promotion. Default disabled does not inspect its arguments. Git transport is restricted to file-only fixture use, with no provider calls.

The focused adapter and existing writer suites passed 44 tests plus 11 subtests. The final 25 adapter cases also passed from the hosted backend working directory with ambient PYTHONPATH removed. Ruff format/lint and diff checks passed. The interrupted disk-full run is excluded from passing evidence. No dependency installation or production data was used.
