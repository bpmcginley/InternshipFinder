# P-2.1de Detached Follow recovery and archive planning

Draft [#606](https://github.com/bpmcginley/InternshipFinder/pull/606), stacked on exact #501 `5a3121b330471ab865c23461d2bdc1589772aafb`. Only the new helper, its test and this note are owned. Existing writer, checkpoint, archive, workflow, public output and STATUS bytes are unchanged.

## Boundary

`scripts.follow_detached_recovery.recover_detached_follow` is unmounted and disabled unless `enabled is True`. The caller supplies a private checkout, existing checkpoint client, exact predecessor source, explicit bounds/deadline/clock and an optional already-authorized forward seed. The dedicated private checkout must have HEAD at the original pending candidate and its native index equal to that candidate tree; the helper never resets or repairs any checkout. For an accepted retry merge, the caller prepares a fresh isolated checkout at the original candidate with the accepted merge object available. The retry checkout at merged HEAD cannot substitute, even if its index is restored. An unrelated accepted descendant may have a different full tree, but the existing binder must prove all owned data equal. The caller must exclusively own this checkout and its configuration throughout recovery.

The dedicated process must set `GIT_CONFIG_GLOBAL=os.devnull`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_NO_LAZY_FETCH=1`, and `GIT_ALLOW_PROTOCOL` to empty (or `file` for local-only fixtures). Only author/committer name/email/date variables are otherwise allowed because they cannot redirect these read operations. Every other case-insensitive `GIT_` override is rejected before private I/O and again after load, including alternate index, location, objects, grafts, replacements and injected config. Tests clear inherited Git variables before setting this narrow fixture environment. No process-global environment is changed by the helper. The caller must keep its dedicated process environment stable; this is a precondition, not an isolation sandbox against concurrent hostile mutation.

The required frozen `AcceptedFollowOperation` is **caller-verified external authority**, not a verifier or self-authenticating receipt. It binds the run, attempt and one of the existing three push ordinals to the exact expected direct predecessor, original pending candidate, pending payload digest and typed accepted commit/tree/original observation time. Only strict primitive fields and the exact existing observation type are accepted, and the helper copies them before private I/O. Matching Git tip, trailer, parent edge or this Python type never proves that the operation occurred. No production witness, exclusive writer guarantee, cross-run journal or permission is selected here.

The helper uses the existing `FollowCheckpointWriter.load` and pending codec for source, full lineage, continuity and lifetime validation. It reconstructs `_StagedFollowProvenance` through the existing validator, binds it through `_bind_published_follow`, and supplies the existing `BoundFollowAcceptance` to `FollowCheckpointWriter.recover`. The asserted direct parent is checked with the pending reader's isolated raw-Git helper, but that check is not accepted-operation authority. Original UTC observation precision is preserved, including submillisecond instants. Parent headers must be contiguous immediately after the tree header; out-of-position parent text cannot attest an edge. The accepted object must be a commit and its declared size must fit the existing positive max_source_bytes bound before its body is read; the returned body must have that exact length. Each new Git inspection uses the existing writer deadline checks before and after its result. These guards reject late results but do not preempt an already-running Git child; the existing #501 outer process deadline remains a separate caller requirement. No new token, retained witness field or storage format is added.

Only an acknowledged `promoted` or `already_promoted` result returns the original typed publication receipt. Every absent, malformed, expired, conflicting, uncertain or deadline-exhausted outcome returns no receipt. There is no mutation retry or compensating write. A lost acknowledgement may have promoted the private record; this adapter deliberately withholds archive input and does not invent a later recovery shortcut.

The returned receipt feeds the unchanged #352 `plan_follow_archive_from_publication` in this new process with the caller's existing archive bytes, catalog, coverage and bounds. The caller must independently verify the current named ref and recheck authority before publication; this historical operation record does not attest ongoing currentness. Archive planning and publication remain separate; the caller must still qualify the actual current manifest/base and release authority. This package does not put private recovery into, or remove it from, any real workflow.

## Offline proof

The focused suite uses tiny actual local Git repositories, existing checkpoint encoding/validation/promotion code and a synthetic private store. A separate Python process receives only synthetic persisted pending bytes, predecessor bytes and explicit fixture authority, reconstructs the receipt, and produces exactly the same #352 archive file hashes. Original open and closed lineage and the original acceptance instant are retained. The test authority is injected, not a production witness.

Cases include exact publication; an actual two-parent `git merge --no-edit` retry with an unrelated remote change, followed by a fresh original-candidate checkout; absent/malformed authority with zero private I/O; wrong generation/candidate/direct predecessor; changed local index and a saved-index environment bypass attempt; disallowed/missing process isolation and an override introduced during load; annotated tags and out-of-position raw parent text; submillisecond observation; changed accepted public facts; original expiry/future observation; already-promoted acknowledgement; lost/stale/malformed acknowledgement; caller record replacement during load; and deadline exhaustion after a committed promotion. Default disabled does not inspect its arguments. Git transport is restricted to file-only fixture use, with no provider calls.

The corrected adapter and existing file-only writer suites passed **57 tests plus 11 subtests** (38 adapter cases and 19 writer cases), from the hosted `backend/` working directory with ambient `PYTHONPATH` removed, in 233.56 seconds. Seven targeted actual-Git boundary cases also passed separately. Ruff format/lint and diff checks passed. The interrupted disk-full run and the initial harness-isolation/setup failures are excluded from passing evidence. No dependency installation or production data was used.
