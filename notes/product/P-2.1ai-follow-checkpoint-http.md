# P-2.1ai Private follow checkpoint HTTP contract

This detached handler takes a caller-owned SQLite checkpoint binding, explicit maximum bytes per record and two distinct SHA-256 digests of high-entropy, 43-character URL-safe Bearer credentials. The writer can load, stage, promote and reject. The recovery operator can load, promote and reject existing generations. Authentication and role checks happen before request body reads or store access. Requests must use HTTPS. There is no CORS or caching.

| Method and path | Request | Success |
| --- | --- | --- |
| GET `/v1/checkpoint` | Empty body | `200`, `Follow-State` and decimal `Follow-Accepted-Bytes` and `Follow-Pending-Bytes` headers. The body is exact accepted bytes followed by pending bytes, with zero length for an absent slot. |
| POST `/v1/checkpoint/stage` | Canonical Python v1 pending bytes | `200` with `pending` or `already_pending`. |
| POST `/v1/checkpoint/promote` | Canonical Python v1 accepted bytes, exact `Follow-Pending-Generation`, canonical UTC `Follow-Checked-At` and `Follow-Predecessor` as `commit:tree:digest` (use `-` for attested seed absence) | `200` with `promoted` or `already_promoted`. |
| POST `/v1/checkpoint/reject` | Empty body and exact `Follow-Pending-Generation` | `200` with `rejected`. |

Stage and promote require `application/octet-stream`. They enforce the configured byte cap against the stream, validate the fixed v1 record shape and compare the canonical sorted compact serialization byte for byte. This also rejects duplicate keys and noncanonical encodings. Mutations return JSON with one fixed `status` field. A stale store result returns `409` and other errors carry an empty body. Existing SQLite rules govern CAS, expiry, replay and the distinction between expired and never-seeded. The trusted writer or operator must verify Git, attest a seed or determine a definitive rejection before making the corresponding request.

The local workerd fixture uses synthetic credentials and the actual SQLite object. It exercises auth before body pull, malformed and oversized streams, exact replay and rejection, and a 26,977-row byte-exact roundtrip. Run it from `worker/` with `node node_modules/vitest/vitest.mjs run --config vitest.follow-checkpoint.config.js`.

An HTTPS GitHub runner client with bounded responses, disabled redirects and exact status handling remains a separate integration step. Production activation requires G3 release, authorized writer/operator credentials, private route and bypass checks, operator configuration and the existing PITR decision. Cloudflare Access can add edge Service Auth using [service tokens](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/). This handler verifies its own Bearer credentials and does not infer identity from forwarded Access headers. This package creates no production binding, client, route, credential or provider request.
