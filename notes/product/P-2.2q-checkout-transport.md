Each Price GET, single creation POST and open-session GET has its own ten-second absolute elapsed deadline and 256 KiB streamed response limit. These are local technical bounds. An internal caller may shorten the timeout but cannot increase it. The timer races stalled transport and body reads, aborts their signal and attempts cancellation without awaiting it. Elapsed checks fence noncooperative late responses and reads even before the timer callback runs. No redirects or automatic retries are allowed. The three operations do not share a lifetime deadline across an arbitrarily retained adapter or intervening database work.

The existing billing helper still supplies its pinned API version, authorization/form/idempotency headers and JSON parser. Only bounded successful bodies reach that parser, with Response.text-compatible UTF-8 decoding. Provider error bodies are not read or logged. The existing fixed generic error and default-off verification remain. No URL, secret or new field is persisted.

Failed Price verification leaves capability disabled. A creation failure after invocation retains the durable unresolved `creating` attempt. A later response cannot attach a checkout ID or return a URL. Existing concurrent reservations cannot issue another POST. A revoked session still receives no attempt through the current fenced reservation path. An abort does not prove the provider rejected a creation or reverse an accepted payment. Historical authoritative recovery remains necessary for ambiguous attempts.
