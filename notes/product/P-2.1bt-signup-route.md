# P-2.1bt dormant Follow signup route composition

`createFollowSignupRoute` constructs the existing bounded HTTP handler once. Future production wiring must keep that instance at isolate scope: its four-request guard spans body reads, catalog resolution, authentication and admission across trusted per-request `{db}` contexts. The only existing HTTP change forwards that context to its admission callback; old callbacks and responses are preserved. The factory is off by default and is not imported by the production router.

The server supplies an explicit origin predicate, positive daily limit, and `loadCatalog()` port closed over the reviewed first-party loader's release URL, source/payload pins, validity, continuity and bounds. The port receives no request, identity or email, and must return only a currently validated `available` catalog. The composition uses `catalog.signup`, never retained `valid` sets or request-selected URLs/pins. Email and scope shape are checked with existing validators before I/O; authoritative membership is checked against the trusted catalog before rate/storage writes. No cache or release policy is invented.

Anonymous signup never reads session state. For `link:true`, only the existing Authorization bearer grammar and `sessionUser(refresh:false)` supply identity; cookies and body proofs cannot authorize. The original expiry is rechecked with a fresh nondecreasing Worker clock after the session lookup, catalog load, token hashing and daily-cap write. `sessionTokenHash` produces the exact transient `{id,user}` pair for the existing linked request. SQLite rechecks that session/account and its execution-time expiry atomically. No session credential is persisted, no refresh occurs, and an uncertain/spent attempt is not retried or refunded. SQL-declined linked writes preserve the existing generic acknowledgement without revealing session/account state.

Qualification uses synthetic Node SQLite and actual local Workers/D1: disabled, wrong-origin and malformed zero-I/O requests; anonymous session isolation; exact trusted current catalog membership; duplicate expiry preservation; linked owner intent without refresh; delayed lookup/catalog/rate expiry; SQL revocation/expiry; and one shared guard across request contexts. An additional Node case composes the actual pinned loader with the checked-in Python catalog fixture using injected transport only. The normal Worker runner registers the new wrapper; native discovery is unchanged.

No route, public API, schema, provider, config, public copy, artifact or activation change. Provider settings, catalog publication, route wiring, exact public copy and coordinated rollout remain separate gates.

Validation: eight focused composition Node cases and seven existing HTTP cases pass; twenty native D1 composition/admission cases pass. ESLint, pinned Prettier and diff checks pass. Full normal Worker results are recorded in the PR. No public artifacts change, so golden fixtures and screenshots are unchanged.
