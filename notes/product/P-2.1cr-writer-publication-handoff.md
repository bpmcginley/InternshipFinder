## Proposed handoff

1. A surviving supervisor opens a journal for the trusted run and attempt. For each existing ordinary push attempt, the writer records a canonical, immutable intent before the push. Each entry binds the run, attempt, ordinal, expected predecessor, exact candidate commit and raw public tree. The current retry ceiling bounds the journal to three entries. A merge retry records its own candidate. A true no-op records no intent and emits no receipt.
2. Validate the whole journal as unique consecutive ordinals from one, with each entry bound to the same run and attempt. Coalesce adjacent entries only when their predecessor, candidate and tree are identical. Hold gaps, reordered or repeated ordinals, conflicting metadata for one candidate, and any candidate that reappears in a later group. An unchanged-base retry can legitimately use the same identity twice.
3. Independently fetch the named remote data ref and read the raw commit and `docs/data` tree with replacement objects and grafts disabled. Require the final journal identity to match the current tip and raw tree, with its predecessor as a direct parent. Require a trusted accepted-operation witness for that exact identity and attempt, or independently qualify exclusive writer authority over publication of that exact candidate. A matching trailer establishes candidate origin alone. Recheck the named ref before issuing output. Missing, stale or ambiguous evidence withholds the receipt. The supervisor makes no recovery push.
4. Keep the #537 receipt fields `run_id`, `run_attempt`, `commit` and `tree`, the same-attempt artifact and the existing Pages checks. Keep private Follow recovery outside the entire success-critical Ingest workflow run whose attempt #537 verifies. Run that recovery separately against independently observed Git using the existing pending checkpoint and promotion rules. The receipt certifies public listing provenance. Follow's private storage, expiry, restore and release gates still apply.

## Offline proof

Twenty cases ran with tiny file-only Git repositories, an actual local bare remote and a fresh verifier. The synthetic journal used canonical JSON, a 512-byte per-entry fixture limit and a synced temporary file renamed into place. The verifier checked a synthetic attempt-bound commit trailer and a separate successful-receive record from the bare remote with injected writer identity. Both the byte limit and the identity injection are fixture inputs. Production durability, witness authority and runner behavior still need qualification.

| Case | Observed outcome |
| --- | --- |
| True no-op | Zero receives, no intent and no receipt. |
| Child killed after intent and before push | Remote stayed at the predecessor. Zero receives and no receipt. |
| Child killed after acceptance and before output | One receive. The supervisor recovered the exact receipt without another push. |
| Wrong run | Held. |
| Wrong run attempt | Held. |
| Wrong attempt witness | Held. |
| Superseding commit with the same raw public tree | Held. |
| Unrelated update rejected the first push | The ordinary merge changed HEAD. The second intent matched the accepted commit and unchanged candidate public tree. One writer push was accepted after the independent update. |
| Exact current commit and tree without the attempt trailer | Held. |
| Wrong journal public tree | Held. |
| First push rejected without ref movement | The retry kept HEAD and both journal identities unchanged. The second push succeeded. The verifier coalesced ordinals 1 and 2, checked the accepted operation for ordinal 2 and issued one receipt without another push. |
| Reordered, duplicate or gapped ordinals | Held in each of three cases. |
| Conflicting identity or a candidate reappearing in a later group | Held in both cases. |
| Duplicate accepted-operation evidence or wrong accepted ordinal | Held in both cases. |
| Independent actor pushed the exact staged candidate | The original writer made zero pushes. The ref, predecessor, raw tree and trailer matched. The verifier withheld the receipt without the authorized accepted-operation evidence. |
| Accepted current tip with the journal unavailable | Held. This simulated missing evidence. |

The trailer proves the fixture candidate was generated for the attempt. Repository push events can corroborate actor, ref, predecessor and head. Actions run and attempt attribution and a bounded accepted-operation witness still require independent proof. Process death with a surviving supervisor exercised recovery. Whole-runner loss and journal durability across host failure were untested. A remote still at the predecessor can accept a previously sent request after a local kill. An unresolved result stays held without another push or a success claim. The proposal introduces no cross-run storage or retention policy.

## Release qualification

Before cutover, independently qualify the supervisor on Ubuntu with #501's real process deadline and ordinary Git retry behavior. Exercise unchanged and changed retry candidates, pre-push and post-acceptance death, no-op, supersession, stale or missing evidence, late acceptance and whole-runner evidence loss. Prove the attempt's accepted-operation witness or exclusive writer authority against an independent actor publishing the exact staged commit. Prove that ambiguity withholds the artifact and any further push or G3 credit.

Then qualify the actual GitHub bot path, including partial reruns, receipt upload, accepted dispatch with lost acknowledgement, current-ref checks and the final Pages pin. Require success of the exact originating whole workflow attempt. An intact artifact and matching tip leave a failed attempt unauthorized. Verify ordinary listing delivery and exercise private recovery failure and timeout in the separate workflow. Stage the cutover only after the engineering lead releases G3 and the writer and private Follow dependencies are qualified for their respective rollout steps.
