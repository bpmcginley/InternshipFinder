## Proposed handoff

1. A surviving supervisor opens a journal for the trusted run and attempt. For each existing ordinary push attempt, the writer records a canonical, immutable intent before the push. Each entry binds the run, attempt, ordinal, expected predecessor, exact candidate commit and raw public tree. The current retry ceiling bounds the journal to three entries. A merge retry records its own candidate. A true no-op records no intent and emits no receipt.
2. After the child exits or loses its deadline, independently fetch the named remote data ref and read the raw commit and `docs/data` tree with replacement objects and grafts disabled. Require exactly one authorized same-attempt intent for the current tip, the recorded predecessor as a direct parent, matching tree bytes by object identity and a trusted witness binding that exact candidate to this attempt. Recheck the named ref before issuing output. A matching tree under a different commit, a local HEAD or a push result alone is insufficient. Missing, conflicting, stale or ambiguous evidence withholds the receipt. The supervisor makes no recovery push.
3. Keep the #537 receipt fields `run_id`, `run_attempt`, `commit` and `tree`, the same-attempt artifact and the existing Pages checks. Finalize the listing attempt on the qualified listing outcome without waiting for private Follow recovery. Perform that recovery separately against independently observed Git using the existing pending checkpoint and promotion rules. A listing receipt certifies only public listing provenance. Follow's private storage, expiry, restore and release gates still apply.

## Offline proof

Twelve cases ran with tiny file-only Git repositories, an actual local bare remote and a fresh verifier. The synthetic journal used canonical JSON, a 512-byte per-entry fixture limit and a synced temporary file renamed into place. The verifier also checked a synthetic attempt-bound commit trailer. The byte limit is a test input. Production durability, the witness authority and runner behavior still need qualification.

| Case | Observed outcome |
| --- | --- |
| True no-op | Zero receives, no intent and no receipt. |
| Child killed after intent and before push | Remote stayed at the predecessor. Zero receives and no receipt. |
| Child killed after acceptance and before output | One receive. The supervisor recovered the exact receipt without another push. |
| Wrong run | Held. |
| Wrong run attempt | Held. |
| Wrong attempt witness | Held. |
| Superseding commit with the same raw public tree | Held. |
| Unrelated update rejected the first push | The ordinary merge changed HEAD. The second intent matched the accepted commit and unchanged candidate public tree. One writer push was accepted after the independent update. |
| Exact current commit and tree with no attempt witness | Held. |
| Wrong journal public tree | Held. |
| Two matching intents | Held as ambiguous. |
| Accepted current tip with the journal unavailable | Held. This simulated missing evidence. |

The trailer proves the fixture candidate was generated for the attempt. If another actor can obtain and push the identical commit, the trailer alone cannot attribute who pushed it. A production witness must establish the exact attempt's authority at that boundary. Process death with a surviving supervisor exercised recovery. Whole-runner loss and journal durability across host failure were untested. A remote still at the predecessor can accept a previously sent request after a local kill. An unresolved result stays held without another push or a success claim. The proposal introduces no cross-run storage or retention policy.
