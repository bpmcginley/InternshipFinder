# P-2.2r Session copy and checkout integration

[#342](https://github.com/bpmcginley/InternshipFinder/pull/342) is based on the reviewed bounded checkout [#337](https://github.com/bpmcginley/InternshipFinder/pull/337) at `c4e95332`. It imports the exact four Worker source and test files from the reviewed session-copy fence [#297](https://github.com/bpmcginley/InternshipFinder/pull/297) at `e09a8744`. The original checkout branch used the same session source baseline as #297. The scoped import keeps the older payment stack reviewable while preserving the exact reviewed Worker bytes. #297 remains available for its independent owner merge.

The existing session-copy handler requires its source session to remain valid through the copy transaction. The synthetic checkout tests use the real copy, session-fenced reservation and bounded Stripe adapter functions. A valid copy can start checkout after the original signs out. Account deletion after copy preflight prevents a new copy or reservation. A verified provider result after the requesting copy signs out can be recovered through the live sibling session without a second creation request. The revoked copy receives the generic auth result. The existing timeout path retains a pending attempt if it never receives verified provider evidence within the bound.

The new deletion test fails on the exact #337 baseline because the old copy transaction succeeds after deletion. The combined branch passes all seven focused Node scenarios, all 480 Worker Node tests and all 79 local Workers tests. The composed scenarios use synthetic sessions, provider responses and in-memory or local D1 data. Production checkout remains dormant. The existing owner policy, route ownership and deployment gates still apply.
