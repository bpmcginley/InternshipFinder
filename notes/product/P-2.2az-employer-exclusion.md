# P-2.2az dormant positive employer-payment exclusion

Based on exact main `35b638afa3ff3515f3191322c7d75e566e5a9562`, after reviewed whole-window replay #577. This package adds a read-only history classifier, narrow `topup-history-events.js`, `topup-history-replay.js` and bounded `topup-stripe.js` seams, and cases in the existing registered shared history scenarios. It changes no STATUS, registry, test helper, order handler, billing, schema or production configuration.

The new whole-window option `excludeEmployerPayments: true` starts only after the existing verifier validates a supported reversal event and acknowledges an empty local top-up claim lookup. Omission preserves existing behavior and result shape. The single-target replay rejects this option. No caller is mounted. A missing claim alone cannot exclude a payment.

Positive exclusion requires one durable paid employer order plus authoritative exact refund/dispute target, successful captured Charge, canonical latest PaymentIntent Charge and the stored paid Checkout. Mode, identity, listing/order metadata, complete one-item USD economics, discount/tax totals and the original paid-order tuple must match. Conflicting top-up metadata, a configured top-up Price match, a payment/checkout claim or an attached top-up attempt blocks exclusion. A final read transaction rechecks both the exact order tuple and absence of those contradictions. No customer-only match, generic pending fallback or unsupported event family enters this path.

The existing employer form creates one inline-price item and permits promotion codes (`orders/checkout.js`, `checkoutForm`). The fixture covers a discounted payment. Free/pilot/zero-paid orders and cases without a verified successful paid Charge/PaymentIntent remain held. No missing historical order is inferred from provider metadata alone. Current order contact, employer-name and description fields are not selected or returned.

The original pinned credential, explicit supported event schemas, five-GET ceiling, streamed per-read bounds and shared absolute replay deadline apply. Every classifier GET, including discovery Charge and direct refund/dispute reads, uses fatal UTF-8 decoding and the existing traversal duplicate-member validator before the Stripe parser. Escaped duplicate names and contradictory metadata are rejected, with no last-member-wins exclusion. The narrow traversal change only exports that existing validator; legacy billing readers retain their existing behavior. Optional prior Charge discovery plus target/Charge/PaymentIntent/Checkout verification is at most five GETs. The existing no-PI discovery gate remains unchanged. Exact epoch checks occur after terminal traversal and after each result. Loss of a read acknowledgement does not retry. The result adds only an aggregate `excluded` count when explicitly requested. It writes no exclusion receipt, raw event, order reference or financial state. Earlier real top-up observations in the same window may already have committed if later classification fails.

Stripe documents that the expanded Checkout line-items property can be partial, so this classifier requires `has_more === false` and exactly one item. [Checkout line items](https://docs.stripe.com/api/checkout/sessions/line_items). Its Charge and PaymentIntent references support the exact payment bridge used here. [Charge](https://docs.stripe.com/api/charges/object) · [PaymentIntent](https://docs.stripe.com/api/payment_intents/object). Reads reuse the existing pinned adapter version and do not select a new historical schema.

Unknown, unmatched, contradictory or unavailable evidence remains held. This is current positive association evidence, not provider history completeness or an atomic coverage commit. #530's provider completeness, restore, enrollment and retirement gates remain separate. No coverage advance, financial authority, retained event data or activation is added. Focused qualification and independent exact review are required before any source release.

Qualification: 124 focused strict Node cases and 118 actual local Workers/D1 cases passed across replay, event association, traversal, page transport, signed webhook, purchase recovery and checkout adapter. The new cases cover exact event metadata, discounted economics, zero-paid holds, malformed or missing associations, five-GET discovery, invalid terminal pages, immutable tuple/claim/attempt races, epoch/deadline loss and ambiguous read acknowledgements. Raw duplicate metadata, escaped duplicate keys and malformed UTF-8 are rejected at all six classifier/discovery phases. No live calls were used. Final normal-lane and independent review results belong in the PR.
