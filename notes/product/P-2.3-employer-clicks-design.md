# P-2.3 posting clicks per employer

2026-11-10. **needs-bruce: proposal only.** No policy, collection, implementation or deployment is approved. Earlier design-note merges do not authorize this package. No production analytics were read.

**Meaning and scope.** Count organic posting-link activations on the dashboard/generated internship pages once per canonical company per page load. Different roles/repeated clicks add nothing; reloads/separate tabs can. Keep the seen-company set in page memory. Honor `nocount`, automated-browser and bot exclusions. Exclude sponsored boxes, widgets, email, extension actions and Auto-Apply starts. Existing global posting clicks, paid-placement counts/reports, billing and payment rules remain unchanged.

**Exact proposed words.** Posting-link labels stay unchanged; no totals appear publicly. Admin heading: “Employer posting-link activations”. Columns: “Day (UTC)”, “Company”, “Count”. Explanation: “At most one organic posting-link activation per company per page load. Reloads can count again. These are not unique people, applications, or verified arrivals. Counts may omit blocked or dropped events.” Disabled: “Employer posting counts are off.” Empty: “No accepted posting-link activations in this period.”

Proposed privacy addition, **unapproved**: “We also count organic posting-link activations by employer and UTC day, once per employer per page load. Reloading can count again. The browser sends only a fixed event name and the employer's public key. We store only the day, employer key and total, never an account, visitor identifier, posting identifier, IP address, search or full URL. Abuse checks hold network addresses and request counts in memory for the current minute, never associated with employers or saved. Daily totals are deleted after 90 days, without monthly rollups. Only the site owner can read these totals. Because they identify nobody, Delete my data cannot remove an individual's contribution. The existing nocount setting disables this counting.”

**Proposed contract.** Reuse `POST /hit` with a validated event/key branch and separate aggregate table: `(day UTC, public_company_key, count)`, unique on day/key. Server supplies day and increments one atomically; reject client dates/counts and extra fields. No company keys in existing event/page dimensions. Add an aggregate member to guarded `GET /admin/employer-metrics`: completed UTC days, existing 1–90-day window and `no-store`; preserve paid/funnel fields/calculations. No public route, employer report or mailing.

**Keys and bounds.** Reuse `seo_pages.employer_key`. `data/roles/index.json` excludes non-purchasable roles; dashboard rows lack keys. Approve an all-organic public mapping, row/link annotations and golden review. Proposed validated snapshot: at most 10,000 keys, each at most 200 UTF-8 bytes; reject unknown keys. Missing/oversized/invalid snapshots fail closed; approve cache lifetime before build. Proposed atomic caps: 1,000/company/day and 50,000/day overall. Reuse origin/body/bot checks; dispatch organic signals BEFORE the shared minute limiter into an independent bounded ephemeral minute budget. Propose 30 requests/address/instance/minute and 2,000 address entries, reset each UTC minute; reject new entries when full. Never consume existing limiter state or change old-signal acceptance rules. No company/IP association or persisted identity. Daily caps do not replace minute-budget isolation. Forged public beacons remain possible.

**Retention, recovery and approval.** Daily cleanup removes rows older than 90 days; admin reads exclude expired rows. No rollup, identity linkage or backfill. Owner deletion removes a company/day range. Disable collection on retention failure; resume after cleanup/snapshot validation, without replay. Bruce approves wording, scope, mapping, caps, minute-budget bounds, cache lifetime, retention/recovery and enablement. Remain off until privacy publication, reviewed worker/schema/client PRs and Bruce's deployment. Offline tests cover duplicate clicks, UTC boundaries, unknown keys, concurrent caps, cleanup, admin auth and opt-out. Interleave saturated organic traffic with paid/global signals behind one campus NAT; prove their acceptance remains unchanged.
