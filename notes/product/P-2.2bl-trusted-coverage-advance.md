# P-2.2bl Trusted Stripe history coverage advance

The approved [payment-history design](P-2.2am-topup-history-design.md) requires two independent inputs before recording a continuous interval. A bounded Stripe replay must classify the entire interval. A trusted server verifier must then affirm that the exact interval is complete for the approved account, mode, event schema and current restore state. Successful pagination and empty lists do not establish completeness. [Stripe event-generation failures](https://docs.stripe.com/events/manage-webhook-endpoints#event-generation-failures)

The verifier must bind to the deployment's exact account and database. It receives the exact captured epoch, revision and replay bounds. A valid response is bound to that invocation. A first interval covers the epoch start. A later interval must overlap the current coverage and extend it. The database transaction verifies the complete previous tuple and prevents a closed or replaced epoch from advancing.

The provider and restore verifier is a separate dependency. This package supplies no verifier, new retention fields, default Worker binding, schedule or production configuration. It does not enable sales or automatic cleanup.
