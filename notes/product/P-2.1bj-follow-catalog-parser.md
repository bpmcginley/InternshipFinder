# P-2.1bj strict Follow catalog parser

Draft [#514](https://github.com/bpmcginley/InternshipFinder/pull/514) on exact main `ec8d4fb17152e82a5b0df46b88fdba19e5e66c2d`. This is a pure Worker parser for the reviewed [#510](https://github.com/bpmcginley/InternshipFinder/pull/510) producer at `47b88b941b5df07eac7ea056658b20ad96a8b72c`. No producer/backend change is stacked or copied into this PR. One new source, one new Node test, one synthetic byte fixture and a coordinated standard-runner import. No fetch, cache, routes, D1, provider, configuration, public files, publication or activation.

`parseFollowCatalog(bytes, {maxBytes, maxKeys, sourceSha256, catalogSha256, previousValid})` requires positive safe integer bounds, both exact lowercase SHA-256 digests and prior approved public company/field/state Sets. Genesis uses three explicit empty Sets. All input bytes and prior memberships are copied before asynchronous hashing; Buffer views cannot change accepted bytes under a prior digest. The source digest must match the versioned envelope. The additional caller-trusted catalog digest binds the entire payload, because its self-declared source digest alone cannot authenticate the projection. This adds no wire field or producer-format change. The caller still owns trusted provenance, freshness, prior-key continuity and approved limits; this function is not an artifact reader.

Within the byte bound, fatal UTF-8 decoding and exact canonical reserialization reject BOMs, malformed UTF-8, duplicate JSON fields, whitespace, alternate number/escape spelling and wrong object order. The exact version1 schema, UTF-16-sorted unique arrays, 200-byte canonical-key ceilings, field/state syntax, alias name bounds/order and alias-value equivalence to current employers are enforced. Current field/state vocabularies are nonempty; current company availability may be empty. Every signup key and every supplied prior valid key must remain in valid. No existing key is renamed or dropped and no filter is broadened. Unknown fields and more than 64 selected fields still fail the unchanged canonicalFollow request contract, even though the catalog exposes 66 choices.

The result contains separate fresh `signup` and `valid` groups of company/field/state Sets, plus an alias Map. Use signup for new scopes, valid for existing saved scopes. Alias maps contain public current display names only; historical aliases are not reconstructed or guessed. The returned containers are caller-owned; mutation cannot affect an independently parsed result. Errors are the constant `Follow catalog unavailable`, without parser/body/provider details. This parser performs no activation or request authorization by itself.
