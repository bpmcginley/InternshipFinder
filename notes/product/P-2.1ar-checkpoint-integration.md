The fixture bootstraps already-verified pending and optional predecessor records into native local SQLite and the two fixed native R2 slots. This trusted bootstrap is explicitly not a production reservation or staging API. SQLite contains reconstructive headers, slot nonce/ETag/digests, original start/expiry and replay cutoffs, initialized state, and an opaque current position/transition receipt. It contains no common payload, lineage tuples or raw checkpoint body. The reviewed codec reconstructs the original bytes from the R2 payload and SQLite header against the required checkpoint digest. All six original Python golden pairs also run byte-for-byte inside workerd. Active-cutoff tests shift synthetic canonical timestamps into the present; they do not manufacture a new Git or publication attestation.

The injected witness test double lives outside the SQLite snapshot restored by the tests. It compares the exact stable predecessor before preparing a nonce-bound successor. A fresh SQLite transaction compares the original control state and current database clock, commits metadata and receipt atomically, and only then finalizes the witness. Ordinary reads and retirement require the reviewed classifier's exact stable position. A committed transition with a prepared witness remains closed until explicit receipt-matched acknowledgement recovery. A prepared predecessor remains ambiguous and cannot be automatically aborted; restoring the earlier SQLite snapshot cannot distinguish a missing commit from rollback. A stable witness ahead of restored SQLite also holds access. A lost reply after the witness actually becomes stable permits a later exact stable read, while replay never repeats the transition or extends expiry.

Promotion reconstructs the pending generation and binds the accepted header to the same payload and public tree. The trusted caller remains responsible for the original typed accepted Git proof; this test fixture does not implement Git verification. Promotion swaps metadata only and leaves both R2 ETags unchanged. The old accepted slot remains intact while pending is present and becomes an explicitly retired slot after promotion. Same-target replay ends at the earlier original pending/predecessor cutoff. Start rounding is the original microsecond ceiling; expiry is the original millisecond floor plus 24 hours or seven days. Reads recheck unchanged control and fresh native SQLite time after asynchronous R2/codec/witness work. The tests cross actual SQLite-clock cutoffs during delayed read release and prepared promotion; no injected Worker clock authorizes those operations.

Expired records are first retired by a witness-fenced metadata transition. Explicit cleanup prepares the witness before conditionally tombstoning the exact retired ETag, then clears its retired metadata and finalizes. It cannot tombstone the live counterpart or delete the fencing keys. Missing/closed witness, rollback, stale ETag or interrupted steps hold. No cleanup scheduling or production retention guarantee is added. Recovery after uncertain R2 cleanup, full pre-upload reservations, late-upload reconciliation, cold coordinator restart, production backpressure and operator restore remain separate work.
