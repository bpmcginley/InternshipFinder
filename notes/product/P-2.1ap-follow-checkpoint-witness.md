# P-2.1ap Private checkpoint restore witness qualification

Draft [#469](https://github.com/bpmcginley/InternshipFinder/pull/469) is based on exact #450 5eff127f49b78329a679a833b2509cfc9aecd61c. #468 owns the separate raw R2 slot adapter.

The classifier compares one versioned external witness record with one local control snapshot. Each position consists of an opaque 128-bit epoch, a safe integer revision, and an opaque 128-bit control token. A prepared intent binds one nonce and an exact same-epoch successor. A local receipt binds the nonce and exact predecessor to the snapshot's current position. The parser accepts only the fields needed for this comparison and returns a coarse decision without echoing any input.

| Result | Evidence |
| --- | --- |
| current | Stable witness and local control have the exact same position. |
| recover_ack | Prepared successor and its exact locally committed receipt match. A future coordinator must recheck and finalize the witness before ordinary access. |
| ambiguous_predecessor | A prepared intent still sees the original predecessor. It cannot determine whether a local commit never happened or was rolled back. |
| rollback | A stable witness is ahead of local control in the same epoch. Identical raw slot ETags do not qualify the older control. |
| mismatch | Valid records disagree in a way that cannot recover the exact prepared transition. |
| closed or unavailable | The witness closed admission, or the required state is missing or invalid. |

A future coordinator must bind every logical control change and its receipt atomically to a fresh control token, then prove the matching stable witness before serving bytes. The classifier alone cannot establish that contract. The caller still owns fresh time, exact Git and slot evidence, and the original pending, accepted and replay deadlines. Recovery never takes a new lifetime from the witness. If exact evidence is unavailable, keep access closed and follow the verified recovery or owner-approved reseed path in #358.

Seven shared synthetic cases ran directly in Node and in actual isolated workerd. The rollback case supplies a simulated older control snapshot and identical synthetic slot ETags. No PITR was invoked. The existing 740-case Node registry and both existing detached checkpoint runtime suites passed. The new Node case file is run directly on this parent and the ordinary native test runner discovers its workerd wrapper. These checks qualify classification only. Storage and retention qualification, restore operations, private bindings, routing, and owner activation remain separate.
