# P-2.1eb dormant archive deployment adapter

This default-off source package owns new `worker/src/follow-archive-deployment.js`, its auto-discovered native test and this note, plus a narrow pure extraction in `follow-signup-release.js`. Its base is main `5f4f109f74a391862191d7ab0014f6190537b930`, including the reviewed #630 archive runner. The Product lead owns shared Waiting for Bruce tracking. No index, route, scheduler, schema, registry, environment value or production configuration changes.

`runFollowArchiveDeployment` accepts an explicit trusted deployment descriptor string and trusted request-scoped database/fetch/clock ports. It does not accept HTTP input, expose a supplier, choose pins, or fetch by default. Absent `enabled: true` returns disabled without inspecting descriptor inputs. The version-one descriptor is bounded to 8,192 UTF-8 bytes and has exact `version`, `catalog`, `archive`, `budget`, `limits`, `maxProgressBytes` and `maxPendingBytes` fields. Duplicate decoded JSON member names anywhere are rejected, including escaped aliases.

The catalog subobject uses the existing release source/catalog SHA-256 pins, first-party origin, URL, validity window, byte/key/deadline bounds and independently pinned predecessor URL/source/catalog hashes, or explicit `{genesis:true}`. The pure catalog-policy validator is extracted from the existing signup deployment module. Signup retains its exact original descriptor shape, daily limit, duplicate-name validation and loader behavior. The archive subobject requires the fixed `https://internscout.org/data/follows/index.json` URL and an explicit SHA-256, plus the existing reader bounds. Every budget and matcher/reader limit remains explicit. No real deployment values are supplied by this package.

The adapter captures database methods once and starts the wall/monotonic budget before parsing or I/O. Both clocks must remain finite, synchronous and nonregressing. It uses the existing bounded catalog loader for the predecessor only, then calls the unchanged real archive runner with that predecessor's valid sets. The runner performs the sole current-catalog GET. The outer fetch counter and clock guard remain authoritative throughout, including each inner read and D1 boundary. The runner receives only the remaining fetch/time allocation. There is no second full deadline or cached release authority.

Malformed authority or insufficient budget for one complete candidate rejects before I/O. The existing technical ceilings remain 128 pages/page size/subscribers, 48 D1 calls, 100 statements and 257 total GETs. A predecessor consumes one of those GETs. Catalog, manifest and snapshot byte ceilings bound each read, and the total read envelope is at most the configured GET cap times the largest applicable per-read ceiling. Native enqueue state, continuity checks, SQL admission guard and receipt semantics stay in the existing runner. Late or lost D1 acknowledgements remain unavailable, with no automatic retry or assertion that the transaction rolled back. No persistent continuation or scheduling policy is introduced.
