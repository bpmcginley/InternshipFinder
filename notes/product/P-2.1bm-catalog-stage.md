# P-2.1bm bounded Follow catalog staging

Draft [#518](https://github.com/bpmcginley/InternshipFinder/pull/518), stacked on #510 refreshed at `c6c14a8212fa8a6ce15b642f57b93d70c1b89a9d`. Own new `site/follow_publication.py`, focused tests, this note and two tracker rows. The producer and main Worker parser are reused unchanged. Both backend packages remain G3-held; no publication, workflow, allowlist, provider or subscriber access.

`prepare_follow_catalog(export_dir, *, enabled=False, source_sha256, prior_path, prior_sha256, genesis=False, max_source_bytes, max_source_rows, max_keys, max_bytes)` performs no I/O unless enabled is exactly true. Enabled calls require all positive safe-integer bounds and an independently trusted expected source SHA. There is no environment/default-directory fallback. Inputs must be regular files with no symlink/junction ancestors. Reads consume one aggregate source-byte allowance, and each read is bounded before JSON decoding. Only the index, every exact declared slim shard and majors are captured; descriptions and unrelated files are not inputs. The unchanged producer validates completeness/counts/conflicts and returns canonical bytes. The exact framed source SHA must match before any result is returned.

The caller establishes the selected export's Git identity and computes/verifies its expected framed source pin independently, then passes the already selected directory. The receipt does not claim a Git revision, freshness or authority from a path. Production selection and trusted pin delivery remain separate. A changing capture cannot be accepted unless the complete captured bytes match that external source pin. Callers combining employer annotations must capture Follow inputs before modifying those original public bytes.

Continuity requires either the complete prior approved public catalog file plus its exact SHA, or explicit `genesis=True` with no prior path/digest. Missing, ambiguous or mismatched inputs fail; they never become an empty retained set. Prior bytes must be canonical v1, have exact key/order/shape, bounded sorted unique sets, current-set inclusion in valid, and exact alias coverage. The full prior valid sets feed the unchanged producer. Empty current employers remain unavailable for new signup but their saved canonical keys stay valid. No database or subscriber data is read, no keys are inferred or retired. This adapter does not add ad hoc retention identities; those require an approved prior catalog.

The result is a frozen `CatalogStage` with immutable `payload` bytes, `source_sha256`, `catalog_sha256`, and `prior_sha256` (null only for explicit genesis). No output path is accepted and no artifact is written. The caller must arrange trusted catalog/source pins for `parseFollowCatalog`; simply accepting a request-supplied digest would not establish trust. Catalog key capacity remains separate from existing per-request selection limits. No request, renderer, Worker route/cache, sending, storage policy, live configuration or default build behavior changes.
