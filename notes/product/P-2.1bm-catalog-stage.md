# P-2.1bm bounded Follow catalog staging

Draft [#518](https://github.com/bpmcginley/InternshipFinder/pull/518), stacked on #510 refreshed at `c6c14a8212fa8a6ce15b642f57b93d70c1b89a9d`. Own new `site/follow_publication.py`, focused tests, this note and two tracker rows. The producer and main Worker parser are reused unchanged. Both backend packages remain G3-held; no publication, workflow, allowlist, provider or subscriber access.

`prepare_follow_catalog(selected, *, enabled=False, source_sha256, prior_bytes, prior_sha256, genesis=False, max_source_bytes, max_source_rows, max_keys, max_bytes)` performs no I/O unless enabled is exactly true. Enabled calls require all positive safe-integer bounds and an independently trusted expected source SHA. There is no filesystem or environment access. `selected` must be a plain dict of exact relative public paths to immutable bytes, with bounded path count and aggregate bytes checked before source decoding. It must contain only the index, every exact declared slim shard and majors; descriptions and unrelated paths are rejected. Mutable bytearrays, path strings and Path objects are rejected. The unchanged producer validates completeness/counts/conflicts and returns canonical bytes. The exact framed source SHA must match before any result is returned.

The caller establishes the selected export's Git identity and computes/verifies its expected framed source pin independently, then passes an immutable byte capture. File acquisition and its race/size protections belong to that caller. The receipt does not claim a Git revision, freshness or authority from its input. Production selection and trusted pin delivery remain separate. The adapter copies the plain dict and requires immutable bytes; complete captured bytes must match the external source pin. Callers combining employer annotations must capture Follow inputs before modifying those original public bytes.

Continuity requires either the complete prior approved public catalog bytes plus their exact SHA, or explicit `genesis=True` with no prior bytes/digest. Missing, ambiguous or mismatched inputs fail; they never become an empty retained set. Prior bytes must be canonical v1, have exact key/order/shape, bounded sorted unique sets, current-set inclusion in valid, and exact alias coverage. The full prior valid sets feed the unchanged producer. Empty current employers remain unavailable for new signup but their saved canonical keys stay valid. No database or subscriber data is read, no keys are inferred or retired. This adapter does not add ad hoc retention identities; those require an approved prior catalog.

The result is a frozen `CatalogStage` with immutable `payload` bytes, `source_sha256`, `catalog_sha256`, and `prior_sha256` (null only for explicit genesis). No output path is accepted and no artifact is written. The caller must arrange trusted catalog/source pins for `parseFollowCatalog`; simply accepting a request-supplied digest would not establish trust. Catalog key capacity remains separate from existing per-request selection limits. No request, renderer, Worker route/cache, sending, storage policy, live configuration or default build behavior changes.

- Synthetic cases cover disabled/no-I/O, immutable repeat receipt and zero writes, explicit genesis, empty-current retention, source/prior digest mismatch, missing/ambiguous authority, malformed canonical prior, missing/conflicting/duplicate/invalid-UTF-8 source, byte bounds, mutable inputs and invalid paths.
- The exact checked-in #514 Worker parser accepts the new adapter output with the receipt's pins and verified previous sets, including all 66 fields, canonical Booz Allen aliases and retained non-current company identity. A wrong payload pin is rejected. This is real cross-language execution on synthetic public data, not live catalog publication.
- Default golden, existing employer publication and public-data regressions: all 17 passed. Ruff check/format and diff checks passed. Both golden artifacts and all default/public files remain untouched. There is no browser surface, visible copy or screenshot change.

Release remains separate: independently reviewed source and hosted tests, G3/lead release, an explicit publication/allowlist seam, trusted prior-catalog lineage and pin delivery, approved production bounds, and later Worker source admission. No operator limit or provider setting is selected here.
