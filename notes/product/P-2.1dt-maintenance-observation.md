# P-2.1dt aggregate maintenance observation

Claim: new `worker/src/follow-maintenance-observation.js`, auto-discovered `worker/test-workers/follow-maintenance-observation.test.js`, and this note. Base main `39de07520031763bb50dec320e43f0b83291d7fd`. No scheduler/router/config, sink, retained state or production changes.

`createFollowMaintenanceObservation(recorder)` returns a dormant callback accepting exactly `{status,durationMs,d1Calls}`. Status is the primitive enum `pass-complete`, `partial`, or `unavailable`; duration is a nonnegative safe integer in milliseconds; actual D1 binding calls are an integer from 0 through the existing scheduler ceiling of 48. Duration can exceed the scheduler deadline when awaited work settles late. These are representation bounds, not a new timing policy. Only plain or null-prototype objects with exactly three enumerable own data properties qualify; extra properties, symbols, accessors, inherited values and coercible substitutes are rejected before recording.

The adapter passes a detached frozen aggregate once to the explicitly injected recorder. No recorder means `disabled` without inspecting input. Invalid input, a malformed recorder, a thrown callback, or a rejected callback yields only `unavailable`; no input, error or callback return value is echoed and no retry occurs. `reported` means callback fulfillment only, not durable recording, completed retention coverage, or a healthy deployment. There is no sink, logging, storage, clock, timer, scheduler import or production configuration.

The future caller owns truthful duration and actual binding-call measurement; it must not relabel unknown work as zero. It should attach observation independently after work settles and **must not await recording within a mutation/deadline or final transport fence**. A recorder can remain pending; this adapter invents no timeout or cancellation policy. Sink selection, retention, cadence and real operational evidence remain separate release work. This package does not activate observation or alter maintenance outcomes.

Validation: seven focused tests pass through the existing configured Workers test lane (`cd worker; node node_modules/vitest/vitest.mjs run --config vitest.config.js --maxWorkers=1 test-workers/follow-maintenance-observation.test.js`). Cases cover disabled zero inspection, all status/numeric boundaries including late duration, malformed identities and shapes, getter/coercion exclusion, detached frozen snapshots, synchronous/asynchronous failures, and an unresolved recorder. No database or provider operation is needed by this pure boundary. ESLint, Prettier and `git diff --check` pass. The test is discovered by the existing native test glob; no shared registry changes.
