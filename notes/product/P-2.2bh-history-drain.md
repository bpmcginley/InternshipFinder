# P-2.2bh bounded history receipt drain

Base: exact main `deebe26def722ee99fda660e65cf0c717bfe6983`. Implements the bounded drain needed for the approved [30-day unlinked receipt retention](https://github.com/bpmcginley/InternshipFinder/pull/530). No caller, cron or production setting is added.

`drainTopupHistoryReceipts(db, {enabled:true, limit, maxPages, deadlineMs, monotonicNow})` reuses `cleanupTopupHistoryReceipts` sequentially. All limits are explicit: 1–256 rows per page, 1–256 pages (at most 65,536 rows) and a 1–60,000ms common monotonic submission budget. These are technical ceilings, not a chosen daily production allowance. Omitted/off enablement inspects no other input or DB; malformed inputs hold without DB work.

The deadline is sampled before each page, immediately before actual D1 batch submission after synchronous preparation, and after acknowledgement. An admitted D1 request is awaited and cannot be recalled; it can outlast this submission budget. A late acknowledged page contributes its known count but cannot certify completion or trigger another page. An invalid/backward clock holds. Accidental ordinary native rejected Promise clock results are observed through the captured Promise intrinsic, without consulting foreign thenables or custom `then` properties; exotic constructor/species promises remain the caller's responsibility, matching the scheduled digest boundary. No background retry or reset is scheduled.

Results contain only fixed status, submitted `pages` and acknowledged `removed` counts. `complete` requires an acknowledged short page before deadline; a full page at the cap remains `partial` even if it happened to delete the last row. A deadline also returns `partial` for known acknowledged work. Malformed or lost acknowledgements return `unavailable` and retain only prior known removal totals; submitted pages include the uncertain call. A later operator invocation is a separate attempt, not an automatic retry.

The existing indexed DELETE and database UTC inclusive 30-day cutoff are byte-identical. Cleanup alone now snapshots required own-data acknowledgement fields once, rejecting getters without executing them; the observation transaction and its receipt handling are unchanged. No purchase, coverage, financial, account, storage, provider or sales policy changes occur. Future daily integration must provision sufficient bounded work and treat `partial`/`unavailable` as incomplete maintenance; this package does not claim a mounted daily cleanup.

Validation: 35 actual local workerd/D1 cases (21 new drain cases plus 14 existing observation scenarios), and 14 existing Node 22 observation cases plus three direct `--unhandled-rejections=strict` clock probes. Covers full/empty/partial, explicit maximum page, stable ties/index plan, actual database age and future records, no DB on malformed/off, pre-submit expiry including time consumed in prepare, late short/full pages, backwards clock, committed lost acknowledgement, malformed second page preserving known aggregates, and forged changes/receipt getters with zero invocation, and rejected async clocks before work and after acknowledgement without another page. One exact-boundary fixture substitutes only SQLite's clock literal so equality versus the next millisecond is deterministic; the production SQL is unchanged. ESLint/Prettier/diff checks pass. All data and acknowledgements are synthetic; no external provider was called.
