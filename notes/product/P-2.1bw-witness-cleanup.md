# P-2.1bw Follow cleanup witness journal

[#532](https://github.com/bpmcginley/InternshipFinder/pull/532) qualifies one canonical, at most 2 KiB v2 witness and cleanup journal using the existing [#529 CAS port](P-2.1bu-witness-cas.md). The original factory preserves its flat v1 record and core methods. The new factory requires v2 and never converts or initializes a stored record.

The v2 record projects the witness position (epoch, revision, token), prepared transition nonce and successor, and at most one exact cleanup journal. The journal retains the transition, previous-control digest, slot number, reservation nonce, payload and checkpoint digests, original start, expiry and cutoff, source ETag, planned empty tombstone nonce/digest/length, and a forwarded bit. It contains no checkpoint bytes, URL, writer identity, listing identity or user data. The exact journal survives an unresolved operation until qualified reconciliation. Production retention and recoverability of this metadata still need approval.

The journal binds only to its exact prepared witness and prior journal version. It starts unforwarded. Forwarding cannot change the plan. A replan preserves the original cutoff and reservation proof, uses a different tombstone nonce and, after forwarding, requires a different source ETag. The cleanup coordinator must verify the actual R2 object and obtain a fresh one-use tombstone receipt before replanning. The adapter never writes R2 or changes a deadline. Exact acknowledged finish advances the witness and removes the journal in one CAS. Uncertainty never retries that CAS or supplies authority to repeat a physical write.

Six new native cases use real local workerd RPC, separate SQLite witness storage and synthetic local R2. The cases cover strict v2 parsing, competing journal CAS, immutable proof, and lost acknowledgements before or after forwarding, physical PUT or finalization. Recovery after independent eviction uses at most one physical cleanup PUT. All seven original v1 cases, 144 dedicated native tests and 875 Worker Node tests passed. Controlled close, drain, reopen, provider selection, private ingress, approved payload deletion, restore and activation remain held.
