# P-3.4a bundled practice page

`before-*-setup.png` shows the actual earlier setup page from `1712e648`, before a practice route existed in the packaged extension. `after-*-idle`, `filled` and `complete` show the new packaged page. Each of the four width/theme combinations uses full-width captures at 1,280 or 375 CSS pixels. The setup page has no new practice link in this package. P-3.4b adds that entry point after the resume-first setup work.

The browser loaded the real developer ZIP unpacked into a temporary directory, with fresh Edge profiles. The browser test checks blank read-only fields, Tab and Enter to fill, `input` and `change` on all four sample values, keyboard focus, Tab and Space to complete, no horizontal scrolling, and zero form submissions, page errors, CSP violations or external page requests. The browser's background requests went to a deny-all loopback proxy. The `measurements.json` file records the blocked attempts separately. No personal profile, real application, provider, sign-in, permission grant or AI run is used.

To reproduce, use Python to build the developer ZIP from the checked-out branch and from a scratch archive of `1712e648`. Run the existing `scripts/package_extension.py` against each source tree with `DIST` pointed at a temporary folder. Unpack the developer ZIPs into `<scratch>/before/unpacked` and `<scratch>/after/unpacked`. With Node 22, set `FIXTURE_ROOT` to `<scratch>`, set `CAPTURE_TOOLS` to a directory with `node_modules/playwright-core`, and run `node notes/product/screenshots/P-3.4a/capture.cjs`. `PRACTICE_BROWSER` can override the Edge executable. The script starts fresh temporary browser profiles and never connects to a live provider.

Both developer and Web Store ZIPs include `practice/practice.html`, `practice/practice.css`, and `practice/practice.js`. The manifest, version, guard, actions and DOM scripts are identical to the baseline source. The packaged manifest and script hashes are recorded in `measurements.json`.
