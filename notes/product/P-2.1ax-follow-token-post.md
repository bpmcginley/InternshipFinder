# P-2.1ax Follow confirmation and pending-request deletion

The approved Follow design requires an explicit confirmation action and a
separate way to delete a pending request. The storage operations already exist.
This package connects them to two bounded POST routes. The bearer is carried
in the request body. Opening an email link or previewing its landing page
cannot invoke either mutation.

Claimed files include the two route entries, their API contract, the isolated
Follow token handler, focused local tests and these notes. The new endpoints
issue no credentials. Signup, sending and the future confirmation page remain
separate release work.
