# P-2.3j dormant employer catalog projection

[PR #331](https://github.com/bpmcginley/InternshipFinder/pull/331) is based on published main `1a9cebed`. Needs Bruce. The [published design #209](https://github.com/bpmcginley/InternshipFinder/pull/209) calls for the existing employer key and a complete organic catalog. This helper does not select the source.

`build_employer_catalog(names, complete=..., max_bytes=...)` takes a materialized list or tuple of already-public eligible organic employer names. The trusted caller attests completeness and supplies a positive safe-integer serialized byte bound. The helper derives keys with `backend/internscout/site/source.py`'s existing `employer_key`, collapses aliases and duplicate canonical keys, then emits a deterministic sorted array as compact UTF-8 JSON. The array contains keys only, with no separate display names, roles, counts or timestamps. A malformed name or over-budget capture rejects the entire projection.

The exact consumer is [#292](https://github.com/bpmcginley/InternshipFinder/pull/292) at `14ae78492cec4c1098c199ae568eb791f735091a`. Its parser accepts one through 10,000 unique nonempty strings. Keys must be trimmed, contain no ASCII control/DEL or lone surrogate, and stay within 200 UTF-8 bytes and 200 UTF-16 units. The UTF-8 cap also enforces the UTF-16 cap for valid scalar strings. The helper applies ECMAScript trimming characters to the key check. It rejects malformed input names before canonicalization, so a stripped control cannot be hidden in a canonical key.

Synthetic tests cover aliases, reordered input, UTF-8 and serialized byte boundaries, the unique count cap, invalid captures and empty output rejection. An opt-in test sends only synthetic bytes over stdin to the exact local Worker module and its actual request-safe catalog parser. It verifies successful membership, an unknown key, one load, and rejection of empty, duplicate, oversized and over-byte-budget inputs. To run the probe, set `INTERN_SCOUT_EMPLOYER_CATALOG_WORKER` to the verified local `worker/src/employer-posting-counts.js` and run `python -m pytest backend/tests/test_employer_catalog.py -q`. Python 3.12.10 and Node 22.23.4 passed all 25 cases with parity enabled. The normal test run passes 24 and skips the optional probe. Ruff and diff checks passed.

Source selection and completeness, actual byte-budget policy, a public URL or path, row/link mapping, allowlist and golden coordination, privacy approval, integration and deployment remain separate. No collector, generator, workflow, site asset, public file, emitter, route, provider, account or production data changed.
