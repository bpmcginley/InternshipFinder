# Bounded Follow digest expiry candidates

`expireFollowDigestCandidate` is a dormant one-job operation. The current Worker entry, scheduler, delivery owner and public output remain unchanged. It requires literal opt-in and the two indexes added by migration 0033. It returns a status and direct mutation counts without returning a job ID or storing a cursor.

A call reads the database clock once. With that same cutoff, it probes up to three due attempting leases and at most one row each for queued expiry, leased expiry and seven-day age. If a third due attempt exists, the call returns unavailable without a write. With at most two due attempts, the seek has the complete set and selects its minimum signed rowid. The other three seeks supply independently eligible candidates. Only attempting-to-uncertain transitions can advance progress, and all due attempts are ordered by their signed rowids even when lease order differs. An empty candidate scan returns completion separately from the cap hold.

A mutation batch recomputes the indexed selection and checks both due rowids and job identities, plus the selected job's exact rowid, identity, immutable fields and eligibility. If the job requires a state transition and age deletion, the batch first applies the existing transition. The delete then requires the immediately preceding direct write and the same identity and rowid. This preserves finalization before pending data is erased and deletion follows. Both writes require exact `RETURNING` receipts and bounded aggregate changes. Lost or contradictory acknowledgement yields unavailable without a retry or a completion claim. A previously committed write may still have taken effect.

## Offline qualification

The exact local Workerd/D1 suites passed 80 cases across candidate selection, migrations, finalization, retention and the existing scheduler. In a 20,000-row healthy-prefix fixture, the five indexed plans read 22, 20, 19, 18 and 15 rows. The four mutation batches read 57, 26, 25 and 22 rows. Actual mutation `EXPLAIN QUERY PLAN` verifies bounded named index seeks and direct integer-primary-key targeting. The overlap case advances the exact pending scope before deleting the old job. Native tests compare the complete relevant state against the original rowid scan for both competing and chained advances with reversed lease order and signed rowid extremes. They also cover a third due attempt, a changed due set or peer identity before mutation, selected-row replacement, cutoff boundaries, rollback, lost and contradictory acknowledgements, preserved healthy rows and the held owner, budget and markers.

The added state/expiry index costs one extra reported write in the existing packed finalization fixture. Its precise write ceiling increases by one. Migration parity verifies the two new indexes in both schema paths, and the existing finalization read and state assertions are unchanged.

Production schema adoption, scheduled integration, operator observation and repeated-pass capacity remain separate. The existing scheduled path still uses its original scan. No provider or production database was used.
